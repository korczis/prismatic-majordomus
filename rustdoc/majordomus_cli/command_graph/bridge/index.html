The workflow bridge: the command graph projected into recipes.

just is an ergonomic front door, not a place where commands are declared. Every recipe this writes is one line that runs the canonical program with the caller’s own arguments — never a second implementation, never a second description, and never a call back into just, which is what would make the bridge a cycle.

  CommandGraph ──► render ──► bridge.just ──► imported by the root justfile
                      └─────► bridge.json  (what was written, and from which graph)

§Where it lives, and why not in the tree

Under .ai/local/cache/, which no commit carries. A generated file in the tree would have to be regenerated by whoever changes a command, checked by a gate, and merged by hand on every branch that touches the command line — for a file that is a pure function of the tree it sits in. The materialisation is cheap and fingerprinted, so the cost of not tracking it is one hash comparison per entry into the repository.

§Argument forwarding

Interpolating a recipe’s arguments into the body — {{args}} — splices text into a shell command, so a path with a space arrives as two arguments and a quote arrives as a syntax error. The runner’s own answer is set positional-arguments, which passes a recipe’s arguments to the shell as $1, $2, …; the body then forwards "$@" and the shell’s own quoting carries spaces, quotes, $(…), newlines and leading dashes unaltered. Nothing here escapes anything, because nothing here interpolates anything.

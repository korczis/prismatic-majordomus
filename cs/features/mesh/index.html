Relace na více strojích pracují s jedním repozitářem, aniž by se srážely

Runtimy Majordoma jednoho repozitáře — na jednom stroji či více — se navzájem objevují, propojují se podepsaným handshakem a sdílejí relace, claimy, předávky a revize jedním replikovaným žurnálem, který přežije odpojení, pády i rozdělení sítě.

Co dělá

Několik AI kódovacích relací — dva terminály na notebooku, desktop, build stroj — pracuje na jednom repozitáři. S povolenou deklarací mesh je server každého checkoutu runtimem mesh: oznamuje se (podepsaně, přes multicast, broadcastový fallback, rendezvous nebo deklarované seedy), a když najde runtime stejného repozitáře, jehož klíči důvěřuje, oba otevřou spojení podepsaným handshakem. Od té chvíle si při každém heartbeatu vyměňují to, co tomu druhému z jednoho žurnálu podepsaných událostí chybí:

  • sessions — kdo pracuje, s jakým klientem, na jakém úkolu, branchi a headu; oznámení nástěnky peerů se promítají automaticky;
  • nároky — exkluzivní nárok učiněný na jednom stroji odmítne překrývající se nárok na každém propojeném stroji, claim_conflict pojmenovává nárok, na který narazí;
  • předávky — mesh handover publish na jednom stroji, mesh handover consume na jiném a záznam přistane tam, kde jej najde majordomus handover --resolve;
  • reviews — požádejte pojmenovaný runtime o review a uvidíte jeho odpověď na svém stroji.

Každý propojený runtime skládá stejné události do stejného stavu a vypisuje stejný digest. Runtime, který přestane tlouct — zabitý, spadlý, odříznutý — vyprší na svých peerech v rámci deklarované expirace, jeho claimy přestanou vylučovat, a když se vrátí, znovu se připojí jako tentýž runtime. majordomus mesh peers, mesh state, mesh verify, /api/v1/mesh/*, nástroje MCP a stránka Mesh v Cockpitu ukazují stroje, runtimy, relace, claimy, spojení a proč bylo cokoli odmítnuto.

Co nedělá

Nevěří síti: zjišťování nachází kandidáty a nic nepřiznává, spojení vyžaduje stejný repozitář, kompatibilní protokol a důvěryhodný klíč a nic, co peer pošle, nic nespouští. Není to silně konzistentní zámková služba — při rozdělení sítě si obě strany mohou nárokovat stejný rozsah a konflikt se po opětovném spojení pojmenuje s jedním vítězem. Nešifruje: spojení patří do privátní sítě nebo overlaye jako tailnet. Nepřekračuje WAN, neprochází NAT a nekopíruje zdrojové soubory — kód vlastní git; mesh nese to, co lidé a agenti říkají o své práci. A nic neodesílá, dokud osoba necommitne enabled: true a nevypíše klíče, kterým důvěřuje.

Mesh mesh experimentální

Mesh tohoto procesu: objevování (discovery) — ověřená pozorování dalších běžících instancí Majordomus v jednom registru — a spolupráce (cooperation) — ověřená spojení s důvěryhodnými runtime téhož repozitáře, která replikují relace, tvrzení, předávky a revize jedním žurnálem, jejž každý runtime skládá do stejného stavu. Objevení nic neuděluje; spojení se připouští po jednotlivých peerech a nic, co peer pošle, tu nic nespustí.

Důkazy

Co je zaručeno

Každé tvrzení, které tato funkce pojmenovává, se stavem, který deklaruje jeho řádek, verdiktem, který podporují zaznamenané běhy, a testem, který o něm rozhoduje.

  • ○deklarovaný stav: zaručeno ○zaznamenané důkazy: nespuštěno Dva runtimy jednoho repozitáře se propojí jen podepsaným handshake chráněným proti replay, který ověřuje protokol, identitu repozitáře a důvěru, a každé odmítnutí je typované a viditelné apps/majordomus-cli/tests/mesh_cooperation.rs
  • ○deklarovaný stav: zaručeno ○zaznamenané důkazy: nespuštěno Výhradní nárok učiněný na jednom runtime vylučuje překrývající se nárok na každém propojeném runtime a souběžné nároky se všude vyřeší na jednoho pojmenovaného vítěze apps/majordomus-cli/tests/mesh_cooperation.rs
  • ○deklarovaný stav: zaručeno ○zaznamenané důkazy: nespuštěno Runtimy obsluhující různé repozitáře nikdy nevytvoří kooperativní spojení, ani když se navzájem objeví apps/majordomus-cli/tests/mesh_cooperation.rs
  • ○deklarovaný stav: zaručeno ○zaznamenané důkazy: nespuštěno Runtime, který přestane vysílat tep — zhroutil se, byl zabit nebo oddělen sítí — vyprší u svých peerů v deklarované lhůtě, jeho nároky přestanou vylučovat a jeho restart se znovu připojí jako týž runtime bez duplikátu apps/majordomus-cli/tests/mesh_cooperation.rs
  • ○deklarovaný stav: zaručeno ○zaznamenané důkazy: nespuštěno Runtimy propojené jen přes relay konvergují k jednomu digestu stavu, každá událost je držena jednou, bez smyčky replikace apps/majordomus-cli/tests/mesh_cooperation.rs
  • ○deklarovaný stav: zaručeno ○zaznamenané důkazy: nespuštěno Samostatné linuxové uzly na skutečné síti se navzájem objeví přes multicast, propojí se, sdílejí claimy a předávky a zotaví se z rozdělení sítě i pádu, v laboratoři, kterou CI spouští test/cases/414_mesh_lab_evidence.sh
  • ○deklarovaný stav: zaručeno ○zaznamenané důkazy: nespuštěno Objevený uzel nezíská žádné provádění ani oprávnění tím, že byl zaslechnut; stav meshe smí změnit jen podepsaný provoz od propojeného uzlu a důvěra označuje záznamy podle explicitní politiky, jejíž výchozí hodnota je deny_unknown apps/majordomus-cli/tests/mesh.rs
  • ○deklarovaný stav: zaručeno ○zaznamenané důkazy: nespuštěno Každé pozorování objevování konverguje do jednoho omezeného registru, deduplikovaného podle identity uzlu a runtime napříč zdroji, chráněného proti replay na úrovni instance, a každý povrch tento registr promítá a nedrží žádné vlastní peery apps/majordomus-cli/tests/mesh.rs
  • ○deklarovaný stav: zaručeno ○zaznamenané důkazy: nespuštěno Žádný objevovací socket meshe se neotevře, dokud repozitář necommitne zapnutou deklaraci meshe, a vypnutá či chybějící deklarace se hlásí jako důvod, ne jako chyba apps/majordomus-cli/tests/mesh.rs

Použití

Z příkazové řádky spustitelného souboru

Synopse každého, jak ji vypisuje nápověda samotného spustitelného souboru.

  • majordomus mesh identity [OPTIONS]

    Identita uzlu tohoto stroje, jen veřejná polovina; nepřítomnost je odpověď, nikoli chyba

  • majordomus mesh enrol [OPTIONS]

    Add this machine's public key to the mesh declaration's trust list, once; commit it to join

  • majordomus mesh doctor [OPTIONS]

    Prokažte předpoklady mesh na tomto stroji samotném: deklaraci, identitu, sockety, multicast, broadcast, protokol od začátku do konce a hostitelský firewall

  • majordomus mesh firewall [OPTIONS] [COMMAND]

    Co musí hostitelský firewall propustit pro deklarovaný mesh a zda to dělá; `apply` to propustí, jako root

  • majordomus mesh firewall apply [OPTIONS]

    Spustí příkazy, které povolí plán ve firewallu tohoto hosta; vyžaduje root a skončí s kódem 10, když odmítne nebo když firewall mesh stále nepovoluje

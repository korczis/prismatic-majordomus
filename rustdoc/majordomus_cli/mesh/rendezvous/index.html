Module rendezvous 

Source
Expand description

The rendezvous provider: discovery across segments multicast cannot cross. Every Majordomus server is a rendezvous — the mesh.register capability accepts a signed envelope and answers with the envelopes it holds — so a “mothership” is any node the declaration points at, not a different program and not a canonical database. The local registry stays the only truth; a rendezvous is one more source of observations, its failure stretches the retry and stops nothing else, and its answers are signed end-to-end: a poisoned rendezvous can withhold nodes, it cannot invent one.

use majordomus_cli::mesh::rendezvous::RendezvousProvider;
use majordomus_cli::mesh::provider::{MeshProvider, MeshProviderState};

// Before the manager starts it, a provider is stopped; with no endpoints declared
// there is nothing to register with, and starting it says so.
let provider = RendezvousProvider::new(vec![], 60);
assert_eq!(provider.id(), "rendezvous");
assert_eq!(provider.status().state, MeshProviderState::Stopped);

Enums§

RegisterError
Why one registration round-trip produced no answer to act on. Each is one failure of the endpoint, which the provider backs off from; the variants say which bound or which step a rendezvous broke, so that a test — or a person reading a log — can tell a hub that is down from one that answers more than it may.

Constants§

MAX_ANSWER_CANDIDATES
The most envelopes a dialer reads from one register answer: the answering node’s own and MAX_CANDIDATES. An answer that carries more is refused at the first envelope over the bound, before that envelope is parsed (I2704).
MAX_CANDIDATES
The most registry candidates a register answer carries besides the answering node’s own envelope: what a rendezvous answers and what a dialer accepts (I2133, I2704).
MAX_REGISTER_ANSWER
The largest register answer a dialer reads, as compact JSON: every candidate it accepts at twice the datagram bound an envelope was admitted under, and 4 KiB for the answer’s own fields. An answer over it is refused before a byte of it is parsed, rather than read up to the HTTP client’s general bound of 32 MiB (I2704).
REGISTER_PATH
The HTTP route mesh.register is served on. Named once, here: the capability declaration and this client read the same word.

Functions§

register
One registration round-trip: present envelope to the rendezvous at endpoint and read its answer, through the same minimal client the MCP bridge uses: over TLS to an https:// hub, in cleartext only to a hub whose address is not public (ADR 0220), with the reply held at most at MAX_REGISTER_ANSWER and its candidates at MAX_ANSWER_CANDIDATES: a rendezvous is somebody else’s process, and what it answers costs this one a bounded buffer and a bounded wait whatever it sends (I2704).

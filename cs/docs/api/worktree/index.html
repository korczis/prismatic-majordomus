HTTP API: worktree

Kam patří každý propojený git worktree tohoto repozitáře a kde který je. Kontejner je sourozenec primárního checkoutu pojmenovaný s `-wt`, cesta pod ním je název větve se zachovanou hierarchií a obojí se odvozuje z vlastní identity gitu — společného adresáře, registrovaných worktrees, větví — nikdy z registru, konfigurace nebo aktuálního adresáře. Worktree jinde je typovaná diagnostika s nápravou; migrace, která ji opraví, je operace příkazové řádky téže služby.

GET /api/v1/worktrees worktree.topology

Celá topologie

Repozitář, kontejner, trunk a jak bylo rozhodnuto, každý registrovaný worktree s jeho postavením (primary, canonical, misplaced, detached, missing), jeho necommitnutou prací, vzdáleností od upstreamu a úkolem, který jeho větev prokazatelně jmenuje, každá lokální větev s worktree nebo bez něj a zda je způsobilá k úklidu, každá diagnostika s kódem a nápravou a součty. Čte se z gitu při každém volání: topologie se mění mimo tento proces.

Co by bylo potřeba, aby se každý worktree vrátil domů

Jeden krok na každý špatně umístěný worktree s větví: kde je, kam patří, jak by se přesunul, necommitnutá práce, která se přesouvá s ním, a co ho blokuje; plus výjimky, které migrace z podstaty nemůže řešit — detached worktrees, zastaralé registrace, primární checkout mimo trunk — každá s tím, co s ní člověk udělá. Plánování nic nemění; `majordomus worktree migrate` jej aplikuje s otiskem pořízeným před každým přesunem i po něm.

GET /api/v1/worktrees/trunk worktree.trunk

Jak daleko je checkout od vzdáleného trunku

`HEAD` checkoutu a lokální větev trunku, každé započítané proti vzdálenému sledovacímu trunku — commity pozadu a napřed, přičemž probíhající merge počítá, co přináší — k poslednímu fetchi, jehož čas je součástí odpovědi; posuzováno proti `checkout.trunk_distance` politiky jako `current`, `lagging`, `stale`, `unjudged` (není deklarován práh) nebo `unmeasured` (není vzdálený trunk), s příkazy, které ho aktualizují. Co vykresluje doctor a co o stromu, který server poskytuje, říkají `server.status` a instrukce MCP (`project.a-checkout-serves-the-current-trunk`). Nic nestahuje a nic nezapisuje.

GET /api/v1/worktrees/uncommitted worktree.uncommitted

Necommitnutá práce v propojených worktree a co ji drží

Každý propojený worktree, jehož index nebo pracovní strom drží změny, které žádný commit nenese: kolik cest (staged, unstaged, untracked, conflicted), kdy byla provedena nejstarší změna (nejstarší čas úpravy mezi změněnými cestami, u smazané ho zastupuje stav souboru indexu) a co práci drží — záznam aktivní úlohy, otevřená epizoda, která není opuštěná, nebo proces, jehož pracovní adresář je uvnitř. Práce, kterou nic nedrží a která je starší než práh, je `abandoned`, s příkazem, který by ji dostal na vzdálený ref `rescue/`; ten se navrhuje, nikdy nespouští. Práh je `session.stranded_after` z politiky, pokud `older_than` nejmenuje jiný. Čte každý worktree a žádný nezapisuje: každý status běží bez volitelných zámků, takže se neobnovuje žádný index.

  • query
  • behaviorally_verified
  • vyžaduje se měření výkonu
  • cache vypnuta
  • Nástroj MCP majordomus_worktree_uncommitted
  • $ worktree uncommitted

Parametry dotazu

názevtyppovinnépopispříklady

Putuje v JSON příkazů worktree create, ensure, migrate a repair, označené outcome, takže čtenář větví podle jednoho slova, místo aby parsoval řádek:

use majordomus_cli::worktree::HooksPath;

let set = HooksPath::Set {
    path: "/r-wt/fix/x/.githooks".into(),

assert_eq!(json["outcome"], "set");
assert_eq!(json["path"], "/r-wt/fix/x/.githooks");

title = "I4371 — An adopter's pull-request and trunk projection workflows are rendered from the tool by `majordomus update`, pinned to a release digest written into the workflow, with a read-only derive job apart from the writing one"
description = "A new projection kind, a workflow, is declared in the adopter's .ai/repo/policy.yaml `projections` list beside the provider bootstraps (for example `- workflow: github-pr-meta` with `target: .github/workflows/pr-meta.yml`); the policy schema and its generated allow-list admit the key, and an entry carries exactly one of provider and workflow. Its templates ship in the tool under share/ci/github/{pr-meta,projection}.yml.tmpl, which the release archive already carries because scripts/release-package copies share/ whole. `majordomus update` renders them from the adopter's .ai/repo/ci/pr-meta.yaml and .ai/repo/ci/github.yaml (trigger, concurrency, actor bound, default branch) and stamps them with a `#` comment, since the provider stamp is an HTML comment that is not YAML, so that `majordomus doctor` reports a hand edit, and a rendering that differs from what the current template and models produce, as drift. A rendered workflow installs the release that pr-meta.yaml `install.version` names, for the runner target `install.target`. The archive's sha256, a 64-hex digest, is written into the workflow text by `majordomus update`. It is taken from a declaration (pr-meta.yaml `install.sha256`, the line of that release's SHA256SUMS for the runner's archive), never fetched at run time, and update renders no workflow while the version or the digest is missing or the digest is not 64 hex. The install step downloads with `curl --fail --retry <n> --connect-timeout <s>`, runs `sha256sum -c` against the pinned digest in the same step before the binary runs, checks that the installed version is the pinned one, carries `timeout-minutes`, and never pipes a download to a shell or substitutes one into a command. The pull-request workflow runs on pull_request_target with the default branch checked out; it fetches the head and reads it as data with git, and never executes it. Its workflow-level permissions are empty, and it has two jobs, whose permissions the pr-meta.yaml model declares per job (`jobs.derive.permissions` and `jobs.project.permissions`; `actor.job` stays project). `derive` (permissions contents: read, pull-requests: read, issues: read, the issue read being what finds each record's GitHub number) runs the forge command's read-only verb, `majordomus forge render --prs --pr <n> --out <file>`, including any declared `facts:` command, and uploads that majordomus.forge-plan/v1 file of facts and owed writes as an artifact (I4370's hand-off). `project` (permissions contents: read, pull-requests: write, issues: read) needs derive, downloads that artifact and runs `majordomus forge apply --from <file>` on it, which derives nothing and executes no `facts:` command. The trunk workflow runs on push to the default branch with contents: read and issues: write, and its phases are github.yaml's owed, apply and prove, where prove is `majordomus forge check`, never scripts/ci/github-check, which is not shipped. Every job and every network step carries its own timeout and a bounded retry, and no step uses continue-on-error."

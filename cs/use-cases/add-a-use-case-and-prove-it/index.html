Přidejte případ užití a nechte ho nástrojem dokázat

Vytvořte scaffold návrhu pro nepokrytý příkaz, zvalidujte ho, spusťte jeho scénář proti skutečnému nástroji a sledujte, jak se pokrytí posune.

○zaručeno Rozšířenípokročilýmaintaineragentzapisuje stav

Situace

Příkaz získal chování a nikdo nezapsal, co s ním člověk dělá. Dokumentace se rozejde v den, kdy se napíše ručně, a odstavec nic nedokazuje.

Scénář

setup: installed
given:
  - 'Majordomus installed; the skeleton seeds the use-case section with no use case yet'
steps:
  - id: nothing-yet
    run: ['usecase', 'list']
    note: 'the section exists and is empty'
    expect:
      exit: 0
      stdout_contains: ['use cases: 0 in']
  - id: the-gaps
    run: ['usecase', 'coverage']
    note: 'every public command is a target; a fresh policy reports gaps and fails on none'
    expect:
      exit: 0
      stdout_contains: ['^command +doctor +0 +0 +0 +gap +advisory']
  - id: scaffold
    run: ['usecase', 'scaffold', '--for', 'command:doctor']
    note: 'a draft from what the registry, the fixture and the claims already know; nothing in it is verified'
    expect:
      exit: 0
      stdout_contains: ['wrote: \.ai/repo/use-cases/doctor-draft\.md']
  - id: validate
    run: ['usecase', 'validate']
    note: 'the draft resolves: its command, setup and category exist'
    expect:
      exit: 0
      stdout_contains: ['usecase validate: 0 failure']
  - id: run-it
    run: ['usecase', 'run', 'doctor-draft']
    note: 'the scaffolded scenario executes the real command in a disposable repository'
    expect:
      exit: 0
      stdout_contains: ['doctor-draft +pass']
  - id: still-a-gap
    run: ['usecase', 'coverage']
    note: 'a draft never counts; coverage moves when the use case is active'
    expect:
      exit: 0
      stdout_contains: ['^command +doctor +0 +0 +0 +gap']
then:
  - 'a use case is a file; everything else (the page, the links, the tally) follows'
  - 'a draft can run but cannot cover: status is authored, maturity is observed'

Výsledek

usecase scaffold zapíše koncept s fakty, která nástroj už má, usecase run provede jeho scénář proti skutečnému nástroji a zaznamená důkazy a usecase coverage říká, co stále chybí. Koncept se nepočítá, dokud není aktivován.

Scénář

Provedeno proti skutečnému nástroji v repozitáři připraveném pomocí installed, při každém generování tohoto webu. To, co následuje, není popis toho, co by se mělo stát; je to to, co se stalo.

Proč to nástroj ví

Řetězec od této stránky ke kódu: případ užití jmenuje příkazy, pravidla a tvrzení; každé pravidlo se dispatchuje z registru a každé tvrzení jmenuje test, který ho dokazuje; scénář výše provedl příkazy. Nic v tomto řetězci není text o záměru.

  • majordomus usecaseSpustitelné případy užití: výpis, zobrazení, validace, běh proti skutečnému nástroji, pokrytí, dopad, kostra.
  • majordomus doctorKontroluje jen governance: je samotný Majordomus zdravý a je každé vynucování, které deklaruje, tady skutečně zapojeno?

Pravidla, díky nimž platí

  • ✕blokující Pokrytí případy užitíKaždý veřejný příkaz a každé zaručené tvrzení a nástroj MCP, které politika žádá, je pojmenován a spuštěn alespoň jedním aktivním případem užití, jehož scénář se provádí proti skutečnému nástroji; mezera je selhání nebo hlášení podle politiky, nikdy mlčení.
  • ✕blokující Integrita kataloguKaždý případ užití a aplikace popisuje nástroj pojmy, které nástroj má — každý příkaz, doktrína a tvrzení, které jmenuje, existuje, a oba katalogy na sebe odkazují v obou směrech.

Uplatněné záruky

  • ○zaručeno Případ užití ani aplikace nemůže jmenovat příkaz, doktrínu nebo tvrzení, které neexistuje, a oba katalogy se nemohou rozcházet v tom, co se na co vztahuje
  • ○zaručeno Každý veřejný příkaz je pojmenován a spouštěn aktivním případem užití, zaručené tvrzení nebo nástroj MCP bez něj je pojmenovaná mezera a politika říká, které mezery shodí doctor, check a finish

Související případy užití

Vypočteno z toho, co sdílejí: tvrzení, pravidla, příkazy, kategorie, aplikace. Tento seznam nikdo neudržuje.

  • Rozšiřte, co spustitelný soubor poskytuje, přidáním souboru, nikdy jeho přebuildovánímPřidejte do .ai/ pravidlo, prompt nebo uzel znalostí a nechte je objevit se jako zdroj MCP, HTTP route a položka reference, se stejným binárním souborem.
  • Dokázat, že pravidlo se skutečně vynucuje, a není jen napsanéOdpovědět na "je toto pravidlo skutečné?" příkazem, ne čtením zdroje.
  • Řekněte jednou, k čemu vaše práce slouží, a nechte to říkat každý povrchZaznamenejte provozní způsob selhání jako jeden soubor a nechte na něj odpovídat příkazovou řádku, API, MCP i web, aniž by se kdekoli registroval.
  • Důvěřujte politice a profilům až po jejich validaciProkažte, že se kanonická politika zparsuje a má deklarovaný každý potřebný klíč, že se zparsuje každý profil a výchozí existuje a že to, co politika deklaruje jako vynucené, je to, co skutečně běží.
  • Převzít repozitář, který už má vlastní pravidlaNainstalujte dozorovou vrstvu do repozitáře s ručně psaným CLAUDE.md tak, aby nástroj nepřevzal vlastnictví souboru, který napsal někdo jiný.

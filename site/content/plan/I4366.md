description = "Two readings that I2901's grammar does not fix. (1) worktree/state.rs issue_of compares a branch component with a declared id ASCII-case-insensitively, keeping its rule otherwise (the component equals the id, or begins with the id followed by `-`), and still returns the declared id, so feat/v603-timeline-pinch names V603. Every caller inherits it: delivery's branch_names, integration/mod.rs:1154, capability/builtin/devtask.rs:180, worktree/trace.rs:612, worktree/service.rs:669 and :861, and intent_realization.rs:508. issues_named and named_by keep finding an id anywhere in the branch bounded by non-alphanumerics, as they do today. (2) plan/delivery.rs merge_subject reads a two-parent commit whose subject ends in ` (#N)`, which GitHub appends to a merge commit titled by its pull request (merge_commit_title=PR_TITLE), as the merge of pull request N, with the subject minus that suffix as its title; the body is not read for this form, because under merge_commit_message=PR_BODY its first line is the pull request's body, not its title. A two-parent commit with no trailing ` (#N)` and no `Merge pull request #`, `Merge branch '` or `Merge remote-tracking branch '` prefix stays what it is today: a merge with no pull request, branch or title. This repository's derived merges ('merge: master (6c79dcf68cf) into I4241, derived') are therefore never read as pull requests. Under PR_TITLE plus PR_BODY a merge commit carries no branch, so in an answer at a commit a pull request that named its id only in its branch cannot be attributed. The delivery report then lists such a merge under a new report-level `unattributed` list (commit, pull request, title, reason): the merge carries no branch, and the live answer reads the pull request's branch from the forge's merged-pull-request observation. It is never dropped silently. A merge the live answer attributes through the forge is not listed. The merge-subject reader is one shared function, merge_subject in plan/delivery.rs or a module both callers use: it is the only code that reads a pull request, branch or title from a merge subject, and the first-parent changelog of I4368 calls it rather than matching subjects of its own."

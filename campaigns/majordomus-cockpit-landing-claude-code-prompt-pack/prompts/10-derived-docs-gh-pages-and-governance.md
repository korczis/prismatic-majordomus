# PROMPT 10 — Documentation, GitHub Pages, rules, doctrines, governance

## Mission

Document and enforce the new landing architecture so future work does not regress into hardcoded frontend sediment.

## Documentation

Update repository-standard docs covering:

- purpose of Cockpit landing
- canonical landing projection
- data sources
- attention/resume semantics
- actions/workflows
- realtime updates
- extension path
- troubleshooting
- how to add a new capability/workflow/entity without editing multiple consumers

## Generated docs

Inventories that can be derived should be generated from canonical registries.

Do not maintain manual lists of capabilities, workflows, statuses or runtime services in prose.

## GitHub Pages

Ensure relevant architecture/product documentation is included through the existing site generation pipeline.

Validate navigation, links and generated content.

If Cockpit screenshots/examples are generated by repository tooling, update them appropriately. Do not add stale screenshots manually if the repository has a better mechanism.

## Governance

Add/update repository-native rule/doctrine/policy enforcing concepts equivalent to:

> Cockpit MUST NOT independently own development-domain inventories or semantics already represented by canonical backend registries/types.

> High-value landing content MUST be derived from canonical project/runtime state rather than maintained as static dashboard configuration.

> New canonical discoverable entities MUST automatically flow into eligible Cockpit/CLI/API/MCP/docs projections without consumer-specific registration where architecture supports it.

> Machine-discovered collections exposed to users MUST have deterministic ordering.

## Executable enforcement

Where practical, add validator/gate checks detecting:

- duplicate frontend catalogs
- schema drift
- generated docs drift
- unknown workflow/capability references
- stale hardcoded status mappings

## Acceptance

The architecture is not merely documented. CI/validation should make the easiest future path the correct one.

# v1.0.1's release run 42569641430 failed on attempt 1 when the macos-aarch64 build met a transient HTTP 504 from rustup's installer and fail-fast cancelled the other five builds; gh run rerun 42569641430 --failed ran them again and the release published (7 assets, 2026-11-09T17:44Z); the run still concludes failure because its live job found the homepage offering 1.0.0 before the record pull request #2991 landed

Observed as workaround about .github/workflows/release.yml in episode s-20261110050845-b1a4.

# Evidence

- `file:.github/workflows/release.yml`

# Evidence

- `gh run view 42569641430 --attempt 1 --json jobs` on 2026-11-10: the macos-aarch64 build failed and the other five builds are cancelled, publish, live, smoke and image skipped; its failed log stops in dtolnay/rust-toolchain's "Install rustup if needed" step. `.github/workflows/release.yml` declares the build matrix `fail-fast: true` (line 105) deliberately ("a release missing a platform is not a release", line 99).
- Attempt 2 (`gh run rerun 42569641430 --failed`): every build, publish, image and smoke job success; `gh release view v1.0.1` published 2026-11-09T17:44:09Z with 7 assets. Its `live` job failed with exit 10: "FAIL the homepage offers 1.0.0 and /releases/latest.json names 1.0.1", because the record pull request #2991 merged only at 2026-11-09T19:50:28Z; the run's conclusion stays failure for that reason, not the 504.
- So a transient installer error in one platform build is answered by a rerun of the failed jobs, which reruns the cancelled builds too; a release run's conclusion is read from its jobs.

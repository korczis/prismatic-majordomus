proceed.step

One step of a session that proceeds, as a work order a loop acts on: `do`, the capability to run next and its input — `devtask.implement` for the issue `proceed.plan` selects, under the idempotency key `devtask.implement` defaults to, so that a repeated order is one execution; `fan_out`, the other free READY issues declared parallel safe that share no path with it, at most four; `report`, what to announce on the board, as `peers.announce` takes it; and `next_due_at`, the next five-minute boundary after `at`, when to step again. Given an `intent`, only the issues serving its unmet criteria (`intent_realization.work`) are ordered, and an intent whose every criterion has current evidence, or that is satisfied, cancelled or superseded, answers `done` with nothing to run and nothing scheduled; without one, the whole plan is stepped and is done when no unfinished issue is left. Each item names the model `models.route` selects for a worker and the effort of the issue's profile. A provisional decision orders nothing. The same state answers the same order: `key` is the digest of everything but the moment, so a step repeated over unchanged state carries the same key at any later time. Writes nothing.

output · WorkOrder

One step of a session that proceeds: what to run now, what may run beside it, what to tell the board and when to step again.
propertytyperequireddescription
at string yes The moment the step was taken at.
do one of 2 no The capability to run next and its input; absent when the step waits or is done.
done boolean yes Whether there is nothing left to do: the intent's realisation is met (or it was cancelled or superseded), or, for the whole plan, no unfinished issue is left. A done order runs and schedules nothing.
fan_out array yes Independent items that may run in parallel with do, each a worker of its own; empty when nothing may.
intent one of 2 no The intent the step was taken for, as its realisation stands; absent for the whole plan.
key string yes The order's identity: the digest of every field but next_due_at, at and sources. The same state answers the same key at any moment.
next_due_at string | null no When to step again, RFC 3339 in UTC: the next boundary of the cadence after at. Absent when the order is done.
outcome reference yes What the step decided.
reason string yes One sentence a reader can check against the decision and the intent.
report reference yes What to announce on the board, as peers.announce takes it.
sources array yes What the decision was read from, as proceed.plan says it.

Module served_executable 

Source
Expand description

A server runs from a copy of a build output, so that a rebuild never replaces the file a live lease names (I2059).

cargo build writes target/debug/majordomus in place. A shared server started from that path is, from the next build on, serving code that is no longer on disk: since #747 its lease is superseded and since I1502 it stops calling itself ready, so a diagnostic build in the primary checkout took the owner’s server — and the address it had been told to bind — away from every session attached to it (2026-10-08, .ai/local/state/mcp/server.log).

The process that is about to serve — majordomus mcp, or majordomus serve with no subcommand — therefore re-executes itself from a copy when the file it was started from is a cargo build output: <profile dir>/served/majordomus-<mtime>-<size>, named by the identity of the build it copies — a second link to the build’s file where the filesystem allows one — made once per build, never replaced, and shared by every server started from it. A rebuild replaces target/debug/majordomus and leaves the copy alone; the running server stays ready on its address until something restarts it on purpose (serve stop, its idle timeout), and a launcher of the new build attaches to it rather than superseding it, because a lease naming another path makes no claim (lease::superseded).

A build output is recognised by cargo’s own mark, CACHEDIR.TAG in the directory above the profile directory. An installed release (a versioned directory of its own), an executable named through a directory without that mark, and a copy itself (whose parent is served/) are run where they are. Copies older than a week are removed when a new one is made. Every failure — a full disk, a read-only target directory — runs the server in place and says so on stderr, which is the behaviour before this module existed.

use majordomus_cli::served_executable::copy_target;
use std::path::Path;
// a release install, or any directory cargo did not mark, is served where it is
assert_eq!(copy_target(Path::new("/opt/majordomus/libexec/majordomus-cli")), None);

Functions§

copy_target
Where the server started from exe should run from instead, when exe is a cargo build output: <dir of exe>/served/<name>-<mtime>-<size>. None for anything else, and for an executable that cannot be stat’ed.
serve_from_a_copy
When command may hold the lease and this executable is a cargo build output, run this process from a copy of it by replacing the process image (same pid, same standard streams, same arguments). Returns only when it does not: another command, an executable that is not a build output, or a copy that could not be made or run — the last two say why on stderr, and the caller then serves in place.

# M00: Reality audit and reconcile

## Outcome
Audit master, open PRs, `.ai/`, UI rules, route topology, actual endpoints, design assets and supplied references; inventory reuse vs gaps.

## Mandatory preflight
Read `MASTER-EXECUTION-PROMPT.md`, relevant contracts and live canonical sources. Trace reuse, selected PRs, current rules, gates and dependencies. Write progress to canonical milestones/issues rather than treating this file as state.

### M00-01: Enumerate canonical routes and real endpoints

**Implementation:** inspect the actual implementation; identify owner and dependents; introduce the smallest composable patch; avoid duplicative registries; migrate legacy consumers; implement both valid and failure paths. Tie the change to an existing or newly justified canonical issue with clear intent satisfaction criteria.

**Acceptance:** behavior is functional over a real repository, exposed through the proper current route/capability, consistent with backend truth; absent or unavailable signals are not silently fabricated. Check optimistic/concurrent/restart behavior where relevant. Ensure permissions and scope rules are preserved.

**Proof:** focused unit/contract tests; adversarial or negative case; rendered SSR smoke; browser interaction at mobile and desktop when visual; derived artifacts check; `.ai/` executable gate; docs update; diff review. Capture exact commands, duration, commit SHA and issue/evidence references.

**Delivery:** integrate when independent and passing, run canonical version analysis (don't force bump for every change), release/deploy if eligible and authorized; verify live route and provenance. Do not mark complete without captured proof.

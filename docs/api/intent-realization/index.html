HTTP API: intent_realization

Which work realises which intent: every task of this checkout's ledger with the episodes, providers and handovers that carried it, every closed session record and every claim on the peer board, joined through the plan to the intents they serve, each link marked declared, observed, derived or inferred; each intent's unmet criteria with the issues serving them; and the drift between closed work and current evidence. Derived on every read and stored nowhere, so an intent outlives every session and provider that worked on it.

GET /api/v1/intents/explain intent_realization.explain

Why an intent stands where it stands

One intent explained from the derivations alone: a sentence for its stage naming each milestone's derived status, a sentence per criterion naming its evidence state, the plan's coverage of it and the command that reproduces it, a sentence for the work and providers realising it, and each drift finding; beside them the derived intent, the coverage of its criteria, its realization and the work linked to it.

GET /api/v1/intents/realization intent_realization.work

Which work realises which intent, and what each still lacks

Every unit of work this checkout can see — ledger tasks with their episodes, providers and handovers, closed session records, peer claims — with every intent it realises through issue, milestone and criterion, each link's provenance (declared: the work cites the issue; observed: its episode moved the issue; derived: its branch names the issue; inferred: only an open issue's scope overlaps) or the first missing link; every intent with its unmet criteria and the issues serving each, the work and providers realising it, and its drift: closed_work_contradicted when every milestone is DONE and a criterion's evidence is stale or failing, closed_work_unproven when it never existed, criterion_closed_unmet when every serving issue is DONE and the criterion is not met; and where the stage and the verdict disagree (ADR 0107), evidence_ahead_of_plan when the verdict is satisfied while the stage is planned or executing, closed_work_not_satisfied when every milestone is DONE and the verdict is unsatisfied or unknown. Live work serving no intent is a warning.

IntentEpisode

object
One execution episode of a piece of work, and the provider that ran it when a record says. A provider is never guessed: an episode opened by hand has none.

use majordomus_cli::intent_realization::IntentEpisode;
let e = IntentEpisode {
    session: "s-1".into(),
    provider: "codex".into(),
    provider_session: String::new(),
};
assert_eq!(e.provider, "codex");
propertytyperequireddescription
session string no The episode id, s-...; empty for a peer's connection, which is not an episode.
provider string no The provider, as its own events or the peer's client name it; empty when unknown.
provider_session string no The provider's own session identity, when recorded.

IntentLink

object
One link from a piece of work to an intent: through which issue and milestone, serving which of its criteria, read from which fact, known how.

use majordomus_cli::intent::IntentStage;
use majordomus_cli::intent_realization::{IntentLink, IntentLinkProvenance, IntentLinkVia};
let l = IntentLink {
    intent: "intent-lifecycle".into(), stage: IntentStage::Executing,
    milestone: "intent-lifecycle".into(), issue: "I1900".into(),
    criteria: vec!["stage-is-derived".into()],
    via: IntentLinkVia::BranchIssue, provenance: IntentLinkProvenance::Derived,
};
assert_eq!(l.provenance, l.via.provenance());
propertytyperequireddescription
intent string yes The intent.
stage IntentStage → IntentStage yes Its derived stage.
milestone string yes The milestone that links the issue to it.
issue string yes The issue that links the work to that milestone.
criteria array of string no The criteria of this intent the issue declares it serves; empty when it declares none.
via IntentLinkVia → IntentLinkVia yes The fact the link was read from.
provenance IntentLinkProvenance → IntentLinkProvenance yes How the link is known, from via.

Used by IntentRealizedWork

IntentLinkProvenance

"declared" | "observed" | "derived" | "inferred"
How a link from a piece of work to an issue is known, strongest first.

use majordomus_cli::intent_realization::IntentLinkProvenance;
assert_eq!(
    serde_json::to_string(&IntentLinkProvenance::Inferred).unwrap(),
    "\"inferred\""
);
assert!(IntentLinkProvenance::Observed < IntentLinkProvenance::Derived);
  • declaredThe work names the issue itself.
  • observedA recorded event shows the work's episode moving the issue.
  • derivedThe branch the work ran on names the issue, by the worktree naming rule.
  • inferredNothing stronger exists, and an open issue's scope overlaps the work's scope.

Used by IntentLink IntentWorkRef

IntentLinkVia

"named_issue" | "moved_issue" | "branch_issue" | "scope_overlap"
The fact a link was read from.

use majordomus_cli::intent_realization::IntentLinkVia;
assert_eq!(serde_json::to_string(&IntentLinkVia::BranchIssue).unwrap(), "\"branch_issue\"");
assert_eq!(IntentLinkVia::ScopeOverlap.provenance().as_str(), "inferred");
  • named_issueThe claim or the task's own words cite the issue by id.
  • moved_issueA plan transition in the work's episode, or the session record's issues.
  • branch_issueThe branch name carries the issue id.
  • scope_overlapAn open issue's scope overlaps the work's scope.

IntentRealizationView

object
One intent, realised: how far reality is from it, the work realising it and by whom, and the drift between closed work and current evidence.

use majordomus_cli::intent::IntentStage;
use majordomus_cli::intent_realization::IntentRealizationView;
let v = IntentRealizationView {
    intent: "x".into(), title: "X".into(), stage: IntentStage::Verifying,
    criteria: 2, met: 1, unmet: vec![], work: vec![], providers: vec![], findings: vec![],
};
assert!(v.met < v.criteria);
propertytyperequireddescription
intent string yes The intent.
title string yes Its title.
stage IntentStage → IntentStage yes Its derived stage.
criteria integer (uint) yes How many criteria it declares.
met integer (uint) yes How many have current evidence.
unmet array of IntentUnmetCriterion → IntentUnmetCriterion yes Every criterion without current evidence.
work array of IntentWorkRef → IntentWorkRef yes Every unit of work linked to it, strongest link first.
providers array of string yes Every provider that ran work linked to it, each once.
findings array of IntentFinding → IntentFinding yes Drift between the plan's closure and the evidence.

IntentRealizedWork

object

use majordomus_cli::intent_realization::{IntentRealizedWork, IntentWorkKind, IntentWorkUnit};

work IntentWorkUnit → IntentWorkUnit yes The work, as recorded.

unlinked string | null no When it realises none: the first link that is missing.

IntentUnmetCriterion

object
A criterion an intent still lacks, with the issues that declare they serve it.

use majordomus_cli::intent::IntentEvidenceState;
use majordomus_cli::intent_realization::IntentUnmetCriterion;
let c = IntentUnmetCriterion {
    id: "surfaces-agree".into(), criterion: "the surfaces agree".into(),

propertytyperequireddescription
id string yes The criterion id.
criterion string yes What must be observably true.
evidence string yes The kind of evidence that settles it.
state IntentEvidenceState → IntentEvidenceState yes Why it is not met.
reproduce string | null no The command that produces its evidence, when one is known.
issues array of string no The issues declaring they serve it, in plan order.

IntentWorkKind

"task" | "peer_claim" | "session_record"
Which record a unit of work was read from.

use majordomus_cli::intent_realization::IntentWorkKind;
assert_eq!(serde_json::to_string(&IntentWorkKind::PeerClaim).unwrap(), "\"peer_claim\"");
  • taskA task of this checkout's ledger: the durable unit a handover continues, across every episode that worked on it.
  • peer_claimA claim a peer announced on the shared server's board.
  • session_recordA closed session record of the shared layer whose episode this checkout's ledger does not hold — another machine's or another checkout's work.

IntentWorkUnit

object
One unit of work as its records describe it, before it is joined to any intent.

use majordomus_cli::intent_realization::{IntentWorkKind, IntentWorkUnit};
let unit = IntentWorkUnit::new(IntentWorkKind::Task, "t-1");

propertytyperequireddescription
kind IntentWorkKind → IntentWorkKind yes Which record it was read from.
id string yes Its identity in that record: a task id, a session id, or <peer>/<claim>.

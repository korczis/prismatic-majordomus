pub fn uncommitted_in(worktree: &Path, rev: &str) -> Option<bool>
Expand description

Does every uncommitted change in this work tree already hold what rev holds at that path, in the index and in the work tree? Some(true) for a clean work tree too. Some(false) when any path differs (a staged version the trunk lacks included), when a conflict is unresolved or an operation (merge, rebase, …) is in progress, for a path that is a symbolic link or a directory git reports whole (a nested repository), and for a path the file system will not describe: none of those is ever judged equal. None when git cannot read the work tree, rev, the index or a file’s content.

use majordomus_cli::worktree::landed::uncommitted_in;
let dir = tempfile::tempdir().unwrap();
assert_eq!(uncommitted_in(dir.path(), "main"), None, "not a repository");

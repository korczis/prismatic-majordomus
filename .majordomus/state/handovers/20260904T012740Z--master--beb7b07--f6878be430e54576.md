# Objective

Complete the final audit of the continuity subsystem and fix the design gap a peer session
found: a task record committed to a shared branch makes the finish contract global to the
repository.

# Current State

The subsystem is implemented, tested, documented and pushed. This record is being closed
immediately because it is itself blocking another worktree: `finish --check` in the
pre-push hook reads the committed `current.yaml`, which travels with the branch, so a
second worktree inherits this task's scope and cannot push anything outside it.

The record carries `repository_id`, `branch` and `head` but not `worktree`, so a record
written in one checkout is indistinguishable from one written in another. "One active task
per checkout" is enforced at `start` and then not represented in the record.

# Next Action

Add a computed `worktree` field to the task record, and make `check` and `finish --check`
treat a record whose worktree is not the current one as another checkout's task: reported,
never enforced. Then re-run the suite and add a case that proves a foreign record does not
gate this worktree.

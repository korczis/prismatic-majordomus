# M06: One MCP capability projection, reliable protocol transports

Audit CLI registry, capability descriptors, `Context::execute`, MCP stdio and Streamable HTTP, tool/resource discovery, feature negotiation and version compatibility. MCP must expose canonical capabilities with one authorization, typed input validation and error taxonomy. Derive operation metadata and routes from registry instead of independent MCP-specific lists. Preserve existing resource behavior and do not serve unrendered prompt templates as completed prompts. Keep read-only default unless a mutation is explicitly authorized and audited. Verify schema names and IDs compatible with current clients.

Treat client attachments, HTTP sessions, initialize, session ID, termination, reconnect after 404, timeout, cancellation, in-flight tasks, backpressure and malformed JSON-RPC correctly. Zero logs/progress on stdio stdout. Prove one MCP client does not destroy server while other clients/UI use it. Connected mesh actions should be exposed only through vetted typed capabilities, never generic unauthenticated peer executor. Claude Code, Codex, Gemini and other declared integrations must be discovered from canonical provider metadata, installed where supported and diagnosed if absent, not assumed present.

Tests: spec-valid stdio transcript, real HTTP initialize/calls/DELETE, reconnect, many clients and session isolation, tool discovery parity, serialization roundtrip, authz failure, oversized payload, disconnect mid-request, unavailable mesh, backwards schema contract and docs drift. Gate: clients work out of box with correct launch config and all visible tools map to canonical operation IDs.

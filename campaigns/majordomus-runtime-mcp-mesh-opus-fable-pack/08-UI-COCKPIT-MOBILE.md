# M08: Human-first Majordomus UI and Cockpit

Inspect current Cockpit, `majordomus ui`, Flowbite/Tailwind/Alpine, design system and interactive charts/graphs already in repo. Preserve actual stack where supported. Build/repair high-level control center as a projection, not a replacement backend: overview, runtimes, mesh topology, trusted/untrusted peers, sessions, agents, tasks, worktrees, handovers, reviews, intents, operational health, audit/events and actionable diagnostics. Implement entity drilldown and cross-navigation to canonical IDs; actions use existing typed operations and policy checks. Distinguish online/offline, known/stale, trusted/untrusted, connected/degraded, confirmed/inferred. Display evidence and explanation for decisions and conflicts.

Mobile first: 320px width, touch navigation/drawers, keyboard accessibility, focus management, aria semantics, dark/light, reduced motion, loading/error/empty/reconnect flows; no horizontal overflow in task tables, no frozen UI when mesh flaps. Visualize topology via Cytoscape only if worthwhile and dynamically sourced; accessible textual/list alternative mandatory. Use charts only when data exists. No mocked production states or demos masquerading as live. UI-first launch must bind proper server lifecycle; reconnect without losing durable state. Support deliberate trust enrollment/revocation with confirmable effects and clear boundaries.

Tests: browser E2E (mobile/desktop), network loss/reconnect, trust controls, peer disconnect, conflicting claims, task handover, permissions, stale status, XSS/path injection, keyboard/focus, no-console-errors, screenshot evidence and route deep links. Gate: user can complete primary coordination workflow without terminal, and all actions are visible consistently in CLI/MCP/API.

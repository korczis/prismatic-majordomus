# M02: Shared server lifecycle, installation and zero-friction bootstrap

Inspect current lease under `.ai/local/state/mcp/`, ownership election, stdio initiator lifetime, attach bridge, heartbeats, static port fallback and runtime endpoints. Harden atomic lease publication, no URL-before-ready race, process death detection, stale/corrupted leases, PID reuse, concurrent cold starts, ABA races, process groups, SIGTERM/SIGKILL recovery, ownership transfer, short partial writes, OS crashes, port collision, stale endpoint, cold cache and incompatible binary versions. Avoid unsafe unlink of another live owner's lease; use identity+generation fencing and OS-safe atomic operations. Ensure one usable server per checkout, not one globally for all repositories. Avoid multiple processes becoming writable authority accidentally.

Implement a single canonical `ensure/attach/start/stop/status/doctor` lifecycle behind existing operation registry, without adding redundant commands if equivalents exist. Entry paths: CLI, MCP stdio, HTTP/Swagger, cockpit, `majordomus ui`, direnv, installer and injected foreign repo. UI-first startup must work even when no MCP client launched; runtime must not depend on one interactive stdio client if other consumers need it. Explicit configurable lifecycle policy: interactive/transient vs persistent-on-demand. Do not start background services silently outside consent or violate host policy. One-line installer must verify checksums/signatures, manage PATH/direnv, avoid repo-embedded build on every entry, preserve user changes, support macOS and Linux and rollback partial installs. Maintain stdout/stderr MCP hygiene.

Tests: N concurrent first clients, corrupt/unpublished lease, killed owner, bridge orphan, port collision, foreign checkout, unexpected files, permission denied, no direnv, no git, offline. Measure cold/warm path and enforce repo-derived budget. Gate: idempotent repeated entry; deterministic diagnostic reason; no hung clients or unexplained duplicate servers.

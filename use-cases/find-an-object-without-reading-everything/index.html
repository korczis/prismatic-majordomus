Find an object of the layer without reading everything

Search durable records literally across kinds from the shell, and ask the shared server the same question over MCP with majordomus_search and majordomus_get.

guaranteed Serving the layer to AI clientsbasicagentread-only

Situation

A client wants the rule about scope, or the decision about the parser, and has the whole layer in front of it. Reading every file to find one is what makes agents slow and expensive; asking a person is what makes them wrong.

What you run

  • search <text>: durable records that contain the text, across kinds
  • knowledge nodes --kind <k>: the canonical objects of one kind, with identity
  • prompt list: the prompt assets, also served as resources
  • over MCP: majordomus_search, majordomus_get by majordomus:// URI, majordomus_list by kind

Outcome

One question, one answer, from the shell or from the server, without reading the layer end to end. The URI a client gets back resolves the same way everywhere.

The scenario

Executed against the real tool, in a repository prepared by active-task-records, every time this site is generated. What follows is not a description of what should happen; it is what happened.

given

  • ·an active task that has already produced a checkpoint, a decision and an open question

when

  1. 1majordomus search parser
  2. 2majordomus knowledge nodes --kind rule
  3. 3majordomus prompt list

then

  • ·the shell and the MCP server answer from the same files
  • ·a majordomus:// URI resolves the same way through the resource read, the tool and the HTTP route
  • ·no index has to exist for the literal search to work

Why the tool knows this

The chain from this page to the code: the use case names commands, rules and claims; each rule is dispatched from the registry and each claim names the test that proves it; the scenario above executed the commands. Nothing in this chain is prose about intent.

  • majordomus searchFind a durable record without reading all of them, in authority order.
  • majordomus knowledgeThe compiled index over what this repository states.
  • majordomus promptList, show and render the repository's own prompt assets, substituting known tokens only.

Over MCP the same layer is reached through majordomus_search, majordomus_get, majordomus_list (the MCP surface).

The rules that make it hold

  • blockingAI layer integrityThe repository's AI layer is real: the manifest declares a format this executable reads and every section it names exists, the checkout-local half is ignored by git and nothing under it is tracked, and no project data remains under the pre-.ai .majordomus/ path.
  • blockingPrompt integrityEvery repository-local prompt asset renders, and every token in it is one the renderer knows.

Guarantees exercised

  • guaranteedEvery repository-local prompt asset renders, and an unknown token is a failure
  • guaranteedDurable records are searchable literally, across kinds, without an index
  • guaranteedThe Rust executable serves the repository's AI layer to an MCP client over stdio, read-only, with protocol frames alone on stdout
  • guaranteedA majordomus:// URI resolves the same way through the MCP resource read, the majordomus_get tool and the HTTP object route, and majordomus://repository answers repository.info as a JSON document tagged builtin

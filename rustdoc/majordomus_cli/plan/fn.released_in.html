pub fn released_in(index: &Index, plan: &Plan, milestone: &str) -> String
Expand description

The release that carried a milestone: the first release record (.ai/repo/releases/v*.yaml, the tracked statement of a tag), in version order, whose commit: contains the merge of its last accepted issue, and UNRELEASED for a milestone that is not DONE or that no record’s commit contains yet. A milestone DONE with no issue was finished by its own evidence: the commit that wrote the latest recorded_at of that evidence stands in for the merge.

Records and not tags, because derived data must not depend on refs outside the tree: the answer is a function of the commit, and it changes only when a record lands. Releases before the first record have none, so work finished before it reads as the earliest release this layer records.

The merge is found through the commit that wrote the issue’s completed_at stamp — the oldest commit whose diff of the record adds or removes that text — and failing that through the latest merge whose message names the issue. A release commit containing either contains the merge that brought it to the trunk. This is mj_pj_m_released_in in lib/project.sh, command for command, so the two engines agree (test/cases/99_plan_capabilities.sh).

use majordomus_cli::plan::{released_in, Plan, UNRELEASED};
let plan = Plan::build(index);
for m in &plan.milestones {
    let release = released_in(index, &plan, &m.id);
    assert!(release == UNRELEASED || release.starts_with('v'));
}

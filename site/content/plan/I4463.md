description = "Both engines of the plan read one more thing from an issue's current_state: an open issue id that the text names as what the issue waits on. The phrases that make a mention a blocker are declared once, as data both engines read (beside the plan schema in share/, not as a constant in either engine): `completes when <ids> ... land`, `blocked by <id>`, `blocked on <id>`, `waits for <id>`, `waits on <id>`, `after <id> lands`, `until <id> lands`. When such an id names an issue that is neither DONE nor CANCELLED and is not in the issue's depends_on, plan validate emits a WARN finding on the issue: `current_state names <id> as a blocker and depends_on does not; add it to depends_on, or reword current_state`. The derived status treats that mention as an open dependency for readiness, so the issue is not READY, and plan next and plan start never propose it while the named blocker is open; plan show names the blocker as the reason. A mention that is not in one of the declared phrases is not read, so citing another issue in prose stays free."

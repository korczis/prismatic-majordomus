A node’s offer of a shared build cache, and the choice among offers (ADR 0157).

A capability, not a host. An Offer says that some node serves an S3-compatible store for compiler output: the protocol, the provider, how far its endpoint is meant to be reached, a non-secret endpoint, a bucket, a priority, the headroom it has and how its own probe judges it. Nothing here names a machine as special, and the type has no field a credential could live in: a client key is provisioned onto a node and read from a file outside the repository, never from an offer, the canonical state, an answer or a page.

Selection is a pure function. select ranks the offers a client may use and returns the choice and why, including every offer it passed over and the rule that passed it over. The same offers and policy give the same answer in any order, because the last tie-break is the node id. With no usable offer the answer is “none”, which is a normal answer: the build goes on with its local level alone (ADR 0157, decision 5).

It reads no network and no clock: the age of an offer and a measured round trip come in with it, so a test is a table.

§Example

use majordomus_cli::mesh::build_cache::{select, Policy};

// no node offers a cache: the answer is "none", and it says the build goes on
let answer = select(&[], &Policy::default());
assert!(answer.chosen.is_none());
assert!(answer.reason.contains("local level alone"));

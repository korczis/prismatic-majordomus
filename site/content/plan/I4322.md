description = "The shell plan model enumerates .ai/repo/project the way the executable's Index does: through `git ls-files` when the policy declares discovery vcs, and through the work tree otherwise. Today lib/project.sh:50-56 always uses `ls -1` of the work tree. After the change, `majordomus plan validate|status|list` and the plan.validate capability count the same records on every projection (CLI, MCP majordomus_plan_validate, HTTP /api/v1/plan/validate). Under vcs discovery, a file under .ai/repo that matches a class pathspec but is not tracked yields one diagnostic, untracked_record. plan validate, intent validate and doctor print it as `INFO untracked_record <path> — skipped until tracked (git add <path>)`. The untracked_record line names both remedies: `git add <path>` to make the record part of the layer, or a rerun with `--discovery filesystem` to validate drafts in place without staging them. Under that option, `intent validate` and the plan.validate capability count and check untracked records exactly as tracked ones. docs/PLANNING.md documents this draft workflow."

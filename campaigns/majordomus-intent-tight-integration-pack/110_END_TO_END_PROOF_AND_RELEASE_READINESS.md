# Milestone 11 — End-to-end proof and release readiness

Goal: prove the entire intent loop works as one system.

## Build one canonical executable scenario

Create a test fixture or dedicated integration case with:

### Outcome
A concrete desired result with at least:
- 2 invariants,
- 3 criteria,
- 2 milestones,
- multiple issues,
- one dependency,
- one criterion initially missing sufficient evidence.

### Flow

1. Create/submit desired outcome.
2. Derive draft intent/plan.
3. Validate.
4. Run opposition.
5. Opposition finds at least one issue.
6. Revise plan.
7. Accept current plan revision.
8. Start session on an issue.
9. Session automatically binds to intent and criteria.
10. Verify briefing/context contains relevant intent information.
11. Execute/record work evidence.
12. Attempt finish while one required criterion is unsatisfied.
13. Assert refusal with actionable diagnostic.
14. Complete remaining work/evidence.
15. Re-evaluate.
16. Assert criterion states satisfied.
17. Assert intent verdict satisfied.
18. Finish successfully.
19. Reconcile GitHub fixture/projection.
20. Assert CLI/API/MCP/Cockpit semantic agreement.
21. Change judged revision.
22. Assert stale evidence invalidates satisfaction as designed.
23. Add fresh evidence.
24. Assert satisfaction restored.

## Failure injection

Also prove:
- missing intent binding,
- stale opposition,
- broken criterion link,
- remote GitHub closed issue with no evidence,
- frontend cannot manufacture satisfaction,
- invalid provider planning output,
- provider unavailable fallback.

## Final acceptance

The original statement must no longer be accurate in these parts:

- "The session does not load an intent when it starts."
- "Completion policy does not yet decide satisfaction."
- "The Cockpit has no intent view."
- "GitHub milestones are not reconciled against intents."
- "Nothing derives a plan from a desired outcome."
- "Majordomus does not run the opposition pass."

If any remains true, the mission is not complete.

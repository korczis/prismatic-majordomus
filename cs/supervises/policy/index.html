Podívat se, jak odmítá a jak přijímá

Jedna politika, několik instrukčních souborů providerů, generovaných deterministicky. Dvojí spuštění zanechá bajtově shodné soubory, a právě to umožňuje razítku odhalit ruční úpravu.

Pro tento repozitář platí

# Installed, but the provider instruction files have not been generated yet.
"$MJ" init >/dev/null
mkdir -p lib && echo a > lib/a && git add . && git commit -qm base

Spustit

$ majordomus update

Výstup obsahuje

  • vytvořit CLAUDE.md
  • nese vlastní razítko

ukončení 0

Každý cíl, který politika jmenuje v projekcích, se zapíše a razítko každého se zaznamená spolu s hashem politiky, která ho vytvořila.

Pro tento repozitář platí

# A repository with Majordomus installed and projections generated, and one commit of work.
"$MJ" init >/dev/null
"$MJ" update >/dev/null
mkdir -p lib docs
echo a > lib/a
echo d > docs/d
git add . && git commit -qm base

Spustit

$ majordomus update

Deterministický výstup tu není zdvořilost. Pokud by regenerace pokaždé vyrobila jiný soubor, razítko by nikdy nerozlišilo ruční úpravu od vlastního šumu generátoru.

Co to vynucuje

  • majordomus.policy-completeness blokující vynucuje doctor, watch Každá hodnota politiky, kterou kód čte, je deklarována v kostrové politice a žádný čtenář si pro ni nenese vlastní výchozí hodnotu.
  • majordomus.policy-integrity blokující vynucuje doctor, watch Politika a každý profil se naparsují, deklarují verzi 1 a nenesou žádný klíč, který schéma nedefinuje.
  • majordomus.doctrine-wiring-integrity blokující vynucuje doctor Každá doktrína v tomto registru se převede na validátor, který existuje, je dosažen z každého příkazu, který jej jmenuje, šíří selhání, je dokázán testem a běží v CI — a každý validátor ve zdrojovém kódu je zde deklarován.
  • majordomus.lifecycle-observed blokující vynucuje doctor, watch Úložiště, které lze číst, není úložištěm, do kterého se zapisuje. Dokud se epizody dál otevírají, musí záznamy, ze kterých bude budoucí worker navazovat, dál postupovat, každá přijatá událost životního cyklu musí zanechat důkaz, že dorazila, a epizoda, která přežije práh zastarání, musí být pojmenována, ne ponechána otevřená.
  • majordomus.prompt-capture blokující vynucuje doctor, watch Repozitář, který deklaruje zachycení promptů, ho má zapojené pod modelem a prokázané během jeho běhu; archiv zůstává ignorovaný a nesledovaný, každý prompt je přítomen jako záznam i jako vykreslení a ani jedno nenese nic, co model řekl.
  • majordomus.prompt-continuity blokující vynucuje doctor, watch Každý zachycený prompt jmenuje epizodu, do níž patří, nebo říká, proč nemůže; archiv je čitelný pouze svým vlastníkem, omezený deklarovanou politikou retence a nikdy nedrží přihlašovací údaje doslovně.
  • majordomus.prompt-integrity blokující vynucuje doctor, watch Každý prompt asset lokální pro repozitář se vykreslí a každý token v něm je takový, který renderer zná.
  • majordomus.session-lifecycle blokující vynucuje doctor, watch Kde poskytovatel spouští události relace, epizodu otevírá a uzavírá hook toho poskytovatele, ne model, událost startu předá workerovi omezený briefing, který politika deklaruje, a pracovní kontext, který každé otevření zmrazí, zůstává pod ignorovanou polovinou vrstvy, nese deklarované klíče a nikdy nenese konverzaci.

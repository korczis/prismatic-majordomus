pub fn static_routes() -> Vec<(&'static str, &'static str)>
Expand description

Every route the dispatcher answers without an identifier in the path, and the area each one belongs to — "" for a page that belongs to none, which the sidebar does not carry.

Derived from the navigation (I1009): every area of nav::areas is a route under its own id, so the sidebar and this list cannot name different Cockpits, and only the pages no area names are written down, in PAGES_WITHOUT_AN_AREA. The match that answers them is not data a program can read back at run time, so what keeps the two honest is that both are compared, in each direction: every_page_renders_complete_html_with_the_shell_and_the_security_headers drives these routes over a socket, so a route the dispatcher lost is a failure; every_plain_arm_of_the_dispatcher_is_a_static_route reads the match from this file’s source, so an arm added there and not here is a failure. Integration, Reasoning and Economics were that kind: each arm and area landed after a hand-kept list of these routes was written, and nothing compared the list with the match it describes. /cockpit/quality was exactly that page: the dispatcher answered it, the navigation did not name it, and no test and no browser sweep could reach it.

let routes = majordomus_cli::cockpit::static_routes();
assert!(routes.contains(&("/cockpit/capabilities", "capabilities")));
assert!(routes.contains(&("/cockpit/monitor", "")));

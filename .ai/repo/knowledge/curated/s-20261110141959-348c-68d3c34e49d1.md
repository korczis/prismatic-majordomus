# after the shared server died and serve ensure started another, every mesh session and claim of the old server was gone; two sessions re-ran mesh session open and mesh claim by hand, and the landing seat lost its seat claim the same way (2026-11-10)

Observed as defect about command:serve.ensure in episode s-20261110141959-348c.

# Evidence

- `file:docs/MESH.md`
- `issue:I3798`

# Evidence

- On 2026-11-10 the shared server of the primary checkout was gone; `majordomus serve ensure` started a new one (port 54334) and `majordomus mesh allocate` answered "no running server" until then. Afterwards this session's mesh session and its exclusive seat claims had to be opened again by hand (`mesh session open`, `mesh claim`), and an adopting repository's session reported the same for its own restart and a server that disappeared on its own.
- I3798 ("A session's mesh claims outlive a lease takeover of the server it made them on") is the open issue that covers it by its clause that a successor server re-opens what its predecessor held; docs/MESH.md describes claims as living while their session is open and their runtime beats.

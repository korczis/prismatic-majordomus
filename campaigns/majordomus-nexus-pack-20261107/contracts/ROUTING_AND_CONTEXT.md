# Prompt classification, context assembly, and surface contract

## Route classes

| Class | Path | Side effects |
|---|---|---|
| QUERY | Targeted context, answer or existing retrieval | None by default |
| ACTION | Existing task/proceed with bounded scope and focused gates | Scoped reversible changes |
| INTENT | Resolve/attach to intent, IDD planning, criteria | Explicit governed development |
| CAMPAIGN | Multi-subsystem DAG/mesh, bounded workers | Scoped parallel development |
| CONTROL | Inspect/resume/replan/pause/cancel target | Existing authorization required |

Prefer deterministic classification with documented rules and exact intent/work candidates. Use LLM only on ambiguous cases, preserve raw input, record alternatives and confidence. Prompts generated by agents or provider system events are not equal to human authorization.

## Context precedence and cost

Read `.ai/README.md` and actual manifest; resolve scoped context using effective tree/precedence and relevant `tracks`. Select minimal sufficient chunks with citations to canonical IDs/paths/SHAs. Never ingest `.ai/local/prompts` as general context. External retrieval and peer consultations must be allowed and budgeted. Every included datum needs relevance; every excluded potentially relevant datum needs a diagnosable reason at debugging level. Cache by policy version, HEAD, scope and source revisions, not arbitrary time alone.

## Presentation semantics

All CLI/JSON/HTTP/MCP/Cockpit/docs/site consumers use a typed canonical projection. No frontend-defined canonical sorting, no independently maintained command/route/catalog arrays. A new discoverable canonical capability propagates to the relevant surfaces through generation with cross-surface contract tests. Explicit user filtering and sorting remain allowed but do not redefine defaults.

## UX workflow

`new intent` → persistent draft → keystroke/submit debounce → context/related work/risks → questions only for materially ambiguous options → plan and prompt pack preview with source/evidence links → materialization through existing project graph → execution with real events → verification and delivery → replan/resume. Avoid LLM request on each keystroke; store draft deltas and run expensive reconciliation on meaningful edit or explicit user action. Show `draft`, `inferred`, `verified`, `blocked`, `delivered` states clearly.

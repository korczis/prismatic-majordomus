title = "I2901 — One grammar names a record id, and every surface reads it: a capital letter and three or more digits that name a record file of the tree read"
description = "Declare the record id grammar once. The issue schema's id pattern is `^[A-Z][0-9]{3,}$` (a capital letter followed by three or more digits), which this repository's I and four digits and an adopter's V603, R022 or M048 all satisfy, and plan validate refuses an issue whose id does not match it. One predicate, plan::is_record_id(word, tree), decides whether a word names a record: the word has that shape, and `<word>.yaml` exists under .ai/repo/project/issues/ or .ai/repo/project/milestones/ of the tree read, which also says whether it is an issue or a milestone. Shape alone is never enough, so H264, v3.13.0 or V999 with no V999.yaml name nothing. Slug milestones (this repository's `work-graph-github` and the like) never have that shape, so they are never a candidate on any surface, as today. Every surface that tests a word against a shape today calls the predicate instead and none spells the grammar its own way: ui/prs.rs is_issue_id and issues_named (and so plan/delivery.rs named_by, which wraps it), release/commits.rs record_candidates and its issue-or-milestone test (:149), capability/builtin/brief.rs:1003 task_label, the JS pattern `/(?<![\\\\/\\\\w-])I\\\\d{4}\\\\b/` in test/cases/3220_the_idd_loop_is_walked_in_a_browser.sh:154, the awk pattern `I[0-9][0-9][0-9][0-9]+` in scripts/ci/audit-plan-check:56, and scripts/github-sync at :394 (`^I[0-9][0-9][0-9][0-9]+$`), :399 (`^I[0-9]+\\\\.yaml$`) and :1126 (the sed title claim `^\\\\([MI][0-9][0-9]*\\\\) — `). The shell and JS callers, and plan validate's refusal, take the answer from one typed subcommand of the executable (for example `majordomus plan ids --json`, the declared ids of the tree with their kind and whether each has the shape), never from a second pattern. The same subcommand answers which ids a text names: `majordomus plan ids --named-by --title <t> --branch <b> --json` returns the ids the title and the branch name, by the same predicate and the same scan as issues_named, so shell and JS callers, and the forge adapter of I4370, never spell a pattern. Which text a surface scans does not change: delivery and the PR Drain read a title, a subject and a branch; the changelog's references() keeps scanning a commit's subject and body together (release/commits.rs:79, documented at :130-133), because a commit that explains itself in its body is the one worth linking."

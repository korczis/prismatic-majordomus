description = "The mesh review events carry the revision they are about, and every reader of a review compares it with the subject now. ReviewRequested (apps/majordomus-cli/src/mesh/journal.rs:638-659) gains optional head and base: when its subject names a branch or a commit the requesting runtime's checkout can resolve, the runtime records the subject's head commit and its merge base with the trunk (the trunk crate::delivery::revision::trunk_ref resolves, apps/majordomus-cli/src/delivery/revision.rs:96), from git, never from the requester's text. ReviewAnswered (journal.rs:661-671) gains the same two optional fields, filled by the answering runtime the same way, and, when it cannot resolve the subject, copied from the request and marked `as_requested`. The mesh.review.answer capability (apps/majordomus-cli/src/capability/builtin/mesh.rs:1579-1606) takes an optional head that the answerer may state and refuses one that differs from what its own git resolves, naming both. A reader (mesh state, the mesh page, the monitor's review lines) gives each answered review one standing: `current` when the subject's head and base are the recorded ones, `stale: head moved <old>..<new>` or `stale: base moved <old>..<new>` when either differs, `unbound` for an answer written before this change, and `unknown: <reason>` when the reading runtime cannot resolve the subject; unbound and unknown never read as current. Both fields are listed in .ai/repo/ci/mesh-event-fields.yaml as clear (commit ids are not secrets), so the mesh check admits them."

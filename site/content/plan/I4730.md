description = "A capability gates.baseline (MCP majordomus_gate_baseline, POST /api/v1/gates/baseline, `majordomus-cli run gates.baseline`) that judges the runs of one check over a change against its runs over the commit the change is built on, and optionally over a neutral perturbation of that commit as a control. The caller runs the check; the capability runs nothing. The input declares the runs per side (`runs`), the rule (`subset`, the default, or `{rate: {slack: k}}` with at least three runs), each side's commit, its runs (exit, or null for a run that did not finish; the tree; the findings, each an id with an optional path and line) and why a side could not be run at all; optionally the change set and the command. Per failure id, with c, b and k the change, base and control runs that show it: introduced (c>0, b=0), pre_existing (c>0, b>0), fixed (c=0, b>0), unknown (the base side is unavailable, of another size than declared, or spans two trees; or the id is synthetic on both sides: a failed run that named nothing shows exit:<code>, one that did not finish also shows not-finished). Flaky (0<n<runs on a side) is a property and never a class. Under subset only introduced blocks; under rate an introduced or pre-existing id blocks when c exceeds max(b, k) by more than the slack, and an introduced finding in the change's own files always blocks. The verdict is clean, clean_with_trunk_failures (the base shows failures; trunk_alarm lists them as `<id> (<b>/<N>)` with the base commit), introduced, or undecided with its reasons. Every report carries its denominator (runs declared and seen per side, ids examined, the rule, and that no multiple-comparison correction is made) and the provenance the caller named. A finding with a path carries in_diff, over the caller's change set or, without one, over gates::changed_paths from the base commit; an introduced finding outside the diff is listed in introduced_outside_diff."

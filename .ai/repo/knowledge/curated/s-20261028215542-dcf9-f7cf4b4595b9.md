# an HTTP 429 whose body says the account's quota or credit is exhausted (insufficient_quota, credit_balance_exhausted) is typed rate_limited, which recovers after its retry-after, and a CLI client that exits with IneligibleTierError is typed error, so the plan keeps selecting advisors that cannot answer (gemini selected three runs in a row on assessment-20261028T185442897Z-849b27)

- `file:scripts/lib/advisors/process.mjs`

# Evidence

Measured on the advisor contract suite (node --test scripts/lib/advisors/contract.test.mjs):

- Against the adapters at 81ef931a3e1 the new assertions fail: tests 5 (HTTP failures are classified), 14 (api adapter 429 typing) and 18 (cli adapters) are not ok, because httpFailure(429, ..., {error:{type:'insufficient_quota'}}) returned rate_limited and an exit with "IneligibleTierError: This client is no longer supported ..." returned error.
- With the change all 21 tests pass.

apps/majordomus-cli/src/reasoning/availability.rs (apply_circuit) shows why the typing mattered: rate_limited recovers after its retry-after (else 900 s), error is transient and opens only after two in a row for 600 s, while auth_failed opens on the first for 3600 s. The adapters now type as auth_failed an exhausted quota or credit, whether the HTTP error body says so by type or code (insufficient_quota, credit_balance_exhausted, billing_hard_limit_reached, billing_not_active) or by message ("credit balance is too low", the wording of a spent Anthropic balance, which arrives as a 400 invalid_request_error), or a client's stderr says so; and a tier that no longer admits the client: scripts/lib/advisors/contract.mjs (quotaExhausted, httpFailure), scripts/lib/advisors/http.mjs (reads the error body), scripts/lib/advisors/process.mjs (EXHAUSTED, INELIGIBLE before RATE).

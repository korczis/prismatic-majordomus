description = "`majordomus handover` takes a repeatable `--delegated <ref>`, and the record keeps what the writer handed to others beside its own task. A ref is one of: a task id (t-...), a branch, a mesh review (<stream>/<review>), or anything else, kept verbatim. The writer names the ref; the tool, never the writer, resolves where it stands from its authority at write time: a task from the task record of whichever worktree of the repository holds it (its outcome and worktree) or from the ledger's task.finished; a branch from git (its head and whether the trunk contains it); a review from the executable's mesh state when the mesh is enabled (open, answered with its verdict, withdrawn). What cannot be resolved is recorded as `unknown: <reason>`, never as done. The front matter (lib/handover.sh:74, mj_record_front_matter) carries a `delegated:` list, one `<kind> <ref> <standing>` per item; `handover --derive` adds a `# Delegated` section listing them. `handover --resolve` and the session briefing print each item with its standing then and its standing now, resolved again the same way, so a resumed coordinator sees which delegated work finished, which is still open and where, and which it can no longer find."

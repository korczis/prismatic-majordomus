Problem

The owner's integration mission of 2026-10-30 asks that a person states a bounded task and the existing Majordomus carries it through one cycle: intent, verifiable criteria and authority, relevant context and existing work, a bounded task and its coordination, implementation, independent verification by risk, integration and deployment where the task's contract requires them, acceptance on current evidence, and a handover with a usable lesson, inside the overhead budgets of its section 10. Two real passes walked that cycle on 2026-10-30. Session 98 ran a stranger fixture (a three-file Python repository, an off-by-one in calc.mean and its regression test) through the installed 1.0.0-alpha.8: a failing test, an out-of-scope change and uncommitted work were refused correctly and a handover resolved for a new session key, but evidence over an empty input set never went stale, completed was accepted over uncommitted work, task.finished named the pre-fix head and doctor took 58.7 s against a 20 s budget. Session f3 ran the in-repo pass on master 51b38035a71 by taking I4292: plan next took 118 s and proposed I0703, which its own record says is blocked; plan start took 346 s, opened no task and named a Rust issue next on a machine below the build floor; start --issue carried none of the issue's evidence; check took 93 s and read 50 never-reported gates as INFO. OSCILLA's adopter dossier (oscilla-b0) and the P00 audit added the review relay, delegated work, the doctrine principle and knowledge edges. Each break, and each step the passes showed working, is one row of the map below; the rows are this milestone's acceptance criteria, each naming the user step, its state, the gap, the existing owner and the proof that will show it closed.

Outcome

Every row reads wired with its proof run: each break is closed in the owner it names by the smallest change that unblocks its user step, with a case that fails before the change, and the stranger fixture and the in-repo pass, run again, reach acceptance with no hand-written state and no step outside its budget.

Out of scope

  • A new orchestrator, graph, database, registry, command family or dashboard (mission section 1)
  • The external fixture harness, owned by the peers that run it (mission section 11)
  • Findings the passes made that break no step of the cycle and have no owner (F5 false WARN on sessions/README.md, F9 integration silently not_applicable with no CI model, F10 start --help on evidence): triaged apart, not bundled (mission section 3)

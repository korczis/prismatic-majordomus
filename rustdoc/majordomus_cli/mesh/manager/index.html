majordomus_cli::mesh

Module manager 

Source
Expand description

The discovery manager: provider lifecycle, the one verification path, and the one registry. Providers hand raw bytes here; this thread parses, checks bounds and staleness, verifies the signature, evaluates trust, and only then touches the registry — in that order, for every transport alike. A provider cannot skip a step because no provider ever parses.

The runtime lives on the capability Context from process start, inactive, and a shared server activates it when the repository’s mesh declaration says so. Activation is idempotent, bounded, and never blocks startup: sockets open on their own threads, and a provider that cannot start is a Failed status, not a failed server.

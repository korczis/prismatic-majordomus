HTTP API: blackboard

Who works on what in this repository, as one projection of the records that already know it: every checkout's board, the mesh journal's sessions, claims, reviews and handovers on every linked machine, and the monitor's newest signals, joined once so that no surface joins them again (ADR 0176). A board peer and a mesh session are one worker only when an explicit identifier joins them; a source that could not be read makes the answer incomplete and says why.

Who works on what in this repository, as one projection of the records that already know it: every checkout's board, the mesh journal's sessions, claims, reviews and handovers on every linked machine, and the monitor's newest signals, joined once so that no surface joins them again (ADR 0176). A board peer and a mesh session are one worker only when an explicit identifier joins them; a source that could not be read makes the answer incomplete and says why.

GET /api/v1/blackboard blackboard.snapshot

Who works on what, now

Every worker of this repository — attached to a checkout's board or in an active mesh session on any linked machine — with the client it is, what it announced, its checkout, branch, machine and claims (advisory or exclusive); the claims that meet (potential, or confirmed when both are exclusive or the mesh marked one conflicted); the open reviews and untaken handovers; typed relations between workers, verified only when an explicit identifier joins them; the newest signals with the monitor's cursor a follower resumes from; each source with how it was read, and whether the answer is complete. Reads only.

  • query
  • experimental
  • benchmark required
  • cache disabled
  • MCP tool majordomus_blackboard
  • $ blackboard

Query parameters

nametyperequireddescriptionexamples
checkouts Checkouts no Which checkouts' boards it covers: `repository` (every one, the default) or `this`. addressed: "this"this-checkout: "this"
for string no Comma-separated names of the reader — a worker (`1b`), a role, a login — so that the signals addressed to it are marked `for_you`. An MCP caller is also its own board session. addressed: "1b"
signals integer (uint64) no How many of the newest signals of the last hour it carries (default 30, at most 200); 0 reads no signals at all, for a follower that reads them by its own cursor. addressed: 10
sources string no A comma-separated subset of the monitor's sources, `mesh`, `executor` and `github` (default: `mesh,executor`). addressed: "mesh"this-checkout: "mesh,executor"

Try it

The port is whatever the server logged; 8741 is the one it asks for first. The values are the operation's first example.

curl -s "http://127.0.0.1:8741/api/v1/blackboard?checkouts=this&for=1b&signals=10&sources=mesh"

Tested by apps/majordomus-cli/tests/http_serve.rs, which replays the route with these values against a server on a real socket.

BlackboardCertainty

"potential" | "confirmed"
How sure a conflict is.
  • potentialTwo claims meet and at least one of them is advisory: two workers about to touch the same paths, told and not stopped.
  • confirmedTwo exclusive claims meet, or the mesh marked one conflicted: what an exclusive claim exists to prevent has happened.

BlackboardOrigin

"board" | "mesh"
Where a worker of the blackboard was found.

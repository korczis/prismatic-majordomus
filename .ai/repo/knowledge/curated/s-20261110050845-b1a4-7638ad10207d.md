# majordomus worktree create <branch> run through a primary checkout whose executable was stale printed only the stale-executable warnings and created no worktree, and the caller, which did not check the exit status, went on as if it had; the worktree was then made by hand with git worktree add at the canonical <repo>-wt/<branch> path

Observed as friction about command:worktree.create in episode s-20261110050845-b1a4.

# Evidence

- `file:docs/WORKTREES.md`

# Evidence

- The output is the launcher's refusal, not a warning: `lib/rust_bin.sh` (lines 263-281 on origin/master dd377e11c35), for a stale executable whose installed release is not of the tree's generation, writes to stderr "<exe> is stale (older than its sources), and no ordinary command builds it (ADR 0224)", the release's reason, and "run: just build ... or set MAJORDOMUS_BIN", then returns 12; the executable never runs, so `worktree create` makes nothing. `bin/majordomus-cli` lines 5 and 31 name the same exit 12.
- The caller of 2026-11-10 did not check the exit status, read the lines as warnings, and made the worktree with `git worktree add` at the canonical `<repo>-wt/<branch>` path (docs/WORKTREES.md); it found it missing only afterwards.
- The lesson: a launcher's exit 12 is a refusal; read the status, and on a checkout that cannot build name an executable of the tree's generation with MAJORDOMUS_BIN (and MAJORDOMUS_BIN_COMMIT), as the message says.

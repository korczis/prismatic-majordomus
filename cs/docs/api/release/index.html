GET /api/v1/release/analysis release.analysis

Co udělal veřejný kontrakt a nejmenší verze, kterou dovoluje

Veřejný povrch schopností tohoto stromu proti tomu, který publikoval poslední release, každý jeho pohyb pojmenovaný s důvodem, proč se počítá tak, jak se počítá, a nejmenší verze, kterou tento strom smí proto deklarovat. Úroveň kompatibility se měří z kontraktu, ne čte z předmětů commitů: schopnost, trasa, nástroj MCP, příkaz nebo povinné pole kteréhokoli ze dvou schémat, které volající mohl držet a už nemůže, je zásadní změna, ať se commit, který je odstranil, nazval jakkoli. Co o sobě commity řekly, se nese vedle verdiktu jako důkaz a odpověď říká, kdy se obojí rozchází.

GET /api/v1/release/currency release.currency

Whether the trunk's landed work is released

How much landed work the trunk holds past the last release, since when, and at which version, measured when asked (I3070). The last release is the newer of the release the layer records and the newest version tag the trunk contains: a tag is pushed before its record lands. Landed work is every commit of the trunk past it except merges and release commits. A landing is a commit of the trunk's first-parent history, and the work has waited since the oldest landing that brought anything but release commits. The stance is current when nothing has landed past the release, owed when work has, and overdue once it has waited longer than six hours. The version the public contract requires is decided by the version selection release.version makes, but only from a recorded release and only in a checkout at the trunk; otherwise the answer says which it is not. Ask with next false to leave the version out, as the brief and doctor do. It reads git and the clock, so it is never committed into derived data.

Verze, kterou landing přidělí, a proč

Na co exekutor integrace zvedá verzi trunku, když přistává head (ADR 0134): verze, kterou trunk deklaruje, jak daleko head posouvá veřejný kontrakt změřený proti commitnutému registru trunku, co ten posun vyžaduje podle režimu verze, spodní mez repozitáře z `release.floor` v politice, třída výjimky, která mez snížila, pokud každá změněná cesta spadá do jedné, větší z požadavku a meze, a verze trunku jím zvýšená — s jednou větou na krok. Vše se čte z gitu na dvou refech, takže odpověď nezávisí na tom, který spustitelný soubor běží, ani na vlastní verzi větve, a proto opakované přistání nemůže zvýšit dvakrát. Rozhoduje a nic nezapisuje; vstup, který nelze přečíst, se odmítne, nehádá se.

GET /api/v1/release/version release.version

Verze a ta, kterou kontrakt požaduje příště

Verze, kterou deklaruje manifest crate — jediné místo, kde se píše — verze, kterou shellový nástroj vypisuje ze své projekce `share/version.txt`, a zda je tato projekce aktuální — otázka, kterou odmítá `generate --check` a na které staví kontrola `scripts/release-version --check`. Pak další verze, což je odpověď veřejné smlouvy: verze, kterou `release analyze` vyžaduje oproti poslednímu releasu — deklarovaná verze, pokud už smlouvu splňuje, jinak nejmenší, kterou smlouva dovoluje, a nejmenší release nad posledním, když smlouva žádný nad ním nevyžaduje — přičemž `decided_by` jmenuje, kdo odpověděl. Je to tentýž výběr releasu, na který `release bump` zvyšuje, když není jmenován cíl, takže zpráva a zapisovatel se nemohou rozejít. Když smlouvu nelze změřit — chybí publikovaná základna, verze nejsou tři čísla, nebo jiná chyba činí plán nesolidním, plán, ze kterého `release bump` odmítá zapisovat — základna je odmítnuta, ne hádána: `next` chybí, `decided_by` je `undecided` a `contract_unreadable` nese každou chybu, jednu na řádek. Zvýšení, které implikují konvenční commity od posledního releasu, verze, kterou by vytvořilo, a samotné commity se nesou vedle jako důkaz a nikdy neodpovídají za `next` místo smlouvy.

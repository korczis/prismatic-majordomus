the challenge

Try to get unfinished work accepted.

A coding agent claims a directory, edits a file outside it, says it is done, hands over, and comes back. Majordomus refuses twice, names the reason each time, and accepts the work only when the repository's own test passes. Every line below is a recorded run of the real tool, executed when this page was generated.

Coding agents are good at doing the work and bad at knowing when it is finished. They touch files nobody asked for, report success over a failing test, and forget the task when the session ends. A better prompt does not fix that, because the prompt is the part being ignored. What fixes it is a check the worker cannot talk its way past.

Run it yourself

The scenario is a file in the repository. Install the tool, clone the repository, and run the use case: it builds a disposable repository, replays every step against your build, and fails if any recorded exit code or pattern no longer holds.

Guarantees this run exercises

  • scoped-task

    A task is started with a declared file scope and a profile, and only one task is active per checkout

    lib/start.sh · test/cases/04_start_check.sh

  • overlap-report

    Overlap between parallel workers is computed on claimed paths in both containment directions

    lib/check.sh · test/cases/04_start_check.sh

  • scope-enforcement

    A touched file outside the claimed scope is a failure, not a warning

    lib/check.sh · test/cases/04_start_check.sh

  • finish-contract

    finish evaluates the finish contract line by line and refuses when any line is unmet

    lib/finish.sh · test/cases/06_finish.sh

  • handover-record

    handover writes an append-only record with computed front matter and required sections

    lib/handover.sh · test/cases/05_handover.sh

  • typed-outcome

    An outcome is a value from a closed vocabulary, not free text

    lib/finish.sh · test/cases/06_finish.sh

# run-plan --before-push in full mode passed a top that changed release.yml, and CI's structure job then refused it in shell-lint for actionlint's SC2155 on an export assigned from a command substitution in a run block (run 44090334938): shell-lint is one gate whose recorded 1437 s is far over the 15 s a push spends on one gate, so the budget left all of it to CI, actionlint's one-second step included; the before-push step now runs actionlint (workflow-lint) when a changed path is under .github/workflows/, and case 1021 drives it with a stub and with the real actionlint

- `file:.ai/repo/ci/structure-durations.tsv`

# Evidence

- Validate run 44090334938 on integration/top-20261117e (a40af76e194) failed its structure job in shell-lint: `.github/workflows/release.yml:277:9: shellcheck reported issue in this script: SC2155:warning:1:8: Declare and assign separately to avoid masking return values [shellcheck]`, `==> shell-lint: FAILED (229s)`. The before-push step on that top had passed in full mode.
- `scripts/ci/run-plan` at ae13be1bd13 chooses structure gates whose recorded seconds are at most 15 (`MJ_PUSH_GATE_SECONDS`); `.ai/repo/ci/structure-durations.tsv` records `shell-lint 1437`, so shell-lint, and with it its actionlint step (`scripts/ci/shell-lint`, `actionlint .github/workflows/*.yml`), is always left to CI.
- This change: `scripts/ci/run-plan --before-push` runs `actionlint .github/workflows/*.yml` as workflow-lint when a path of the plan's `changed` list is under `.github/workflows/` and shell-lint was not chosen; a host without actionlint says so. `bash test/run.sh 1021_a_push_runs_what_ci_would_find_first` passes; with the condition replaced by `false` it fails with `expected exit 1, got 0 from: wf/scripts/ci/run-plan --before-push`. The case drives a stub actionlint first on PATH (CI's suite job has none) and, where the host has it, the real actionlint over the same SC2155 line.

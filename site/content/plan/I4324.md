title = "I4324 — A finished worktree's build output is reclaimed, node_modules and target/ included, whether its branch landed by merge or by squash"
description = "Three changes to `majordomus worktree cleanup`, and one reading of doctor. First, a worktree whose branch has landed by the predicate of I4333 is cleanup-eligible, so a branch squash-merged under `landing: squash` is offered, as one merged by merge commit is today. Second, a finished worktree that cleanup keeps (its branch landed, or it is idle past the sweep window, but its status is not empty) is offered for build-output reclaim: `majordomus worktree cleanup --build-output` lists, and with `--remove` deletes, its node_modules/ and target/ directories (any depth). A directory is reclaimed only when `git check-ignore` reports it ignored and git tracks no file under it. Reclaim runs under the guards I3832 already gives the removal: no process cwd, open file or command line inside, not named by the derive lock or a live mesh claim, idle past MAJORDOMUS_WORKTREE_SWEEP_IDLE_MIN, and under every cargo lock in a target/. The listing gives each directory's size, and the answer gives the total reclaimed. The worktree, its branch and every tracked or unignored file stay. Third, the removal refusal of `worktree cleanup --remove` (apps/majordomus-cli/src/commands/worktree.rs:751-780) stops refusing a gone upstream on its own: a clean worktree whose upstream is gone and whose HEAD is an ancestor of the trunk's remote-tracking branch (git merge-base --is-ancestor, read at the moment of removal like every other reading there) is removed, because every commit it holds is on the remote through the trunk. A worktree whose HEAD carries a commit that remote trunk lacks is still refused, naming the count, whether its upstream is gone or it never had one, and so are uncommitted work, a process inside, and an ancestry git cannot decide. Fourth, doctor reads the same listing, read-only: when the build output reclaimable by `worktree cleanup --build-output`, plus the worktrees `worktree cleanup` lists as eligible, exceed a floor stated beside the check (overridable through an environment variable), it prints one `WARN disk — <n> finished worktrees hold <size> of reclaimable build output` whose remedy is `majordomus worktree cleanup --build-output` (then `--remove`). Doctor never deletes. Under the pre-commit context (MAJORDOMUS_DOCTOR_CONTEXT=commit) the reading is left out, as the per-worktree uncommitted-work reading already is, so the hook stays within its latency budget."

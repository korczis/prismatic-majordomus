# pull-request validates that yielded to the release path are resumed only by release-path.yml's 15-minute schedule and by the last job of a validate run that is not a pull request's; GitHub ran that schedule 7 h apart (19:13Z and 02:16Z on 2026-11-09), and a pages deploy or a record verdict ending resumed nothing, so the yielded runs stayed cancelled until a tick came

Observed as defect about .github/workflows/release-path.yml in episode s-20261110050845-b1a4.

# Evidence

- `file:.github/workflows/release-path.yml`
- `file:.github/workflows/validate.yml`
- `issue:I4569`

# Evidence

- `.github/workflows/release-path.yml` runs resume on its schedule (`cron: '7,22,37,52 * * * *'`, line 19) and on workflow_dispatch; `validate.yml` asks it at the end of a run that is not a pull request's. `gh run list --workflow release-path.yml --event schedule` on 2026-11-10 lists consecutive scheduled runs at 2026-11-09T19:13:09Z and 2026-11-10T02:16:07Z: GitHub skipped every tick between, 7 hours.
- Nothing else resumes: a pages deploy or a record pull request's verdict ending does not ask release-path (docs/CI.md, the release-path paragraph: "It is asked at the end of every validate run that is not a pull request's").
- Filed as I4569 by the same run ("Pull-request runs that yielded to the release path run again when the release path's last run ends, not on the next scheduled tick"), which carries the change.

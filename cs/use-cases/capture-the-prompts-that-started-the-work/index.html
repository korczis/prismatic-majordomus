Uchovat prompty, které práci zahájily, pod modelem, ne kolem něj

Zapojte hook providera, dokažte jej protažením payloadu a ověřte, že prompt, který nástroj nedokázal parsovat, se ohlásí, a ne tiše zahodí.

○zaručeno Relace a předávkazákladnímaintaineragentzapisuje stav

Situace

Prompt, který práci zahájil, je jediná věc, kterou nikdo neuchovává. Žije v přepisu poskytovatele, který další relace nepřečte, takže za šest týdnů repozitář drží změnu a žádný záznam o tom, co bylo požadováno.

Scénář

setup: capture-installed
given:
  - 'Majordomus installed, with the provider hook written and the executable on PATH'
steps:
  - id: is-it-real
    run: ['capture', 'status']
    note: 'the state is read from the provider configuration and a payload driven through the shim, not from a flag somebody set'
    expect:
      exit: 0
      stdout_contains: ['claude-code', 'majordomus-capture']
  - id: one-prompt-one-record
    run: ['capture', 'prompt', '--provider', 'claude-code']
    stdin: claude-code-prompt.json
    note: 'what the provider sends on UserPromptSubmit; the record is the person half of the exchange'
    expect:
      exit: 0
      files_exist: ['.ai/local/prompts']
  - id: both-formats-or-neither
    run: ['capture', 'render']
    note: 'a prompt is kept twice under one stem: the record for a machine, the rendering for a person. render rebuilds a missing rendering from its record and never the other way round, because only that direction is possible'
    expect:
      exit: 0
      stdout_contains: ['rendering']
  - id: never-rejects-a-prompt
    run: ['capture', 'prompt', '--provider', 'claude-code']
    stdin: not-a-payload.txt
    note: 'in a hook, exit 2 rejects the person prompt, so a payload the tool cannot read is written to the failure log and the turn goes on'
    expect:
      exit: 0
      files_exist: ['.ai/local/prompts/.capture.log']
  - id: a-subcommand-that-is-not-one
    run: ['capture', 'nonsense']
    note: 'the command line still refuses what a person typed wrong: only the hook path is forbidden to exit 2'
    expect:
      exit: 2
      stdout_contains: ['unknown subcommand']
then:
  - 'the archive is written under the ignored half of the layer and never committed'
  - 'every prompt is present as both a JSON record and its Markdown rendering'
  - 'a prompt the tool could not read is a named failure, not a silence'

Výsledek

Prompty se zachytávají pod modelem hookem providera do souborů, které repozitář ignoruje a nic je nenačítá do kontextu. Zda je zapojení skutečné, se zjišťuje průchodem payloadu, ne tvrzením, a payload, který nejde přečíst, je nahlášen, a ne zahozen.

Každý prompt se uchovává dvakrát pod jedním kmenem, protože oba čtenáři jsou různí. Záznam .json je to, co provider poslal — jeho vlastní spany, stále escapované, hezky vypsané jeden člen na řádek — a z něj se odvozuje všechno ostatní. .md vedle něj je ten záznam vykreslený pro člověka: pole jako front matter a znovu jako tabulka, pak samotný prompt pod ## PROMPT, dekódovaný a ohraničený. Archiv, který nikdo neotevře, je důkazem ničeho, a vykreslení, z něhož nelze nic znovu sestavit, není důkazem vůbec, takže dvojice se vynucuje, a nenechává zvyku. Asymetrie činí toto bezpečným: capture render znovu sestaví jakékoli vykreslení z jeho záznamu a žádný příkaz nemůže jít opačným směrem.

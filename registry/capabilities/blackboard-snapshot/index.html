blackboard.snapshot

Every worker of this repository — attached to a checkout's board or in an active mesh session on any linked machine — with the client it is, what it announced, its checkout, branch, machine and claims (advisory or exclusive); the claims that meet (potential, or confirmed when both are exclusive or the mesh marked one conflicted); the open reviews and untaken handovers; typed relations between workers, verified only when an explicit identifier joins them; the newest signals with the monitor's cursor a follower resumes from; each source with how it was read, and whether the answer is complete. Reads only.

input · BlackboardInput

The input of blackboard.snapshot: how wide the board is, who reads it, and how much of what happened it carries.
propertytyperequireddescription
checkouts reference no Which checkouts' boards it covers: repository (every one, the default) or this. default "repository"
for string | null no Comma-separated names of the reader — a worker (1b), a role, a login — so that the signals addressed to it are marked for_you. An MCP caller is also its own board session.
signals integer | null no How many of the newest signals of the last hour it carries (default 30, at most 200); 0 reads no signals at all, for a follower that reads them by its own cursor.
sources string | null no A comma-separated subset of the monitor's sources, mesh, executor and github (default: mesh,executor).

output · Blackboard

The answer of blackboard.snapshot: who works on what in this repository, on every board and every linked machine, with what meets and what waits, read once from the records that know it.
propertytyperequireddescription
at string yes When it was read (RFC 3339).
boards array yes Each checkout's board the summary lists: reached or not, with a server or a worker.
checkout string yes The identity of the checkout whose server answered.
complete boolean yes Whether every board was read and the mesh, when the repository declares one, could be asked. false names its reason in sources, so that "nobody is here" is never what "I could not ask" reads as. The monitor's sources are reported in sources with their state and do not decide it: an empty executor trail or an absent gh is no board that could not be read.
conflicts array yes The claims that meet, at most a hundred, confirmed first.
conflicts_total integer yes How many conflicts there are in all.
covered integer yes How many checkouts the answer covers, listed in boards or counted in omitted.
cursor string yes The monitor's cursor after these signals: where a follower resumes.
for_you integer yes How many of them are for the reader.
handovers array yes The handovers nobody has taken, at most fifty.
head string | null no That checkout's HEAD, when it has one.
omitted object no The covered checkouts boards does not list, counted by standing (absent, stale): no server, nobody attached, no board.
present integer yes How many workers are here now: attached to a board or in an active mesh session.
relations array yes The typed relations between workers.
reviews array yes The review requests nobody has answered, at most fifty.
signals array yes The newest signals of the last hour, oldest first.
sources array yes Each source and how it was read.
workers array yes Every worker, this checkout's board first, then the other boards, then the mesh.

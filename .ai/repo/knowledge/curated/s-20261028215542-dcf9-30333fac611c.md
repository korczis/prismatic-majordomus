# On 2026-10-28 ~22:30Z the shared Mac reached load 92 and the shared MCP server stopped answering (brief: Resource temporarily unavailable, os error 35) because one session's workflow agents asked whether any branch carried a path or an id with unbounded history scans: git grep -l over refs/remotes/origin/* (~1200 branches, 276% CPU, 5 min), git log --all -SI4338 (7.5 min) and git log --all -S<text>; stopping the three pids took load to 68 and the server answered in 2.4 s. scripts/collision-check answers the path question from branch tips in one cat-file pass, and a tip check plus a date-bounded --grep answers the id question in about 3 s.

# Evidence

The incident (operator observation of 2026-10-28 ~22:30Z, shared Mac 641b):
- load average 92; the shared MCP server http://0.0.0.0:62328 did not answer
  (`brief` failed: "Resource temporarily unavailable (os error 35)").
- The three heaviest processes were one session's workflow agents, all read-only
  history or content scans across every ref:
  `git grep -l -i -E ... refs/remotes/origin/*` over ~1200 remote branches (276% CPU, 5 min),
  `git log --all --oneline -SI4338` (7.5 min) and `git log --all ... -S<text>`.
- Stopping those three pids took load from 92 to 68 and the server answered again
  (HTTP 200 in 2.4 s).

The bounded forms, measured in this worktree on 2026-10-29 at load ~34
(`git for-each-ref refs/heads refs/remotes/origin refs/rescue | wc -l` = 2118):
- tip check for a file, `git for-each-ref --format='%(refname):.ai/repo/project/issues/I<id>.yaml %(refname)' ... | git cat-file --batch-check='%(objectname) %(rest)'`:
  real 4.28 s (I4350, cold), 2.05 s (I4006), 2.06 s (I9999, none); finds I4350 on
  refs/heads/chore/evolve-20261028 and its origin copy only.
- `git log --oneline --since=14.days -i --grep 'I4296' --branches --remotes=origin`: real 0.87 s,
  finds 77155f4137c, the colliding commit of 2026-10-28; the 30-day form finds both
  I4251 commits a3ed641d92b and fe771e59115 of 2026-10-27.
- `scripts/collision-check` reads branch tips through one `git cat-file --batch-check`
  pass (scripts/collision-check:197) and merge bases only for refs that carry the path; it never walks
  history content.

Round 1 of this evolve (fbd9243c449) itself told readers of .ai/repo/project/issues/README.md
to run `git log --all --oneline -i --grep` and `git log --all -- <file>`; that block is now the
bounded pair above, and the implement skill's step 3 says how history and other branches are
asked.

Nothing refuses such a scan yet; the two documents above are all that decides it. The
enforcement this names as its follow-up is the heavy-work slot of issue I4006 (pull request
#2397, `machine.slot`): an unbounded content search across every ref is heavy work like a
build and belongs under that slot or behind a command guard that refuses `git log --all -S`,
`-G` and `git grep` over every remote branch outside it. It is named here, not built.

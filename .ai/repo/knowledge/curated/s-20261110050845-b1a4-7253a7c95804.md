# Evidence

- Done on 2026-11-10 in the evolve run itself: the installed release 1.0.1 (RELEASE.json: tag v1.0.1, commit 426e98551fffde8613b77faedcd05de14f191317, target aarch64-apple-darwin) ships its executable as `libexec/majordomus-cli` (a Mach-O binary; `bin/majordomus` and `bin/majordomus-cli` beside it are bash launchers). With MAJORDOMUS_BIN naming the libexec executable and MAJORDOMUS_BIN_COMMIT that commit, `--version` answers 1.0.1 and `knowledge candidates` answered in 0.8 s in a worktree at origin/master dd377e11c35; no build ran.
- `lib/rust_bin.sh` refuses a launcher as MAJORDOMUS_BIN ("MAJORDOMUS_BIN names <path>, a Majordomus launcher, not the executable: it would run itself without end", line 254) and trusts an explicit MAJORDOMUS_BIN about freshness (lines 105-127). A first try with a guessed `.../apps/majordomus-cli/target/debug/majordomus` path did not exist.
- The executable alone answers `knowledge observe` with "unrecognized subcommand 'observe'": observe, promote, reject and `session` are shell commands, so they run through the launcher (the installer's launcher on PATH) with the same two variables set; that is how every write of this run was made.
- The evolve skill (version 4) does not say this; step 1 says the primary checkout can stand behind the trunk and names no executable to use instead.

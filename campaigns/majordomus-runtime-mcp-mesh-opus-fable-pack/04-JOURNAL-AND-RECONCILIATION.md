# M04: Durable, deterministic cooperation and anti-entropy

Audit `mesh/journal.rs`, `state.rs`, `cooperation.rs` and existing signed event grammar: sessions, claims, handovers, reviews, beats. Preserve single journal semantics, identity `(stream, seq)`, signatures, Lamport ordering, monotonic liveness, deterministic folds and restart rules. Extend existing event schema only for genuine needs; version and migrate. Make reconciliation idempotent across retry, duplicate, out-of-order, gap, restart, conflicting journals and offline rejoin. Ensure canonical hashes, explicit bounds, compaction/snapshot evidence with validation and replayability; never evict unresolved events without a recovery guarantee. Avoid wall-clock-based authority or session resurrection from disk.

Define ownership/consistency precisely: eventual conflict detection during partitions is not exclusive global lock safety. For operations that require true mutual exclusion, implement a scoped authoritative lock/fencing backend only if repo doctrine authorizes it; otherwise refuse strong guarantees and surface conflicts/compensation. Develop convergence and anti-entropy tests with deterministic scheduler/model/property-based permutations; test three-node relay and partial graph topology. Include crash halfway through publish/consume/review and ancient replay.

Gate: convergent replicas produce equivalent canonical digest for identical authenticated event sets, no forged origin, no duplicate side effects, no stale claim returning as live, and partition claim conflicts are discoverable and explained.

Vykresleno z docs/COCKPIT_IDE_AUDIT.md — stejného Markdownu, který zobrazuje GitHub.

Forenzní zjištění, změřené 2026-09-10 v linked worktree v feature/development-runtime-model, odvětveném z origin/master v 08e4bb252, proti serveru, který si tento worktree sám sestavil a spustil. Je to fáze 01 balíku Cockpit IDE / control-plane a nic neimplementuje: zjišťuje, co existuje, dokazuje to spuštěním a říká, jaká je nejmenší bezpečná další fáze.

Architektura, proti které se měří, je ADR 0040 a DEVELOPMENT_RUNTIME.md: jeden kanonický runtime — registr schopností spustitelného souboru v Rustu — a každý povrch jeho konzumentem. Tento dokument je důkazem za tímto rozhodnutím a plánem, který z něj plyne.

Každé tvrzení zde vzniklo příkazem a příkaz je ukázán. Kde se číslo objeví bez příkazu, je to vada tohoto dokumentu.

Zjištění v jednom odstavci

Cockpit je věrná projekce registru, v němž je téměř nic vývojového. Jediné schopnosti, které cokoli mohou měnit, jsou executions.start, executions.cancel a peers.announce, a dokument OpenAPI, který server poskytuje, má přesně tyto tři operace jiné než GET. Každý příkaz vývojového životního cyklu žije ve druhém programu, bin/majordomus, a každý jeho uzel v grafu příkazů je odepřen každému strojovému povrchu. Cockpit proto nelze udělat IDE přidáním stránek: za stránkami není co volat. První fáze práce není UI, ale vybavit runtime měnícím vývojovým povrchem, který bude Cockpit spotřebovávat.

Tři další vady jsou nosné a byly nalezeny spuštěním systému, ne čtením: majordomus run se provádí ve vlastním procesu a běžící server ho nevidí, takže rovina provádění, kterou ukazuje Cockpit, a rovina provádění, kterou používá člověk, jsou disjunktní; server, který servíruje kód, jenž už na disku neexistuje, o sobě hlásí ready; a /cockpit/worktrees trvá 18,3 s, zatímco každá jiná stránka 1–4 ms.

Dvě vady preflightu, obě skutečné, žádná neobejitá:

P1 — MAJORDOMUS_SHARE rozbíjí push hook, nejen commit hook. Proměnná se exportuje do každého shellu v tomto repozitáři a ukazuje na share/ primárního checkoutu. Commit pod env -u MAJORDOMUS_SHARE uspěl; git push ve stejném skriptu ji nepřenesl a pre-push hook zamítl:

majordomus: MAJORDOMUS_SHARE names ~/dev/prismatic-majordomus/share, the
distribution of ~/dev/prismatic-majordomus — another worktree of this
repository, not this one … Run with: env -u MAJORDOMUS_SHARE
error: failed to push some refs to 'github.com:korczis/prismatic-majordomus.git'

Diagnostika je výborná a náprava je jeden příznak, ale past je v tom, že proměnná je zděděná, takže každý hook je hod mincí podle toho, jak byl příkaz vyvolán. Oprava patří k hookům, ne k tomu, aby si ji pamatoval každý worker.

P2 — základ auditu je sám už historický. origin/master bylo 08e4bb252, když byl tento worktree vytvořen, a 06fa25891, když audit skončil zhruba o čtyřicet minut později. Jakýkoli plán, který tento dokument navrhuje, musí předpokládat, že se master pohybuje během fáze, která jej implementuje.

2. Současná kanonická architektura, předmět po předmětu

Úplný soupis po jednotlivých konceptech — kanonický vlastník, úložiště, schéma, objevování, konzumenti, cesta mutace, události, testy, dokumenty a drift — je v DEVELOPMENT_RUNTIME.md a neopakuje se zde. Tento oddíl zaznamenává jen to, co ten soupis neobsahuje: subjekty vstupu a projekce, které balíček pojmenovává, a rozdělení na dva programy, které vysvětluje většinu zbytku.

Rozdělení, které vysvětluje zbytek

bin/majordomus (shell, lib/**) vlastní vývojový životní cyklus — start, check, finish, session, context, checkpoint, handover, evidence, decision, question, plan, adr, usecase, rules, doctrine, knowledge, history, search. bin/majordomus-cli (Rust) vlastní registr schopností a každou jeho projekci. Každý program odmítne příkazy toho druhého podle názvu:

$ ./bin/majordomus worktree create feature/development-runtime-model
majordomus: unknown command: worktree
majordomus: worktree is a command of the Rust executable, not of this tool; run: bin/majordomus-cli worktree

Diagnostika je přesná, což je smysl: rozdělení je záměrné a zdokumentované a je to stále důvod, proč Cockpit nedosáhne na životní cyklus. Povrch poskytovaný Rust exekutorem může promítat jen to, co Rust exekutor zná.

3. Provoz systému

Spuštěno podporovanou cestou repozitáře, v tomto worktree, proti vlastnímu sestavení tohoto worktree. Server primárního checkoutu zůstal nedotčen.

Start, opětovné použití a flotila

Start je idempotentní a opětovné použití stojí 30 ms. Dvě strukturní pozorování ze stejného výstupu:

  • Jeden server na checkout, ne na repozitář. desired je 127.0.0.1:8741 pro každý checkout, takže první získá port a každý linked worktree sklouzne na efemérní (tento dostal 62354). Id repozitáře je sdílené; server ne. Dokument, který říká „jeden sdílený server na repozitář“, popisuje primární checkout.
  • Flotila je většinou mrtvá. serve status vypisuje každý checkout, který kdy viděl. Téměř všechny jsou absent, ty, které ještě obsluhují, jsou většinou outdated, a seznam obsahuje dávno zmizelé scratch stromy pod /private/tmp/classify-* a /private/tmp/force-merge-*. Nic registr neuklízí.

To je nejnebezpečnější jednotlivá třída v auditu, protože každé měření, které kdokoli přes ten server provede, je tiše špatně — včetně, jak zjistil koordinátor této flotily, měření expozice schopností.

Peery

Nástěnka je vázaná na spojení a ukázalo se to náhodou: sonda MCP výše se objevila jako p1 / phase01-probe / http / attached: true a po zavření spojení sondy se počet vrátil na 0. Oznámení patří spojení, přesně jak varuje AGENTS.md; worker, který se znovu připojí, si ponechá práci a ztratí své místo.

Co může Cockpit už měnit

Cockpit není jen pro čtení a tvar jeho cesty zápisu je invariant, který funguje, nikoli porušení. Nese přesně tři akce a každá je schopnost druhu command vyvolaná přes vlastní deklarovanou trasu: spustit schopnost jako provedení a zrušit ho (share/cockpit/executions.js) a formulář generického runneru, který se generuje ze vstupního schématu schopnosti a může proto řídit jakoukoli příkazovou schopnost — dnes jen peers.announce, na /cockpit/capabilities/peers.announce.

Žádná stránka nenese ručně psaný <form method="post">; tlačítka deklarují data-mj-start, data-mj-cancel-route a data-mj-effect a prohlížeč čte trasu ze stránky, místo aby ji konstruoval. cockpit/mod.rs rovnou odmítá každou trasu Cockpitu jinou než GET a změna stavu z jiného původu je odmítnuta a pokryta testem.

Mutační povrch Cockpitu je tedy přesně mutační povrch runtimu, což je pravidlo, které uvádí ADR tohoto auditu. Problém není zapisovací cesta Cockpitu; je v tom, že mutační povrch runtimu neobsahuje žádnou vývojovou sémantiku, ke které by se dostal.

Executions — vada disjunktních rovin

$ curl /api/v1/executions                     → 0 count / 0 remembered
$ ./bin/majordomus-cli run objects.verify &   # while polling the server every second
  t+1s server sees: 0 count, 0 active, 0 remembered
  (run finished at t+1s)
run exit=0                                    → "OK read — 976 current, 0 drifted"
$ curl /api/v1/executions                     → 0 count / 0 remembered
$ curl /api/v1/peers                          → 0

Dřívější běh vyprodukoval pojmenované, úspěšné provedení — x-20260910T222800Z-2adbdce0 health.report — a server nikdy neviděl ani to.

majordomus run nepoužívá běžící server. Sestaví registr ve vlastním procesu, provede tam, streamuje na vlastní terminál a skončí. Úložiště provedení serveru je jiná rovina v jiném procesu. Důsledky pro IDE jsou přesné: /cockpit/executions může vždy ukázat jen práci spuštěnou přes tento server příkazem executions.start; vše, co vývojář skutečně spouští, je pro něj neviditelné; a živý kanál docs/EXECUTIONS.md, který funguje — GET /events vrací 101 Switching Protocols a streamuje rámce — je oknem do roviny, do které téměř nic nezapisuje.

V kombinaci s už zaznamenanou netrvalostí (an execution lives in the process that accepted it) historie provedení, kterou IDE potřebuje, dnes neexistuje nikde.

Řetěz generování je poctivý: ADR této větve dvakrát odmítl, než jej přijal, jednou kvůli nepodporované konstrukci YAML a jednou kvůli špatné úrovni nadpisu, a obě odmítnutí jmenovala soubor a důvod. doctor hlásí nula selhání a trvá 51–74 sekund proti rozpočtu 3 sekund — sedmnáctkrát až pětadvacetkrát přes, při každém commitu.

4. Matice mezer

5. Audit driftu

Repozitář sesouhlasuje většinu svých zrcadel a to je právě tak zjištění jako drift: CLI s registrem, každý generovaný artefakt s jeho zdrojem, dva stavové enginy plánu mezi sebou bajtovou shodou, dispatch tabulka s registrem příkazů, poskytovatelé se šablonami, projekce verze s jediným místem, kde se píše. docs/HARDCODING_LEDGER.yaml je poctivý rejstřík toho, co zbývá. 6. Plán

Hlavní příčiny, seřazeno

R1 — životní cyklus a registr jsou ve dvou programech a jen jeden z nich má plochy. Vše níže z toho plyne. Není to nehoda a je to zdokumentováno; prostě to není slučitelné s tím, aby se Cockpit stal vývojovou plochou.

R2 — runtime nemá žádnou mutující vývojovou schopnost. CapabilityKind::Command používají jen roviny provádění a peerů a nikde jinde, takže neexistuje typované vstupní schéma pro žádný vývojový přechod na žádném strojovém povrchu.

R3 — graf příkazů vidí shellový nástroj jen na nejvyšší úrovni. Každý uzel nástroje je skupina, takže politika expozice nemá co posuzovat a doplňování nemá co nabídnout a důvod zadržení každého je vlastností skupiny, a ne operace.

R4 — příkazy životního cyklu jsou interaktivní. Většina uzlů nástrojů je zadržena, protože se člověka na něco ptají. Interaktivitu povrch nijak neobejde.

R5 — nikde neexistuje vývojová historie. Trvalá úroveň je lokální ledger s vlastním slovníkem; živá úroveň je na proces a při ukončení zapomíná; a majordomus run nezapisuje ani na server, ani, pro vlastní provedení, nic trvalého.

R6 — seznamy sousedící s UI jsou ty bez správců. Repozitář své zrcadlené kopie sladí dobře, kromě hranice, kterou chce tento balíček rozšířit: oblasti navigace, zdokumentovaná směrovací tabulka Cockpitu a sémantika rozhodovaná v prohlížeči.

Fáze

Fáze A — jeden vertikální řez a nic jiného. Vezměte přechody plánu (start/verify/done) a deklarujte je jako jeden capability! druhu command v modulu plan, s typovaným vstupem, případy měření a registrovanou událostí knihy. Nasměrujte lib/plan.sh na něj, tak jako lib/context.sh a lib/capture.sh už volají binárku v Rustu. Odstraňte backing:plan z .ai/repo/development-semantics-baseline.txt.

Přijetí: nástroj MCP existuje a tools/call posune úkol; POST /api/v1/plan/… se objeví ve vygenerovaném OpenAPI, aniž by ho kdokoli upravil; stávající generický runner Cockpitu ho umí řídit bez úpravy Cockpitu; lib/plan.sh už samo nezapisuje YAML; test/cases/99_plan_capabilities.sh stále drží oba enginy na bajtové shodě; kontrola development-semantics hlásí o jednu položku méně a odmítne návrat baseline.

Tato fáze je celá architektura v miniatuře. Pokud přistane čistě, každá další fáze má stejný tvar; pokud ne, nic pozdějšího by nefungovalo také.

Fáze B — jeden model událostí. Schopnost druhu command připojí do ledgeru událost, jejíž název deklaruje share/events.yaml, a stejnou změnu publikuje do streamu provádění. Dejte ledgeru schopnost čtení, aby Cockpit mohl vůbec ukázat historii.

Fáze C — životní cyklus. task start/checkpoint/finish, session open/close, handover, evidence, podle vzoru, který založila fáze A, každý neinteraktivní, aby je politika expozice přestala zadržovat.

Fáze D — sestavený kontext jako schopnost. Patří paralelní práci na kompilátoru kontextu, ne této fázi.

Fáze E — vývojové stránky Cockpitu. Úkoly, milníky, relace, peery, úloha. Až po A–C, a jen jako projekce: stránka, která sama počítá stav, je přesně ta vada, které má celý tento dokument předejít.

Fáze F — odvodit navigaci. Sladit areas() s enumem Area a dispatcherem a odvodit směrovací tabulku docs/COCKPIT.md nebo ji zkontrolovat. Nezávislé na zbytku; levné; zabrání další nepropojené stránce.

Necíle

Terminál nebo PTY na jakémkoli povrchu. Úprava zdroje repozitáře v prohlížeči. Opakování a plánovač — provedení ve vlastní modulové dokumentaci uvádí, že je z rozhodnutí nemá. Druhé úložiště dat. Druhý projektový model. Hromadný port lib/*.sh, dříve než může cokoli jiného začít. Nové podstatné jméno pro cokoli, co repozitář už pojmenovává.

# three remote waiters of the form ssh host 'pgrep -f "<script>" && echo running' never ended on lundra on 2026-11-05: Linux pgrep -f matches the remote zsh -c whose own command line carries the pattern; anchor the pattern to the interpreter (pgrep -f '^bash /abs/path/script.sh') or poll the pid with kill -0, and the ssh-failure branch of an until ! ssh ... loop read a timed-out connection as ended, so a wait on a remote process must tell a dead connection from a finished process

# Evidence

- `ssh lundra 'pgrep -f "<script>" && echo running'` spawns a shell on the host whose own argv carries the pattern, and procps `pgrep -f` matches the full command line of every process, that shell included; the waiter answered "running" for as long as it asked. The anchored form `pgrep -f '^bash /abs/path/script.sh'` matches the interpreter's argv only, and `kill -0 <pid>` asks for one pid, as the seat's waits of 2026-11-05 did after the change (`until ! ssh host 'kill -0 <pid>'; do sleep 45; done`, curated note s-20261028132518-6330-51679dda646b).
- The ssh-failure branch of such a loop reads a timed-out connection (ssh exit 255) as the process having ended; a remote wait tells the connection's exit from the command's before it reports.
- `scripts/reap-orphans` keeps the same discipline on this side ("a process is never matched by name"), and curated note s-20261020233257-5779-6b073d83896e is the earlier incident of listing processes by a name match.

HTTP API: trace

Které větve a commity realizovaly úkol a kterému úkolu a milníku commit sloužil — odvozeno z gitu a z kanonického projektového modelu při každém volání, nikde se neukládá. Větev pojmenovává úkol, když je některá z jejích složek cesty identifikátorem úkolu; commit patří úkolu, jehož větve ho drží; commit, který žádná taková větev nedrží, se hlásí jako nepřiřazený, a ne vynechává, protože práce bez prováděcího kontraktu je přesně to, co má zpráva o dohledatelnosti zviditelnit. Pull requesty jsou fakt GitHubu a tento spustitelný soubor nevolá síť: čte je a k této odpovědi je připojuje podle názvu větve `scripts/traceability`.

GET /api/v1/trace trace.report

Celý graf práce nad větví

Každý úkol, který jmenuje alespoň jedna větev, s jeho větvemi a commity, každý deklarovaný úkol, který nejmenuje žádná větev, a nejnovější úsek trunku s každým commitem přiřazeným úkolu, jehož větve jej drží, nebo ohlášeným jako nepřiřazený. Součty počítají obě strany, takže podíl trunku, který nezohledňuje žádný kontrakt provádění, je číslo, ne dojem. Čte se z gitu při každém volání: historie se mění mimo tento proces.

  • query
  • behaviorally_verified
  • vyžaduje se měření výkonu
  • cache vypnuta
  • nástroj MCP majordomus_traceability
  • zdroj MCP {"name": "traceability", "uri": "majordomus://traceability"}

GET /api/v1/trace/commit trace.commit

Jakému kontraktu tento commit sloužil

Jeden commit s úkolem a milníkem, kterým sloužil, nebo fakt, že žádný nelze najít. Přičtený, když ho drží větve právě jednoho úkolu, nejednoznačný, když ho drží větve pojmenovávající dva úkoly, a nepřičtený, když ho nedrží žádná větev pojmenovávající úkol — což je buď práce commitnutá bez kontraktu provedení, nebo větev smazaná po svém mergi, a odpověď to říká, místo aby mezi nimi hádala.

GET /api/v1/trace/issue trace.issue

Co tento úkol realizovalo

Jeden úkol s větvemi, které ho pojmenovávají — lokálními i vzdálenými sledovacími, kde větev má už jen remote — a u každé s commity, které drží a trunk ne: měřeno proti trunku, dokud je větev otevřená, a proti prvnímu rodiči merge commitu, který ji přinesl, jakmile je mergnutá. Větev, která se dostala do trunku bez vlastního merge commitu, to říká a nic si nenárokuje, protože její commity nelze od trunkových rozeznat. Milník pochází z kanonického záznamu úkolu, což je jediná hrana, kterou git nedrží, a `declared` říká, zda projektový model toto id vůbec má — repozitář bez plánu stále dostane větve a překlep se stále nemůže číst jako práce, kterou nikdo neudělal.

  • query
  • behaviorally_verified
  • vyžaduje se měření výkonu
  • cache vypnuta
  • Nástroj MCP majordomus_trace_issue

Parametry dotazu

názevtyppovinnépopispříklady
issue string ano ID úkolu tak, jak jej píše projektový model (`I1305`). ID, které model nedeklaruje, se zodpoví `declared: false`, nezamítne se a neodpoví se holou prázdnou stopou: překlep čtený jako "nic tento úkol nerealizovalo" je jediná odpověď, kterou tato schopnost nesmí nikdy dát. first-issue: "I0001"

Přiřazení

Integrace

"open" | "merged" | "absorbed" | "unknown"
Jak větev stojí vůči trunku, což rozhoduje, které commity jsou její vlastní.
  • openNení dosažitelné z trunku: jeho commity jsou ty, které trunk nemá.
  • mergedDosažitelné z trunku přes merge commit, který stopa jmenuje: jeho commity jsou ty, které tento merge přinesl.
  • absorbedDosažitelné z trunku bez vlastního merge commitu — fast-forward nebo rebase na něj. Jeho commity nelze od commitů trunku odlišit a žádné se nenárokují.
  • unknownKmen je neznámý, takže není s čím větev měřit.

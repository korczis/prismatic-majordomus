HTTP API: knowledge_base

Co odvozovač znalostí nechal k revizi a zda stále zapisuje: kandidátní záznamy čekající na povýšení s větví epizody, ze které každý pochází, jeden záznam podle id se všemi referencemi, které pojmenovává, vyřešenými proti indexu, ledgeru a gitu, a stav odvozování tohoto checkoutu posuzovaný podle prahů čerstvosti politiky. Čteno z indexu a ledgeru; nic zde nezapisuje — odvozovač patří shellovému nástroji a povyšuje člověk.

GET /api/v1/knowledge/candidates knowledge_base.candidates

Kandidáti čekající na review

Každý znalostní záznam se stavem candidate ve zdrojové třídě kandidátů: jeho třída, tvrzení, epizoda, ze které vznikl, a branch této epizody a jak dlouho čeká — měřeno od derivace, která ho zapsala, pak od commitu, který ho přidal, a nakonec od jeho vlastního data — posuzováno podle session.freshness; proti limitu politiky. Kandidát, jehož epizodu tento checkout nezná, je uveden bez branche, nikoli skryt. Řazeno podle id.

GET /api/v1/knowledge/record knowledge_base.record

Jeden záznam znalostí

Jeden záznam znalostí podle id — kandidát nebo schválený — s rozlišeným každým odkazem, který jmenuje: relace vůči sledovaným záznamům relací a ledgeru, úloha nebo rozhodnutí vůči ledgeru a úložišti úloh, commit vůči gitu, soubor nebo test vůči indexu a stromu, pravidlo, ADR, úkol nebo jiný záznam vůči indexu. Které odkazy visí, je otázka, kterou si recenzent klade před povýšením, a kterou klade validátor integrity každému záznamu. Odkaz `task:none` nebo `decision:none` se odmítne jménem.

  • behaviorally_verified
  • vyžaduje se měření výkonu
  • cache vypnuta
  • nástroj MCP majordomus_knowledge_record
  • $ knowledge record

GET /api/v1/knowledge/status knowledge_base.status

Zda deriver ještě zapisuje

Polovina úsudku o zastaveném zapisovači týkající se čerstvosti (ADR 0052, aplikováno na deriver znalostí ADR 0091): nejnovější řádek knowledge.derived, nejnovější řádek session.closed, kolik uzavřených epizod nejmenuje žádné odvození, počty kandidátů a — jakmile se v tomto checkoutu odvození spustilo a přepínač je zapnutý — zda nejnovější uzavřená epizoda zůstala neodvozená déle než session.freshness.stale_minutes. Id epizod se porovnávají, nikdy pořadí řádků. Zda cesta uzavření stále volá deriver, čte z kódu shellový validátor, ne zde.

  • Nástroj MCP majordomus_knowledge_status
  • Zdroj MCP {"name": "knowledge-status", "uri": "majordomus://knowledge-status"}
  • $ knowledge status

Schémata

Komponenty, které používají jen operace tohoto tagu. Každý řádek je pole daného typu, jeho doc komentář je popis; typ vlastněný jinou stránkou na ni odkazuje.

AgeSource

"derivation" | "commit" | "date"
Odkud bylo čteno stáří kandidáta ve frontě review. date kandidáta je záměrně den důkazu, z něhož pochází, aby stejný důkaz dával stejné bajty; den, kdy vstoupil do fronty, je jiný fakt a čte se nejprve z ledgeru, pak z gitu a teprve potom ze záznamu.

use majordomus_cli::capability::builtin::knowledge_base::AgeSource;
let from_ledger: AgeSource = serde_json::from_str(r#""derivation""#).unwrap();
assert_eq!(from_ledger, AgeSource::Derivation);
assert!(AgeSource::Derivation < AgeSource::Date, "the ledger is asked before the record");
  • derivationNejstarší řádek knowledge.derived v knize tohoto checkoutu, jehož cesty ho jmenují.
  • commitCommit, který soubor do této historie přidal.
  • dateVlastní date záznamu o půlnoci UTC: den důkazu, ne den fronty.

Úsudek patří ADR 0052 a je aplikován na tohoto zapisovatele: dokud se epizody zavírají, odvození následuje po každém zavření. Čtyři slova a žádné páté: reference pojmenovává objekt indexu, nebo něco, za co může ručit jen ledger a git, nebo soubor, který strom už nedrží a historie gitu ano, nebo nic. external není slabší object — commit nebo úloha jsou stejně skutečné jako pravidlo — říká, který čtenář odpověděl; historical se rozřeší také a je pojmenováno zvlášť, aby čtenář viděl, který původ přežil svůj soubor (I1987).

use majordomus_cli::capability::builtin::knowledge_base::ReferenceResolution;
let r: ReferenceResolution = serde_json::from_str(r#""external""#).unwrap();
assert_eq!(r, ReferenceResolution::External);
assert!(r.resolves(), "vouched for by the ledger or git is resolved");
assert!(!ReferenceResolution::Missing.resolves());
  • objectObjekt indexu: target je jeho URI, nebo u souboru jeho cesta.
  • externalRučí za to účetní kniha, úložiště úloh nebo git: relace, úloha, rozhodnutí, commit.
  • historicalfile: nebo test:, které strom už nedrží a historie gitu ano: citované před smazáním souboru, nebo připnuté jako file:<path>@<commit>. target je blob, který odpovídá, <commit>:<path>, který čte git show.
  • missingNic se k němu nehlásí. Visící odkaz je zjištění validátoru integrity.

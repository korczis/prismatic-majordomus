# A task's scope is judged over every file of every commit since the branch base (git log --first-parent --name-only base..HEAD), so a branch that cherry-picks another PR's commit as its base must name that commit's files in --scope at start; the I3769 task's pre-push finish --check refused site/i18n/cs/memory/db.jsonl from #2943's commit, and the cure was finish partial, start again with the file, three evidence runs, check, push. A scope cannot be widened while active (I4340).

Observed as friction about lib/finish.sh in episode s-20261105135037-9134.

# Evidence

- `lib/common.sh`, `mj_git_touched` (lines 496-523): the files a task touched are `git log -z --first-parent --no-merges --name-only --format= "$base..HEAD"`, less the commits already on the trunk (`--not "$trunk"`) that this checkout did not make. A commit cherry-picked from another pull request is not on the trunk, so its files are the task's and must be in its scope.
- The I3769 task of 2026-11-06: the pre-push `finish --check` refused `site/i18n/cs/memory/db.jsonl`, a file of #2943's commit that the branch had taken as its base; the cure was `finish --outcome partial`, `start` again naming the file, three evidence runs, `check`, push.
- A scope cannot be widened while a task is active: curated note s-20261029014908-3ca1-303247a52e23 (`start` refuses while a task is active).

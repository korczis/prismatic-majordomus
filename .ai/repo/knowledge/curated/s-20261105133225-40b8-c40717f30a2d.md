# POST /api/v1/peers/announce over HTTP is refused (announce needs an MCP session) and bin/majordomus-mcp refuses to start on a stale executable, so a seat on a checkout under the disk floor reaches the mesh but never the board

Observed as friction about docs/MCP.md in episode s-20261105133225-40b8.

# Evidence

- `file:docs/MCP.md`

# Evidence

- Still so on origin/master dd377e11c35: `apps/majordomus-cli/src/capability/builtin/peers.rs` line 413 refuses `peers.announce` reached over HTTP ("announce needs an MCP session: this call came through an interface with no peer identity"), and the declaration (line 462) says so: "Needs an MCP session: over plain HTTP there is no caller." `bin/majordomus-mcp` (lines 13-18, commit 8c8a331fc2a) never builds and answers a stale executable with the installed release only when it is of the tree's generation, otherwise exit 12, so the client reports a failed server and the session has no board.
- The way through, met by the evolve run of 2026-11-10: MAJORDOMUS_BIN naming an installed release whose crate is master's, with MAJORDOMUS_BIN_COMMIT, is trusted about freshness (`lib/rust_bin.sh`), so the MCP server starts on a checkout that cannot build. docs/MCP.md does not say this.

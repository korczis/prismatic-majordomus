# PHASE 02 — DURABLE EXECUTION COORDINATOR + MESH

Audit existing execution, task lifecycle, journaling, session checkpoints, mesh peer boards, leases/claims, handovers, reviews and worktrees. Reuse their canonical storage and identifiers. An 'orchestrator' is a reconciler of desired and observed states over existing entities, NOT an alternate agent framework or independently managed job queue.

Model attempts, dispatch decisions, progress events, external effect outcomes and recovery markers in the existing typed ledger/event infrastructure. Suggested observable phases (only if absent): READY, CLAIMING, DISPATCHED, RUNNING, VERIFYING, REVIEWING, INTEGRATING, COMPLETED, RETRY_WAIT, BLOCKED, FAILED, CANCELLED, UNKNOWN. Clearly separate domain status from derived presentation; avoid persistently writing redundant aggregates. Identify stable work identity from repo + intent + issue + plan generation, independent of ephemeral peer IDs.

Scheduling requirements: dependency-aware ready queue; bounded global and per-repo WIP; scope overlap detection; worker capability + provider constraints; available context and locality; fair aging/priority; cost/token/time budgets; critical-path-aware priority without starving low-priority work; explicit backpressure from PR/CI pipeline. Use no remote execution claim unless a secure worker executor exists: implement the narrowest typed worker execution boundary and authenticate it, with allowlisted actions, cancellation, typed sandbox/scopes, resource constraints and auditable effects. Mesh propagates claims/state and coordinates, while actual execution occurs only through authorized local/remote worker capability. Respect existing mesh trust and network limits.

Every side-effect: idempotency key; causal correlation ID; owner/lease epoch; duration/deadline; replay-safe receipt; completion evidence. Ensure at-least-once message delivery does not mean double effect: reconcile external GitHub PR/release/deployment state and use dedupe keys plus compare-and-swap where available. Explicitly document impossible exactly-once guarantees across external systems. Reject stale-leader actions (fencing), expire abandoned leases safely, and recheck authorization before effects.

Failure matrix: worker disappears; coordinator restart; mesh partition; two peers claim same exclusive scope; duplicate event delivery; out-of-order events; expired claim; GitHub rate limit; CI stuck; provider unavailable; user pause/cancel; worktree deleted externally; GitHub PR force-update; disk full; partial deploy. Derive healthy / degraded / unknown visibility, never pretend a partial board is complete. Resume from last recorded durable boundary without reapplying successful effects, or safely mark reconciliation-required when ambiguous.

Operator controls via canonical capabilities: start/pause/resume/cancel/retry/reassign/reconcile, with policy-checked authorization; scoped kill rather than global process termination; explain dispatch and schedule. Live events include monotonic cursor/sequence or suitable checkpoint with resume support; expose event stream via existing web transport (SSE preferred if sufficient, WebSocket if bidirectional needs justify), and avoid polling storms.

Tests: property tests for scheduler determinism given equivalent inputs; isolated worktree concurrency; restart after each state transition; injected duplicate/out-of-order events; expired/stale lease; side-effect dedupe; partition test; peer incapability; budgets; user cancel during running job; never spawn a second overlapping worktree for same canonical work unless explicitly configured. Instrument queue wait, execution time, failure/retry, pending PR backpressure.

Acceptance: launch two nonconflicting tasks, observe mesh assignments and real progress; a conflicting task waits; kill coordinator mid-run; resume and reconcile without duplicate effect, leaked lock or lost evidence.

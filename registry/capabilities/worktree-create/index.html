worktree.create

Make the worktree of a branch at its canonical path — the container beside the primary checkout, then the branch name with its hierarchy kept, derived and never given — or find it there. Idempotent: the canonical worktree already holding the branch is the answer (`existed: true`), with nothing created. Refused with the service's reason and nothing changed: the branch checked out somewhere else (`BranchAlreadyCheckedOut`, with the path it belongs at), the canonical path occupied by something else (`DestinationConflict`), a name git or the topology does not accept. A branch that does not exist here starts at `base` when given, else where the remote has it, else at the remote's trunk fetched now within a deadline, else the local trunk with how far behind it is (`start`). `git worktree add` runs under the worktree lock and a deadline, and is killed and refused when it passes it. The answer is the branch, the path, the `head` read back from the worktree, and whether it was created or existed; direnv's approval and the per-worktree hooks are carried to it as `worktree ensure` does, because this is that command.

What a create did.
propertytyperequireddescription
base string | null no The ref a new branch started from (origin/master).
branch string yes The branch checked out in it.
branch_created boolean yes Whether that branch was created by this command.
container string yes The container it went into.
container_created boolean yes Whether the container was created by this command.
envrc reference yes What became of its .envrc under direnv: the primary checkout's approval carried to this path, or why it was not. A worktree that starts blocked is the recurring "direnv does not work again"; this says so before the first cd does.
envrc_local reference no What became of the primary checkout's machine-local .envrc.local here. default {"outcome":"none_primary"}
existed boolean yes The worktree already existed at its canonical path and nothing was created: the existing answer of an idempotent create, where false is created.
head string | null no The commit the worktree's HEAD names now, read back from it after the create or the find, whichever this was; None when git cannot say (an unborn branch).
hooks reference no Which hooks it runs: its own tree's, bound per worktree when the shared core.hooksPath would have sent it to the primary checkout's (I2718). default {"outcome":"not_configured"}
path string yes Where the worktree is.
start one of 2 no Where a branch this command created started, and why there.
start_commit string | null no The exact commit a branch this command created starts at, read back from the worktree rather than assumed.

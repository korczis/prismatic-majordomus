title = "I4413 — A failed verification is run again over the trunk commit the work is built on, and its refusal says which failures were already there, so one red test of the trunk does not read as every task's defect"
description = "Two changes to mj_validate_verification in lib/finish.sh, none of which changes a repository that declares nothing. First, a policy key verification.failure_pattern (an extended regular expression with one group, absent: none): when it is declared, the verify command's output is written to a temporary file instead of /dev/null, the group's text on every matching line is a failure id, and the sorted, unique ids (at most 50, with their count) go into the refusal line and into a verify object that task.refused now carries (verify.failures); the output file is removed afterwards. Second, a policy key verification.base_rerun (boolean, absent: false), overridable per invocation by `finish --no-base-rerun`: when the verify command failed, finish exports the base commit with `git archive` into a temporary directory (never a linked worktree, so no worktree is registered and no hook runs), runs verification.base_prepare there when declared (for example `npm ci`), runs the same verify command there with the same environment, and removes the directory on every exit path. The base is the merge base of HEAD and the trunk's remote-tracking branch (mj_git_trunk_ref, lib/common.sh:540-549), and the task's start head (mj_cur head) when no trunk is known; the record says which (base_source: trunk or start). The verification is classified in the vocabulary I3313 defines for session records: introduced when the base run passes, or when a failure id of this run is absent from the base run's ids (only those ids are listed as introduced); pre-existing only when the base run fails, a failure_pattern is declared and every failure id of this run is among the base run's; unknown when the base run fails with no failure_pattern declared, or the base could not be exported, prepared or resolved (a shallow clone, a missing object), with the reason. unknown is never shown as pre-existing. The classification never accepts the task: a red verification stays a refusal whatever its class, as majordomus.verification-integrity requires. A pre-existing refusal reads `npm test — exit 1, 412s; pre-existing at 3e89654 (trunk): 1 of 1 failure fails there too: studio perf budget`, and its remedy names re-running finish once the trunk's failure is fixed and `finish --outcome blocked` with that reason, instead of a re-run of the same command over the same tree. task.refused records verify.origin with base, base_source, base_exit, base_seconds, class, failures, base_failures and, for unknown, reason. The rule majordomus.verification-integrity states that the base run classifies a refusal and never turns it into a pass."

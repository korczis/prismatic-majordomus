HTTP API: intents

What must become true above the milestones that realise it: each intent's statement, invariants and satisfaction criteria, its stage derived from the plan's milestone status, and each criterion's state derived from the evidence ledger. Nothing is stored and nothing transitions; an intent added under the project model is answered by all of these without a registration anywhere.

intents

What must become true above the milestones that realise it: each intent's statement, invariants and satisfaction criteria, its stage derived from the plan's milestone status, and each criterion's state derived from the evidence ledger. Nothing is stored and nothing transitions; an intent added under the project model is answered by all of these without a registration anywhere.

GET /api/v1/intents intents.list

Every intent, with its derived stage

Every intent the project model declares, each with the status the plan derives for its milestones, the state of the evidence behind each satisfaction criterion, and the stage those two derive: declared, planned, executing, verifying or satisfied — or cancelled or superseded, when the record says so.

  • query
  • behaviorally_verified
  • benchmark required
  • cache disabled
  • MCP tool majordomus_intents
  • MCP resource {"name": "intents", "uri": "majordomus://intents"}
  • $ intent list

No parameters.

Try it

The port is whatever the server logged; 8741 is the one it asks for first. The values are the operation's first example.

curl -s "http://127.0.0.1:8741/api/v1/intents"

Verified by apps/majordomus-cli/tests/http_serve.rs, which replays the route with these values against a server on a real socket.

GET /api/v1/intents/coverage intents.coverage

Which work carries which criterion, and why each issue exists

The plan read against the intents (ADR 0073): every criterion of every live intent with the live issues that serve it, the milestones they belong to, and its strength — covered, weakly covered when no serving issue requires evidence, observed when the recorded gap saw it already true, or uncovered when nothing in the plan will make it true — and every issue with the reason it exists: the criteria it serves, maintenance under a milestone no intent names, or unexplained under one that realises an intent.

  • query
  • behaviorally_verified
  • benchmark required
  • cache disabled
  • MCP tool majordomus_intent_coverage
  • $ intent coverage

GET /api/v1/intents/preflight intents.preflight

Which intent a piece of work serves

Given the issue a piece of work executes, or the paths it will touch, the intents it serves — issue to milestone to intent, each link named — and the governance those intents load; or a refusal naming the first link that is missing: an issue that does not exist, paths no open issue covers, a milestone no intent names.

  • query
  • behaviorally_verified
  • benchmark required
  • cache disabled
  • MCP tool majordomus_intent_preflight
  • $ intent preflight

nametyperequireddescriptionexamples

GET /api/v1/intents/record intents.record

One intent, with everything derived about it

One intent in full: its statement and invariants as authored, each milestone with the status the plan derives, each satisfaction criterion with the state of its evidence and the command that reproduces it, and the stage. The record's own file stays at `majordomus://intent/<id>`.

GET /api/v1/intents/validate intents.validate

What the intent model refuses

Every finding over the intents: an intent naming no milestone or no criterion, a milestone that does not resolve, a criterion with no evidence reference or one that names nothing this repository holds, governance that does not resolve, a successor that is not an intent, a file name that disagrees with its id — each a failure — and a milestone no intent serves, a warning.

  • query
  • behaviorally_verified
  • benchmark required
  • cache disabled
  • MCP tool majordomus_intent_validate
  • $ intent validate

Schemas

The components only this tag's operations use. Each row is the type's own field, its doc comment the description; a type another page owns links there.

IntentCoverage

object
The whole derived coverage: every criterion of every live intent, every issue with the reason it exists, and every finding the two produced. Nothing here is stored; it is derived on each read from the intents and the plan.

use majordomus_cli::intent_plan::{IntentCoverage, IssueOrigin, IssuePurpose};
let coverage = IntentCoverage {
    criteria: vec![],
    issues: vec![IssuePurpose {
        issue: "I0007".into(),
        milestone: "ops".into(),
        origin: IssueOrigin::Maintenance,
        serves: vec![],
        intents: vec![],
    }],
    findings: vec![],
};
assert_eq!(coverage.failures(), 0);
assert_eq!(coverage.purpose("I0007").unwrap().origin, IssueOrigin::Maintenance);
propertytyperequireddescription
criteria array of CriterionCoverage → CriterionCoverage yes Every criterion of every live intent, in intent then declaration order.
issues array of IssuePurpose → IssuePurpose yes Every issue of the plan, in id order, with the reason it exists.
findings array of IntentFinding → IntentFinding yes Every finding, in derivation order.

Used by intents.coverage

IntentList

object
Every intent, with its derived stage, and how many there are in each stage: what majordomus intent list, GET /api/v1/intents and the majordomus_intents tool all answer with, out of one derivation.

use majordomus_cli::capability::builtin::intents::IntentList;
let empty = IntentList {
    count: 0,
    stages: std::collections::BTreeMap::new(),
    intents: vec![],
};
// a repository that declares no intent answers the route, with nothing in it
assert_eq!(empty.count, 0);
propertytyperequireddescription
count integer (uint) yes How many intents.
stages map of integer (uint) yes How many in each stage, keyed by the stage word.
intents array of IntentView → IntentView yes Every intent, in identity order.

Used by intents.list

IntentPreflight

object
Which intent a piece of work serves, or why it serves none: the issues it resolved to, every intent reached with its link, the governance those intents load, and — when nothing is reached — the first link that is missing.

use majordomus_cli::intent::IntentPreflight;
let refused = IntentPreflight {
    verdict: "refused".into(),
    issues: vec![],
    matches: vec![],
    governance: vec![],
    refusal: Some("no open issue's scope covers README.md".into()),
};
assert_eq!(refused.verdict, "refused");
assert!(refused.refusal.is_some());
propertytyperequireddescription
verdict string yes serves or refused.
issues array of string yes The issues the work was resolved to: the one named, or the open issues whose scope covers a path.
matches array of IntentPreflightMatch → IntentPreflightMatch yes Every intent reached, with the link.
governance array of string yes The governance of every intent reached, each entry once, in first-seen order.
refusal string | null no When refused: the link that is missing.

Used by intents.preflight

IntentPreflightMatch

object
One intent a piece of work serves, and the link that says so: issue to milestone to intent, each step named rather than asserted.

use majordomus_cli::intent::{IntentPreflightMatch, IntentStage};
let m = IntentPreflightMatch {
    intent: "intent-lifecycle".into(),
    title: "Work is traceable to the intent it serves".into(),
    stage: IntentStage::Executing,
    milestone: "intent-lifecycle".into(),
    issue: "I1900".into(),
};
assert_eq!(m.issue, "I1900");
propertytyperequireddescription
intent string yes The intent.
title string yes Its title.
stage IntentStage → IntentStage yes Its derived stage.
milestone string yes The milestone that links the work to it.
issue string yes The issue that links the work to that milestone.

Used by IntentPreflight

IntentValidation

object
What the intent model refuses: whether it is valid, how many intents were examined, and every finding with its level. Warnings are reported and do not make it invalid.

use majordomus_cli::capability::builtin::intents::IntentValidation;
let v = IntentValidation {
    valid: true,
    intents: 2,
    failures: 0,
    warnings: 20,
    findings: vec![],
};
// twenty warnings and no failure is a valid model
assert!(v.valid);
propertytyperequireddescription
valid boolean yes True when no finding is a failure. Warnings do not make it false.
intents integer (uint) yes How many intents were examined.
failures integer (uint) yes How many findings are failures.
warnings integer (uint) yes How many findings are warnings.
findings array of IntentFinding → IntentFinding yes Every finding.

Used by intents.validate

IssueOrigin

"intent" | "maintenance" | "unexplained"
Why an issue exists: because it serves a criterion, because it is maintenance under a milestone no intent names, or because nobody said — which is a failure under an intent.

use majordomus_cli::intent_plan::IssueOrigin;
assert_eq!(serde_json::to_string(&IssueOrigin::Maintenance).unwrap(), "\"maintenance\"");
// work under no intent is legitimate and says so; it is never given an invented intent
assert_ne!(IssueOrigin::Maintenance, IssueOrigin::Unexplained);
  • intentIt serves at least one criterion of a declared intent.
  • maintenanceIts milestone is named by no intent: maintenance or operational work, stated as such.
  • unexplainedIts milestone realises an intent, but it names nothing it serves.

Used by IssuePurpose

IssuePurpose

object
The answer to "why does this issue exist?": the criteria it declares it serves, the intents whose milestones contain it, and which of the three origins that adds up to.

use majordomus_cli::intent_plan::{IssueOrigin, IssuePurpose};
let purpose = IssuePurpose {
    issue: "I1901".into(),
    milestone: "intent-planning".into(),
    origin: IssueOrigin::Intent,
    serves: vec!["intent-planning#criteria-are-covered".into()],
    intents: vec!["intent-planning".into()],
};
assert_eq!(purpose.origin, IssueOrigin::Intent);
assert_eq!(purpose.serves.len(), 1);
propertytyperequireddescription
issue string yes The issue id.
milestone string yes Its milestone.
origin IssueOrigin → IssueOrigin yes Which kind of reason it has.
serves array of string yes The <intent>#<criterion> references it declares, as declared.
intents array of string yes The intents whose milestones include this issue's milestone, sorted.

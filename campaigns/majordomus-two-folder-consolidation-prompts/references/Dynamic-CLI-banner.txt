### `.envrc` musí zůstat stupidně malý

Ideálně přibližně:

```bash id="1o87e1"
#!/usr/bin/env bash

PATH_add "apps/majordomus-cli/target/debug"

if command -v majordomus >/dev/null 2>&1; then
  eval "$(majordomus env export --shell=direnv)"
  majordomus env banner
fi
```

Možná ještě bootstrap fallback, pokud binary není dostupná. Ale **žádná business logika**.

`majordomus env export` a `majordomus env banner` přitom používají stejný snapshot.

## Co inferovat

Banner bych skládal automaticky minimálně z:

| oblast | source of truth |
|---|---|
| project name | git root / workspace metadata |
| version | Cargo workspace/package metadata |
| description | existující canonical project metadata |
| branch | git |
| dirty state | git |
| ahead/behind | git |
| issue | branch / Majordomus issue state |
| Rust version | toolchain |
| Node version | runtime, pokud relevantní |
| rules | typed `.ai/` registry |
| doctrines | typed `.ai/` registry |
| skills | skill registry |
| ADR count | knowledge registry |
| providers | provider registry + env availability |
| cockpit URL | server configuration |
| REST URL | server configuration |
| Swagger URL | router/OpenAPI metadata |
| docs URL | server routing metadata |
| recommended commands | **just metadata**, ne banner config |

Provider secrets samozřejmě nikdy neukazovat:

```text id="efqj96"
OPENAI     ✓ configured
ANTHROPIC  ✓ configured
OLLAMA     ○ unavailable
```

nikoli nějaký inteligentní pokus vypsat `sk-proj-...`, protože lidstvo má dost způsobů, jak si leaknout credentials.

## `justfile` bych současně rozsekal

Současný `just` podporuje jak `import`, tak stabilní moduly přes `mod`; moduly navíc tvoří přirozené namespaces typu `just dev foo` / `just dev::foo`. ([just.systems](https://just.systems/man/en/modules.html?utm_source=chatgpt.com))

Třeba:

```text id="qix9bs"
justfile

.just/
├── dev.just
├── test.just
├── docs.just
├── ci.just
├── release.just
├── deploy.just
├── generated.just
└── majordomus.just
```

Root:

```text id="84bye9"
mod dev '.just/dev.just'
mod test '.just/test.just'
mod docs '.just/docs.just'
mod ci '.just/ci.just'
mod release '.just/release.just'
mod deploy '.just/deploy.just'
```

A root si nechá jen několik ergonomických aliases:

```bash id="wmaq62"
just
just dev
just check
just test
just docs
just deploy
```

`just` umí navíc dumpnout parsed justfile jako JSON, takže Majordomus může jeho metadata **strojově introspektovat místo parsování textu vlastním polofunkčním parserem**. ([just.systems](https://just.systems/man/en/formatting-and-dumping-justfiles.html?utm_source=chatgpt.com))

To se mi líbí ještě víc:

```text id="rv5uis"
just definitions
      ↓
just --dump --dump-format json
      ↓
Majordomus just registry
      ├── banner suggestions
      ├── CLI
      ├── docs
      ├── Cockpit
      └── validations
```

### Ale pozor na „dynamic“

Nedělal bych generátor, který při každém vstupu do adresáře přepisuje `justfile`.

Lepší Majordomus princip je:

```text id="9b7wn9"
declarative files
       +
structural conventions
       ↓
discovery
       ↓
typed registry
       ↓
validation
```

Ne:

```text id="8u165h"
scan filesystem
↓
generate source
↓
commit generated garbage
↓
wonder why merge conflicts exist
```

Moduly jsou pro to vhodnější. `just` umí i optional modules, takže platform-specific nebo local části lze připojovat bez rozbití hlavního stromu. ([just.systems](https://just.systems/man/en/modules.html?utm_source=chatgpt.com))

## Schema

Rozhodně explicitní typ:

```rust id="i2rfy7"
struct RepositoryEnvironment {
    schema_version: String,
    project: ProjectIdentity,
    vcs: VcsState,
    toolchains: Vec<ToolchainState>,
    capabilities: CapabilitySummary,
    providers: Vec<ProviderState>,
    services: Vec<ServiceState>,
    workflows: Vec<WorkflowHint>,
    diagnostics: Vec<Diagnostic>,
}
```

A JSON Schema generované ze stejného Rust typu.

Potom platí:

```text id="4jveqv"
Rust type
   ↓
JSON Schema
   ↓
CLI JSON
   ↓
OpenAPI
   ↓
MCP
   ↓
Cockpit
```

Jedna pravda. Žádný ručně udržovaný schema soubor vedle implementace, protože proč mít drift zadarmo, když můžeme nemít drift vůbec.

## Ještě jedna věc: intelligent banner levels

Banner nemusí pokaždé řvát román.

Například:

```bash id="4bi0t2"
MAJORDOMUS_BANNER=full
MAJORDOMUS_BANNER=compact
MAJORDOMUS_BANNER=auto
MAJORDOMUS_BANNER=off
```

`auto`:

```text id="2ky02v"
first entry / changed repo state → full
ordinary re-entry                → compact
same shell/repo snapshot         → silent
error/warning                    → force relevant diagnostics
```

A zase to není ručně konfigurovaný hack. Renderer pouze rozhoduje podle snapshotu.

Kompaktní varianta:

```text id="leqn66"
◆ majordomus · master ✱3 ↑2 · Rust 1.91 · rules 27 · doctrines 18 · cockpit ✓
  just dev · just check · majordomus doctor
```

Tohle je IMO správná implementační hranice:

> **Nevytvářet „direnv banner“. Vytvořit typed `RepositoryEnvironment` subsystem a nechat `.envrc` být jedním z jeho consumerů.**

A zároveň bych v tom samém zásahu rozložil `justfile` na namespaced modules, přidal schema, validation/gates, tests, benchmarks, CLI/API/OpenAPI/MCP/Cockpit exposure a doctrine, že `.envrc` nesmí obsahovat repository-domain logic. Tím je to Majordomus řešení, ne další roztomilý shell script, který za půl roku nikdo nesmí otevřít. ([just.systems](https://just.systems/man/en/modules.html?utm_source=chatgpt.com))

# 07 — Evidence and fault-injection test matrix

Tests must include: zero-open state; one green PR; 82+ PR pagination; API partial/error responses; draft; approvals missing; checks bound to stale SHA; stacked ancestors; rebase conflict; already merged PR; semantically equivalent change; duplicate/superseded PR; associated auto-close issue; independently completed issue; milestone with and without distinct acceptance; same GitHub event delivered twice; concurrent allocator workers; two integration writers; process loss before/after merge; merge reply lost; version allocated but tag request lost; release created but deployment unconfirmed; deployment finished but ACK lost; failed remote health probe; rate limit; retry cap; lease expiry/fencing; active worktree cleanup; uncommitted files; mutated PR head; git branch protection; rollback/resume.

Assert: one and only one version per eligible independent completion event, no release for fake admin closure, monotonically valid versions under concurrent retries, no skipped required obligation, correct compatibility classification, current verified revision, issue/milestone acceptance evidence, no secret exposure, deterministic queue order, no destructive cleanup on uncertainty. Gate known failure modes; run unit, integration and adversarial end-to-end scenarios. Test with real repository tooling in a sandbox/fixture when possible; do not use production merges as destructive test fixtures.

Require concrete receipts from the repo's canonical CI / `.ai` governance. Report gate id, relevant commit, status, timestamp and provenance. Never describe a test as passed because the command returned a green exit code while its actual content was not verified.

{#- The site's one search: the dialog the navbar's trigger opens, on every page of every layout. It reads /docs/index.json, which scripts/site-build writes last from the pages the build published (scripts/lib/docs-index.mjs), so a result can only be a page that exists and an entity without a page is never a result. Nothing here lists what can be found. The index is fetched on the first open, not with the page: a reader who never searches pays nothing for it. The behaviour is site/search.js, which also drives the documentation hub's inline search (partials/docs-hub.html) with the same index, the same matching and the same ranking. The dialog is the combobox pattern: the field owns the listbox, the arrows move the active option through aria-activedescendant, Enter opens it, Escape closes and focus returns to whatever opened the dialog.

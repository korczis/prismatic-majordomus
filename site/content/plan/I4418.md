description = "Two changes. Neither moves a checkout that holds anything to lose, and neither supplies a threshold that no policy wrote. First, `majordomus serve ensure` (and through it the start event's mj_capture_ensure_server, lib/capture.sh:1679-1699) measures the trunk distance (worktree::trunk::measure) before it converges, and decides whether the checkout can be fast-forwarded. It can only when all of the following hold: HEAD is the trunk branch; the checkout is strictly behind the remote-tracking trunk as last fetched (behind > 0, ahead 0); no tracked file is staged or modified; no merge, rebase, cherry-pick, revert or bisect is in progress; and no index.lock exists. A new policy key checkout.fast_forward (off | offer | apply, absent: offer) decides what happens to an eligible checkout. With offer, the ensure answer (the human line and the JSON EnsureReport, which today carries no trunk field) gains `trunk` with standing, behind, eligible and the command `majordomus serve ensure --fast-forward`; the remedy in the MCP initialize trunk sentence names the same command. With apply, and with `--fast-forward` on any policy but off, ensure runs `git merge --ff-only <remote trunk>` in the checkout before it converges, never fetches, and reports the old and new heads as trunk.fast_forwarded {from, to}. A checkout that is not eligible is never moved. The answer says which condition failed (not the trunk branch, ahead of the remote trunk, uncommitted tracked changes, an operation in progress, or no remote trunk) and keeps today's remedy with its rescue step. A `git merge --ff-only` that refuses, for example over an untracked file it would overwrite, is reported with git's message and the checkout is left unchanged. The server's standing and its exit code are decided exactly as today. Second, share/skeleton/policy.yaml declares a checkout: block, trunk_distance with warn_behind 20 and fail_behind 200, plus fast_forward: offer, each commented, so a repository made by `majordomus init` judges its distance with numbers written in its own policy. Doctor's unjudged INFO (lib/doctor.sh:760) names the block to add, taken from the skeleton, instead of only `majordomus worktree trunk`. The reader still supplies no default threshold: a policy without trunk_distance stays unjudged, as project.a-checkout-serves-the-current-trunk requires."

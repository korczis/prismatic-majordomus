# a seat claim taken over a worktree's server on 2026-11-17 vanished within fifteen minutes when the server idle-exited (server.log: idle for 900 s ... stopping): the idle timer counts attached MCP sessions, board rows, executions, live channels and client requests, never a held claim (by design since I4007), so a claim made from the command line lives at most one idle bound after the last request and its answer does not say so; docs/MESH.md (Seats are claims) now says how to keep it (mesh beat once per bound, or serve ensure --idle 0) and I4653 makes mesh claim say it

# Evidence

- `apps/majordomus-cli/src/idle.rs` at ae13be1bd13: `Activity` holds peers (MCP sessions or board rows), executions, live channels and whether a client request was answered; `counts_as_use` excludes only the mesh transport, probes of `/` and sibling board reads. No held claim keeps a server, by design: I4007 was filed because idle servers kept their claims live.
- `apps/majordomus-cli/src/commands/serve.rs`: with `args.idle > 0` the loop logs `{why}; stopping` once `IdleTimer::observe` returns; `serve ensure` passes `--idle` from `server.idle_seconds` (900 in `.ai/repo/policy.yaml`) unless `--idle` is given, and `--idle 0` takes the branch that never idle-exits.
- 2026-11-17: a seat claim (seat/landing, seat/release) taken over a worktree's server ended within fifteen minutes; that server's log said `idle for 900 s ... stopping`, and a peer then found no seat holder.
- This change: `docs/MESH.md`, "Seats are claims", says a seat claim lives as long as its server run and how a holder without an attached client keeps it (`mesh beat` once per bound, or `serve ensure --idle 0`). I4653 records the tool change: `mesh claim` says when its claim would lapse, and an idle exit names the claims it ends.

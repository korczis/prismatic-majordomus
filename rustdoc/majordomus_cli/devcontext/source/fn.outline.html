Function outline

pub fn outline(text: &str) -> Result<Vec<Definition>, String>
Expand description

The definitions of one Rust file, in the order they are written.

An impl block and an inline mod are decomposed into the definitions inside them, so the ranges of one file do not nest; every other item is one range, a trait included. Two definitions written on one line share their span, and the compiler offers that span once, naming both; adjacent items may share a boundary line, so the costs of a file’s ranges add up to about, not exactly, the file.

The parser’s span table is released before this returns: the spans are turned into line numbers here, and a long-lived server that parses source on every request must not keep every file it ever read. Spans of other parses held on this thread across the call are invalidated with it.

use majordomus_cli::devcontext::source::outline;

let text = "/// A thing.\npub struct T;\n\nimpl T {\n    fn go(&self) {}\n}\n\nmod inner {\n    pub fn deep() {}\n}\n";
let defs = outline(text).unwrap();
let named: Vec<(&str, &str, usize, usize)> =
    defs.iter().map(|d| (d.item, d.symbol.as_str(), d.first, d.last)).collect();
assert_eq!(
    named,
    [("struct", "T", 1, 2), ("impl fn", "T::go", 5, 5), ("fn", "inner::deep", 9, 9)],
);

// a file that is not Rust syntax is an error, never an empty outline
assert!(outline("fn (").is_err());

# Mission 01: Reality audit and canonical provenance

Identify what actually exists in HEAD. Read repo policy before editing. Build the machine-readable `fact -> owner -> derivation -> surfaces -> proof -> gate` inventory using existing typed facilities when present. Compare latest repo state, generated web build, release metadata, claims catalogue and Cockpit. Identify and reproduce actual drift, with exact source locations and validation commands. Audit duplicate authored facts, generated inventory drift, stale public copy, undocumented exceptions, unknown or unverified status printed as verified, and inferred values sourced from stale JSON snapshots. Check claimed 0.20.0 vs older site detail versions as a hypothesis, not as an assumed current bug. Distinguish valid historical documentation from accidental stale runtime metadata. Repair observed root causes only, not superficial strings. Produce severity/prioritization and failing regression tests BEFORE a fix. Acceptance: every critical field has canonical owner and provenance, or a typed unresolved finding; issues/milestones/intent and acceptance evidence are represented through existing machinery.

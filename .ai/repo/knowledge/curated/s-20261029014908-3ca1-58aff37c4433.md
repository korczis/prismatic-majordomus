# mj_cargo_build_dir answers nothing for a relative crate directory, because mj_cargo_metadata_dir cds into it and then passes the same relative --manifest-path; every caller passes an absolute path, and a hand run of mj_rust_bound_build_dir must too

Observed as friction about lib/rust_bin.sh in episode s-20261029014908-3ca1.

# Evidence

- `file:lib/rust_bin.sh`

# Evidence

- `bash -c '. lib/rust_bin.sh; mj_cargo_build_dir apps/majordomus-cli'` printed nothing on 2026-10-29, while `mj_cargo_build_dir $PWD/apps/majordomus-cli` printed `~/.asdf/installs/rust/1.90.0/build-shared/majordomus`.
- lib/rust_bin.sh mj_cargo_metadata_dir runs `cd "$1" && cargo metadata ... --manifest-path "$1/Cargo.toml"`, so a relative `$1` is resolved twice. Every caller in the tree passes `$ROOT/...` or `$MJ_ROOT/...`, so only a hand run of mj_rust_bound_build_dir or mj_rust_prune_build_dir meets it.

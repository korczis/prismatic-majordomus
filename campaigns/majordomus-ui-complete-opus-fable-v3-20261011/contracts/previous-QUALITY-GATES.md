# Acceptance and gates

At completion demand actual proof of:
1. All reachable screens SSR with JavaScript off; links and navigation resolve from canonical route topology.
2. Data provenance verified per visible real metric, no reference art values/copied mock identifiers.
3. No extra state model, duplicative UI inventories, mock API, client-side business decisions or independently maintained statuses.
4. No-JS forms and links where meaningful; Cytoscape/ECharts deferred and local bundled; graceful failure fallback.
5. Keyboard/focus/touch, WCAG relevant contrast, reduced motion, responsive widths, CSP/auth/CSRF and secret masking.
6. Tests: Rust core/view unit, contract parity CLI/HTTP/MCP, server integration, UI interactions, negative/failure, incremental asset compilation, generated drift and visual regression.
7. `.ai/` canonical rule ownership and proof binding; update actual CI model and tests; no new unconditional 20-minute gate; targeted PR selection, slower suites where impact requires.
8. Docs: `docs/COCKPIT.md`, design/UX, user guides, page links and OpenAPI generated from actual declarations; no manually typed counts or versions.
9. Safe incremental merge and version analysis; staged rollouts through existing pipelines only, deploy URL/live SHA verified, record releases or blockers.
10. Self-host on clean external repo; no Majordomus-specific hardcoded feature IDs assumed.

Visual regression: compare all 11 reference images for composition but never enforce fabricated text/data equality. Add accessibility baseline and screenshots of **real** running UI.

Stop the mission only at verified satisfaction, delegated limit or genuine external blocker. A green CI job without deployment evidence is not deploy proof.

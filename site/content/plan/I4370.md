title = "I4370 — The pull-request and plan projection ships in the release as `majordomus forge`, reads an adopter's own models and facts, and writes only what they declare"
description = "`majordomus forge render|check|apply [--prs [--pr <n>]] [--plan-records [--milestones-only]] [--labels] [--budget <n>] [--out <file>] [--from <file>]` is the release's projection command. bin/majordomus dispatches it (a public command: share/commands.yaml, the usage text, its page and coverage, cases 30 and 31) to the adapter scripts/github-sync, shipped in the release archive under share/libexec/ and resolving its lib/ from the installed tree rather than from a checkout. share/libexec/ is already shipped whole (release-package:95 copies share/), but release-package:98 sets every file under share/ to 0644; the installed-archive case proves that the shipped adapter runs. The derivation and the writes can run in separate jobs: `forge render --prs --pr <n> --out <file>` writes a versioned JSON document, schema majordomus.forge-plan/v1 (share/schemas/majordomus/forge-plan/forge-plan.v1.schema.json), holding the facts it read and the writes it owes, and `forge apply --from <file>` applies exactly those writes, derives nothing, reads no record and never runs the `facts:` command. lib/forge.sh and share/libexec/github-sync are new shell units, so each gets a record in .ai/repo/automation/inventory.jsonl with an exemption (platform adaptor over gh), or `majordomus shell check` refuses them (ADR 0069). It reads the adopter's .ai/repo/project/project.yaml (repository, default_branch), .ai/repo/ci/pr-meta.yaml (actor, including `actor.login`, the GitHub login the projection writes as; trigger, permissions, the label families it owns, and an optional `facts:` command) and .ai/repo/ci/github.yaml (apply window, and `apply.budget`, the write budget per run, which `--budget` overrides for one run). A pull request's ids come from the typed subcommand I2901 adds, over its title, its commits' subjects, the records its head changes and its head branch, the branch read case-insensitively as I4366 defines. github-sync --prs reads no branch today. When pr-meta.yaml declares `facts:`, the pull request's facts come from that command's JSON in the declared schema majordomus.pr-facts/v1, shipped as share/schemas/majordomus/pr-facts/pr-facts.v1.schema.json and named by its validator in lib/ (doctor reports a schema nothing in lib/ or the Rust source names as applied by nothing, lib/doctor.sh:1652-1655): served ids with title, milestone and priority, conventional level and breaking flag, role (release, release-record or train), and landing method. Without `facts:`, they come from the adapter's own derivation. The `facts:` command is the default branch's: it runs only from the default-branch checkout, in the read-only job, and a `facts:` declaration that the pull request's head changes is ignored and reported. Type labels: an adopter's declared families override release/model.rs's commit types for that adopter, so OSCILLA's train(...) titles can carry a type. github-sync's own list is hard-coded today (header :90-91), not read from model.rs. I3979's equality test is amended to match: this repository's declaration still equals model.rs:23-43, and an adopter's declaration may add types. Where the pull-request vocabulary lives (the type and label families) is this issue's decision, which OSCILLA's owner left to this repository (C7): it is made before the implementation, recorded as a `majordomus decision` or in the ADR this command owes, and that record names the one file that holds the vocabulary; forge, I4371 and I4372 read it from that file and no second declaration exists. Identity markers (<!-- majordomus:record <id> -->), the six body states plus unmanaged, the managed pr-meta region and the closing-keyword refusal stay as github-sync has them. Exit codes, each an MJ_EX_* constant of lib/common.sh and declared on the `forge` entry of share/commands.yaml: 0 in sync or applied; 2 usage; 10 a declaration or a forge-plan file this version cannot read; 11 drift; 12 cannot run, or the reading is incomplete (gh unauthenticated, a pull request unread, a listing shorter than its totalCount; I4372 adds a declared repository field read UNKNOWN under `forge check --repo`); 13 a mutation failed; 14 a title over GitHub's limit; 15 apply refused; 16 the write budget is spent, nothing is half-written, and the next run resumes. A projection-owned `release-freeze` label family is added, declared in the pull-request vocabulary and in integration/classify.rs LABEL_POLICY. classify holds a pull request on it only when the observation shows that the login pr-meta.yaml declares as `actor.login` set it. To know that, integration/forge.rs reads, for an open pull request that carries release-freeze, the actor of its latest `labeled` event (one bounded issue-events read, inside ADR 0101's existing exception). A release-freeze set by any other login is ignored and reported, and `hold` stays a person's. Every workflow that writes with GITHUB_TOKEN writes as the same login, so a projection that uses GITHUB_TOKEN cannot be told apart from any other workflow of the repository; the documentation recommends a dedicated bot account or app token for the projection actor. The hold acts only on landings by `prs drain`: an adopter that merges with GitHub auto-merge, as OSCILLA does, gets no effect from release-freeze, and the documentation says so. The adapter in share/libexec reaches the forge through gh, so it is a network call by 'the tool itself' as github-sync's header defines it (bin/, lib/, share/, test/). That overrides work-graph-github's non-scope 'Moving network calls into the tool itself, which test/cases/08 forbids'. An ADR records the override; it is accepted by the owner's act before the pull request lands, and SECURITY.md and .ai/repo/project/milestones/work-graph-github.yaml cite it by number. SECURITY.md's 'Local only' promise (SECURITY.md:13-24, 'Nothing leaves the machine', one loopback request) is amended to name the adapter as the one request of the shell tool that leaves the machine, and the adapter joins the mesh (ADR 0067) and pull-request integration (ADR 0101) as the declared exceptions that reach the network, the second that reaches the forge. Case 08 adds share/libexec/* to the files it scans, recognises gh as a network client (it names none today), admits gh only in the declared adapter, and states how it treats share/libexec/sccache-mesh, whose loopback `nc -z` probe and `eval` of derived exports its existing patterns refuse. scripts/github-sync in this repository becomes the wrapper the release ships, so cases 3970, 894 and 45 keep passing. The trunk projection's prove phase, which today runs scripts/ci/github-check (.ai/repo/ci/github.yaml phases, github.yml:152) and is not shipped either, becomes `majordomus forge check` for an adopter."

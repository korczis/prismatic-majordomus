What is this intent for?

What the work is for, what it holds the work to, and whether the evidence says it is met.

the-layer-evolves-when-it-is-due

The repository decides when its layer should evolve, and a session carries it out

plannedunknown0 of 5 criteria metClose

At each episode boundary the repository derives once, at the episode's close and with no model, whether evolving its layer is due (skip, defer or run) and why, and the next session is told, with a directive to run the evolve skill when it is run; friction from refused tasks becomes a candidate only after it has been measured over every checkout's ledger; what an evolve run changes yields no candidate about itself; what evolution changed is measured; a curated note whose cited source moved since its last review is flagged for review; and promotion stays a person's act. It extends intent a-session-leaves-what-it-observed, whose criteria stand unchanged.

What does it hold the work to?

  • Promotion, routing into the plan and rejection remain acts; the readiness verdict proposes and never promotes (ADR 0091)
  • Derivation needs no model, network or provider
  • At most one evolve run acts on a scope at a time: the evolve skill holds an exclusive mesh claim on it, so concurrent 'run' verdicts in several checkouts lead to one run

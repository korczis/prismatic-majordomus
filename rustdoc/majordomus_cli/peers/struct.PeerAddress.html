Expand description

Where the worker behind a peer can be reached from outside its MCP connection.

A board row named a client and a version, and nothing a person or another session could act on: on 2026-10-22 the session running a 33-minute remote cargo test --doc could be found only by walking an ssh client’s parent chain to a provider pid, its messaging socket, and a start time matched by hand. Every one of those facts is in the environment the provider hands the processes it starts — the MCP server among them — so the address is read from there when the peer attaches, and never asked of the model.

The provider’s messaging token is a credential and is never read: the address is where to knock, not the key.

use majordomus_cli::peers::PeerAddress;
// a client that exposes nothing still has a machine and a parent process
let bare = PeerAddress::from_env(|_| None, Some(4242), "lundra").unwrap();
assert_eq!((bare.host.as_str(), bare.pid), ("lundra", Some(4242)));
assert!(bare.provider.is_none() && bare.mesh_session().is_none());

pub fn from_env( env: impl Fn(&str) -> Option<String>, parent: Option<u32>, host: &str, ) -> Option<PeerAddress>

The address an environment describes. env answers a variable by name; parent is the pid of the process that started this one, used when the provider names no pid of its own; host is the machine. None only when there is no host to name.

use majordomus_cli::peers::PeerAddress;
let env = |k: &str| match k {
    "CLAUDE_CODE_SESSION_ID" => Some("s-1".to_string()),
    "CLAUDE_CODE_MESSAGING_TOKEN" => Some("secret".to_string()),
    _ => None,
};
let a = PeerAddress::from_env(env, Some(7), "mac").unwrap();
assert_eq!(a.provider.as_deref(), Some("claude-code"));
assert_eq!(a.pid, Some(7), "no provider pid: the parent is the worker");
assert!(!serde_json::to_string(&a).unwrap().contains("secret"));
Source

pub fn from_initialize(params: &Value) -> Option<PeerAddress>

The address a bridge carried in initialize params, under _meta["dev.majordomus/address"].

use majordomus_cli::peers::PeerAddress;
let params = serde_json::json!({ "_meta": { "dev.majordomus/address": { "host": "mac", "pid": 9 } } });
assert_eq!(PeerAddress::from_initialize(&params).unwrap().pid, Some(9));
assert!(PeerAddress::from_initialize(&serde_json::json!({})).is_none());
Source

pub fn mesh_session(&self) -> Option<String>

The id this provider session has on the mesh, the one the edit guard judges its claims under (<provider>-<session>): what joins a board row to a mesh session. None unless both the provider and its session id are known.

use majordomus_cli::peers::PeerAddress;
let env = |k: &str| (k == "CLAUDE_CODE_SESSION_ID").then(|| "s1".to_string());
let a = PeerAddress::from_env(env, Some(7), "mac").unwrap();
assert_eq!(a.mesh_session().as_deref(), Some("claude-code-s1"));
let bare = PeerAddress::from_env(|_| None, Some(7), "mac").unwrap();
assert_eq!(bare.mesh_session(), None);
Source

pub fn line(&self) -> String

One line a person can act on: claude-code pid 85501 on mac, /tmp/cc-socks/85501.sock.

use majordomus_cli::peers::PeerAddress;
let a = PeerAddress::from_env(|_| None, Some(12), "lundra").unwrap();
assert_eq!(a.line(), "pid 12 on lundra");

mesh

The nodes this process discovered on the mesh: authenticated observations of other running Majordomus instances, converged into one registry, with the providers that heard them and the trust the policy assigned. Observation, never authority: a listed node can execute nothing here.

GET /api/v1/mesh mesh.status

The mesh, at a glance

Whether the mesh runs in this process and why not when it does not; this node's public identity; every discovery provider with its state and counters; the registry's tallies; and the refused datagrams by reason. The one status every surface shows.

  • benchmark required
  • cache disabled
  • MCP tool majordomus_mesh
  • MCP resource {"name": "mesh", "uri": "majordomus://mesh"}

GET /api/v1/mesh/doctor mesh.doctor

The mesh self-check

Every prerequisite proved on this machine alone: the declaration parses, the identity loads, a UDP socket binds, the multicast group joins, broadcast enables, and the protocol signs, encodes, parses and verifies end to end in memory. Deterministic, no second node required.

GET /api/v1/mesh/identity mesh.identity

This machine's node identity

The node identity kept under the user's state directory, public half only: node id, public key, display name. The signing key appears in no projection. Absent is an answer, not an error — the identity is created when a mesh first activates.

POST /api/v1/mesh/register mesh.register

Register with this node's mesh

Present one signed envelope; it is verified exactly as a datagram — bounds, staleness, signature, trust policy — and recorded as a rendezvous observation when it holds. The answer carries this node's own envelope and the candidates its registry holds, each verifiable end to end on its own signature. Registration grants nothing: the caller becomes a record, never an authorization. Changes this process's memory only.

  • command
  • experimental
  • benchmark required
  • cache disabled
  • MCP tool majordomus_mesh_register

Request body — RegisterInput, JSON

example refused

{"envelope":{"v":0}}

Try it

The port is whatever the server logged; 8741 is the one it asks for first. The values are the operation's first example.

curl -s -X POST "http://127.0.0.1:8741/api/v1/mesh/register" -H "content-type: application/json" -d '{"envelope":{"v":0}}'

Schemas

The components only this tag's operations use. Each row is the type's own field, its doc comment the description; a type another page owns links there.

DoctorCheck

object
One check's verdict.
propertytyperequireddescription
check string yes What was checked.
ok boolean yes Whether it holds.
detail string yes The evidence: a path, an address, an error.

Used by MeshDoctorReport

Envelope

object
The wire envelope: the advertisement plus its signature.
propertytyperequireddescription
v integer (uint32) yes Protocol version.
pk string yes The Ed25519 public key, hex. The node id is derived from it, never carried: a field that could disagree with the key is a field somebody will forge.
inst InstanceId → InstanceId yes This run of the node.
name string no A human name for the node. Presentation only.
seq integer (uint64) yes Monotonic per instance: a replayed datagram carries a counter the reader has already seen and is dropped.
ts integer (uint64) yes Seconds since the Unix epoch at signing time.
ep array of string no Where this node answers HTTP, as host:port authorities, at most MAX_ENDPOINTS. Advisory: an endpoint is where to try, identity is the key.
caps array of string no The transports the node serves: http, mcp, ws. Sanitized capability awareness, never an authorization.
repos array of string no The repositories this node serves, as the same 32-hex git-repository digests server.status reports. A digest discloses nothing about a path; a reader that serves the same repository recognises it, anyone else learns only "some repo".
ver string no The executable version, informational.
sig string yes Ed25519 over Advertisement::signing_bytes, hex.

Used by RegisterAnswer

InstanceId

string
One run of a node: 16 hex characters of OS entropy, new at every process start. A restart keeps the node id and changes this, which is how a reader tells "the same node came back" from "the same process is still there".

Used by Envelope NodeRecord PublicIdentity

MeshIdentityReport

object

Used by mesh.identity

MeshProviderState

"running" | "failed" | "stopped"
The provider's health, as every surface reports it.
  • runningThreads up, socket bound (where the provider has one).
  • failedThe provider could not start or died; ProviderStatus::detail says why. One provider failing never stops another — failure isolation is the contract.
  • stoppedStopped by the manager.

Used by ProviderStatus

MeshSource

"udp_multicast" | "udp_broadcast" | "rendezvous" | "synthetic"
Where an observation came from. A record accumulates these; provenance is the answer to "why do I see this node".
  • udp_multicastA multicast datagram.
  • udp_broadcastA broadcast datagram.
  • rendezvousA rendezvous answer or registration.
  • syntheticA synthetic provider (tests, self-check).

Used by Sighting

The stable identity of a node: 32 hex characters of the SHA-256 of its Ed25519 public key. Derived, never chosen: two nodes with one id hold one key.

Presence

"present" | "absent"
Whether the node is answering now, by its own announcements.
  • presentAn advertisement arrived within PRESENCE_TTL.
  • absentNothing within the TTL; the node may be gone or unreachable. It stays listed until RETENTION passes, then expires out entirely.

Used by NodeRecord

PublicIdentity

object
What everyone may know about this node: the id, the public key, a display name and this run's instance. Everything an advertisement carries; nothing that signs.
propertytyperequireddescription
node_id NodeId → NodeId yes The node id: a digest of the public key.
public_key string yes The Ed25519 public key, 64 hex characters. Whoever holds the matching secret is this node; there is no other proof.
display_name string yes A human name for the node, from the identity file; defaults to the first eight characters of the node id. Presentation only — never used for trust.
instance_id InstanceId → InstanceId yes This run of the node.

Used by MeshIdentityReport MeshStatus

Refusals

object
Refused datagrams, by reason. The diagnosis of a hostile or misconfigured network: a mesh that hears garbage says so, with numbers, instead of being quietly empty.
propertytyperequireddescription
oversized integer (uint64) yes Longer than the datagram bound.
malformed integer (uint64) yes Not an envelope.
version integer (uint64) yes A protocol version this executable does not read.
bounds integer (uint64) yes Out-of-bounds fields.
stale integer (uint64) yes Outside the clock-skew window.
signature integer (uint64) yes A signature that does not verify.
self_heard integer (uint64) yes This node's own datagrams, heard back and skipped.

Used by MeshStatus

RegisterAnswer

object
What a registration answers: whether the envelope was accepted, and the candidates the rendezvous holds. Defined here beside the client; the capability re-exports it.
propertytyperequireddescription
accepted boolean yes Whether the presented envelope was accepted into the local registry.
refusal string | null no Why not, when it was not.
candidates array of Envelope → Envelope yes The signed envelopes of the nodes this rendezvous currently holds, the answering node's own included. Each verifies on its own signature; the rendezvous vouches for nothing.

Used by mesh.register

RegisterInput

object
The input of mesh.register: one signed envelope, exactly as the wire carries it.

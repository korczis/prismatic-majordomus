Vykresleno z docs/SCHEMAS.md — stejný Markdown, který zobrazuje GitHub.

Tak, jak je implementováno. Každé zde uvedené pole je něčím zapisováno a něčím čteno. Pole, které ztratí jedno z toho, se odstraní, nezachovává se „na později“.

Conventions:

  • YAML pro vše, co edituje člověk. JSON Lines pro vše, k čemu jen připisuje Majordomus.
  • YAML je podmnožina a podmnožina je zúžení: žádné flow mapy, žádné skládání, žádné kotvy. Soubor, který tento repozitář přijme, se proto musí parsovat jako YAML i pro všechny ostatní, protože share/ je vendorován do repozitářů, jejichž nástroje nejsou naše. Tři konstrukce čtou naše zploštěvače tak, jak byly myšleny, a pro všechny ostatní parsery jsou syntaktickými chybami: nekvotovaný : uvnitř prostého skaláru, prostý skalár začínající indikačním znakem (`, %, @) a vnořené závorky uvnitř flow sekvence. Skalár ocitujte — oba stroje odstraní odpovídající okolní uvozovky, takže se hodnota nepohne. test/cases/128_the_subset_is_a_subset.sh se zeptá nezávislého parseru a selže, když kanonický soubor opustí jazyk.
  • Neznámé klíče jsou chyby na každé úrovni.
  • Pole identity (repository_id, branch, head, working_tree, changed_files) se vždy počítají z gitu při zápisu. Worker nebo člověk, který je dodá, je chyba, ne přepsání.
  • Časová razítka jsou UTC ISO 8601 se sekundami: 2026-09-03T19:30:12Z.

.ai/manifest.yaml

Registr sekcí vrstvy AI repozitáře. Discovery čte tento soubor a nikdy neprochází .ai/; soubor pod repo/, který nepokrývá žádná sekce, není kontext a nenese žádnou autoritu. init jej zapisuje z kostry; verze formátu je to, co spustitelný soubor ověří před čtením čehokoli jiného, a tu, kterou nečte, odmítne s uvedením důvodu.

schema: ai-repository/v1

repo:
  path: repo              # tracked canonical context
local:
  path: local             # this checkout's own; ignored by git
  tracked: false
  implicit_context: false

sections:                 # relative to .ai/; each one resolves to a path the tool reads
  policy: repo/policy.yaml
  profiles: repo/profiles
  rules: repo/rules
  prompts: repo/prompts
  skills: repo/skills
  workflows: repo/workflows
  knowledge: repo/knowledge
  adrs: repo/adrs
  project: repo/project

Každý klíč je povinný, kromě toho, že project se smí rozřešit na adresář, který neexistuje, což je repozitář bez plánu. Neznámé klíče jsou chyby (share/allow/manifest.txt). doctor selže, když chybí sekce, kterou manifest jmenuje, když local/ není ignorován nebo nese sledovaný soubor, nebo když projektová data z doby před .ai stále leží pod .majordomus/.

  always_loaded_budget_lines: 150        # hard cap on the always-loaded projection

    - scope_respected
    - verification_ran
    - state_updated
    - no_open_blockers
    - note_present

checkpoint:
  max_body_lines: 40                     # a body over this is refused, not truncated
  retention_max_files: 500               # doctor reports when exceeded

handover:

  retention_max_files: 200               # doctor reports when exceeded

  retention_max_lines: 5000

benchmark:

    p50: 0.5
    p95: 0.5
    p99: 0.6
  budget:                # doctor and watch report their own wall time against these (WARN, never the exit code)
    doctor_ms: 20000     # the skeleton's values, measured on a freshly adopted repository
    watch_ms: 20000      # re-derive with `majordomus bench` once your catalogue has grown

enforcement:                             # what doctor reconciles; each must be wired

    path: majordomus                       # on PATH, repo-relative, absolute, or named in the hook line
    args: [doctor]
    wired_by: git-hook:pre-commit

    path: majordomus
    args: [finish, --check]
    wired_by: git-hook:pre-push

projections:
  - provider: claude-code
    target: CLAUDE.md
    mode: region                         # file (default) | region
    always_loaded: true                  # exactly one projection may be always_loaded
  - provider: codex

    target: GEMINI.md
  - provider: generic

mode: file generuje celý cíl a vlastní každý jeho bajt. mode: region generuje jen text mezi dvěma značkami a nevlastní nic jiného v souboru:

Whatever the repository already wrote. Majordomus never reads or rewrites this.

<!-- majordomus:begin 7b88abe0f22a -->
... generated from the policy ...
<!-- majordomus:end -->

Hash v počáteční značce jmenuje politiku, ze které oblast pochází; není součástí hashovaného obsahu, takže opakované spuštění update po nesouvisející úpravě politiky není ruční úprava. update nahradí existující oblast na místě a v souboru, který žádnou nemá, jednu připojí. Neuzavřené, nesprávně seřazené nebo opakované značky se odmítnou (15), nikdy se nehádají. fingerprints.yaml zaznamenává mode vedle hashe a u oblasti hash pokrývá oblast — úprava mimo značky je věcí repozitáře a nikdy se nehlásí jako drift.

Hodnoty wired_by: git-hook:<name> (vyřešeno přes core.hooksPath nebo .git/hooks/), ci:<path> (soubor, který musí existovat a obsahovat volání), git-config:<key> (klíč, který musí vlastní konfigurace gitu klonu nastavit na hodnotu jmenující nástroj), toolchain:<file> (připnutý toolchain Rustu, který soubor jmenuje, je na tomto stroji nainstalován, takže scripts/derive a prs repair --apply umějí buildovat), manual (zdokumentováno, neověřeno; doctor to uvádí jako neověřené, nikdy jako zapojené). Řádek hooku nesmí spolknout návratový kód (|| true, || exit 0).

.ai/**/README.md — kontextové dokumenty

Kontextový dokument je soubor Markdown ve stromu .ai/ (bez local/ a rules/vendor/), jehož front matter deklaruje níže uvedený kontrakt. context.documents v manifestu pojmenovává názvy souborů, které ho musí nést všude, kde se ve stromu objeví; dnes je to README.md. Model viz CONTEXT.md.

kind: context

status: active                    # active | deprecated (discovered and listed, never applied)
scope: subtree                    # directory | subtree | explicit
paths: []                         # explicit only: repo-relative directories inside the tree

order: 100                        # integer; ties within one depth are broken by path
supersedes: []                    # replace only: ids of ancestor-chain documents, none of them final
tracks: [lib/rules.sh]            # git pathspecs this document describes

  require_contract: true          # true | false; the default where nothing declares it is true

created_at, head a working_tree popisují uzavření, takže se záznam čte zpět tímtéž resolverem a týmž štítkem divergence jako předávka: head je commit, na kterém relace skončila, a štítek ho porovnává s aktuálním. start_head a start_working_tree popisují otevření.

Referenční seznamy nesou identitu, kterou každý druh skutečně má, a nic žádnou nevymýšlí:

Dvě z nich jsou slabší identity než ostatní a to je zaznamenáno, ne zamlčeno: rozhodnutí nebo otázka se odkazuje textem, takže úprava toho textu odkaz rozbije a validace relace to hlásí jako visící odkaz, místo aby se tiše vyřešila v nic.

Seznamy se odvozují, nenahromadí se. Počítají se při uzavření čtením ledger.jsonl a ničím jiným. Žádný jiný příkaz nezapisuje do záznamu relace; checkpoint, decision, question a plan jsou beze změny a o relacích nic nevědí.

Alternativa — každý příkaz připojuje svůj odkaz k otevřenému souboru relace, jak běží — byla zamítnuta dvakrát: dává zápis na horkou cestu příkazů, které dnes jen připojují jeden řádek ledgeru, a vytváří druhé měnitelné úložiště faktů, které ledger už drží, čemuž se má tento záznam právě vyhnout.

Výběr probíhá podle razítka relace na každém řádku, ne podle časového rozsahu. Každý řádek registru nese pole session jmenující epizodu, která jej zapsala, vedle head a branch, které už nesl; všechna tři se počítají, žádné není ručně psané. Časový rozsah se zkusil jako první a byl špatně: registr je jeden soubor na repozitář a jeho první skutečný běh sebral úlohy, kontrolní body a předávky jiného pracovníka, protože nic v časovém razítku souběžné pracovníky neodliší.

Řádek bez session nepatří do žádné epizody a žádná obálka si jej nenárokuje. To je správná odpověď, ne mezera — relace jsou volitelné a práce provedená mimo ně se připisuje nikomu, ne tomu, kdo měl náhodou poblíž otevřenou relaci.

Cenou je, že se ledger stává nosným pro druhý účel. Je jen přidávaný, zapisuje jej pouze Majordomus a už jej validuje majordomus.ledger-integrity, což z něj činí bezpečnou věc, ze které odvozovat. Pořadí řádků ledgeru se zachovává, takže dvě události zapsané ve stejné sekundě nepotřebují vůbec žádný tiebreak.

Front matter zapisuje Majordomus. Tělo obsahující řádek, který vypadá jako klíč front matteru, je odmítnuto, stejně jako u předávky. Režim 0600. Vytvořeno atomicky. Nikdy se nepřepisuje, nikdy se dodatečně needituje: uzavřená relace je nahrazena pozdějšími informacemi, ne opravena.

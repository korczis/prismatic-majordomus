# a build host whose pinned tools differ from CI's fails cases on plain master: with zola 0.22.1 against the 0.23.4 setup-site installs, cases 1070, 3043, 533 and 805 failed on the component tag and 3196, 3503 and 731 on the host's environment, on master c98e5d3f81f exactly as on the train top built on it, so that host's train-top pre-push refused the top; a host with zola 0.23.3 passed the recomposed top's 35 gates and 195 cases

Observed as drift about scripts/ci/run-plan in episode s-20261103014800-e1b0.

- `file:.github/actions/setup-site/action.yml`

# Evidence

On 2026-11-02 the seven cases train 22b's pre-push failed on the build host (1070, 3043, 3196, 3503,
533, 731, 805) were run with `MJ_TEST_JOBS=4 bash test/run.sh <cases>` in a detached worktree of
master c98e5d3f81f on the same host: "tests: 0 passed, 7 failed", the same reasons as on the top.
Master's own CI run had passed them. The host's zola was 0.22.1; .github/actions/setup-site/action.yml
installs zola 0.23.4; zola 0.22 refuses `{% component cite_figure(name) %}` ("unexpected tag"), which
is what 1070, 3043, 533 and 805 printed. On a macOS host with zola 0.23.3 the top recomposed on
5bc72353c8d (fcafbcbff2e) passed: "35 gate(s) and 195 case(s) in 198s ... nothing CI would find here first".
This statement replaces s-20261103014800-e1b0-f47681588ac2, which named master 5bc72353c8d where the
cases had run on c98e5d3f81f.

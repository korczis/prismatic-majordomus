evaluate, following the successions a runtime holds (ADR 0067, addendum of 2026-10-15). Only statements that verify count; of those:

  • a key that two different successors claim to succeed is a fork, which only a stolen key can produce: the key and both successors are Rejected("succession fork"), unless the allowlist names a successor itself;
  • a key with one successor that is trusted (the allowlist names the key or the successor) is Retired(successor), whatever the allowlist says of the key;
  • a key the allowlist does not name is Trusted("succession") when a predecessor the allowlist names hands over to it. The depth is one: a key trusted only through a succession confers nothing on a successor of its own until the allowlist names it, and withdrawing a predecessor withdraws its successor with it.
use majordomus_cli::mesh::identity::{NodeIdentity, Succession};
use majordomus_cli::mesh::trust::{evaluate_with_successions, TrustPolicy, TrustState};
let old = NodeIdentity::ephemeral().unwrap();
let new = NodeIdentity::ephemeral().unwrap();
let (old_key, new_key) = (old.public.public_key.clone(), new.public.public_key.clone());
let statements = [Succession::sign(&old, &new, "2026-10-15T08:00:00Z").unwrap()];
let trust = |allow: &[String], key: &str| {
    evaluate_with_successions(&TrustPolicy::Allowlist, allow, &statements, key, None, None)
};
let allow = [old_key.clone()];
assert_eq!(trust(&allow, &new_key), TrustState::Trusted("succession".into()));
assert_eq!(trust(&allow, &old_key), TrustState::Retired(new_key.clone()));
// a withdrawn predecessor confers nothing
assert_eq!(trust(&[], &new_key), TrustState::Observed);

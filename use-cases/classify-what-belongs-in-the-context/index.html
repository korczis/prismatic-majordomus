Decide what belongs in the AI context, as data

Read the repository’s declared scope policy, see which paths are in and out of the index, and let doctor and the knowledge index apply it rather than a hardcoded list.

guaranteed Repository knowledgeintermediatemaintainerread-only

Situation

An AI client indexes what it finds: build outputs, the local state directory, a vendored binary, a data dump. The context fills with noise and, sometimes, with a secret. Every tool has its own ignore list, and none of them is the repository’s own statement of what matters.

What you run

  • doctor: the scope policy exists and parses
  • knowledge sources, knowledge nodes --scope shared: what the index discovers once the policy is applied
  • over MCP: majordomus_scope reads the policy, majordomus_scope_classify answers for one path

Outcome

What belongs in the AI context is declared once in the layer, checked, and applied by the shell tool and the server alike. A client that honours it indexes the repository, not the machine.

The scenario

Executed against the real tool, in a repository prepared by installed-wired, every time this site is generated. What follows is not a description of what should happen; it is what happened.

given

  • ·installed, and the two enforcements the policy declares are actually in place as hooks

when

  1. 1majordomus doctor
  2. 2majordomus knowledge sources
  3. 3majordomus knowledge nodes --scope shared

then

  • ·what is in and out of the context is one file in the layer, with a schema
  • ·build outputs, local state, binaries and secrets are out by declaration, not by luck
  • ·the MCP server classifies a path with the same data

Why the tool knows this

The chain from this page to the code: the use case names commands, rules and claims; each rule is dispatched from the registry and each claim names the test that proves it; the scenario above executed the commands. Nothing in this chain is prose about intent.

  • majordomus knowledgeThe compiled index over what this repository states.
  • majordomus doctorIs Majordomus itself healthy, and is every enforcement it declares actually wired here?

Over MCP the same layer is reached through majordomus_scope, majordomus_scope_classify (the MCP surface).

The rules that make it hold

  • blockingAI layer integrityThe repository's AI layer is real: the manifest declares a format this executable reads and every section it names exists, the checkout-local half is ignored by git and nothing under it is tracked, and no project data remains under the pre-.ai .majordomus/ path.
  • blockingPolicy completenessEvery policy value the code reads is declared in the skeleton policy, and no reader carries its own default for one.

Guarantees exercised

  • guaranteedThe repository's AI layer is one directory whose manifest names every section, readable without the tool
  • guaranteedCheckout-local state lives under .ai/local/, is ignored by git, and is absent on a fresh clone or worktree
  • guaranteedWhat a worker reads of the repository is declared once in .ai/repo/scope.yaml, out wins over in, and the Rust executable discovers, indexes and serves nothing outside it

Related use cases

Computed from what they share: claims, rules, commands, category, applications. Nobody maintains this list.

  • Trace a change to the context documents it affectsList the scoped context documents, resolve which apply to a path and why, and find out which documents a change set touches before it lands.
  • Extend what the executable serves by adding a file, never by rebuilding itAdd a rule, a prompt or a knowledge node to .ai/ and have it appear as an MCP resource, an HTTP route and a reference entry, with the same binary.
  • Move a repository from the pre-.ai layout to the layerSee what a migration would move, move it with a backup, and prove the result is a layer the tool reads.
  • Find an object of the layer without reading everythingSearch durable records literally across kinds from the shell, and ask the shared server the same question over MCP with majordomus_search and majordomus_get.
  • Serve the repository's AI layer to every AI client through one shared serverOpen the repository in Claude Code, Codex or Gemini CLI and have each of them read the same rules, prompts and knowledge over MCP from one process, seeing each other.

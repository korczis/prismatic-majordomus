# Implementation milestone M05: Roadmap and milestones

**Execute against actual current repository.** First inspect canonical conventions and reconcile existing intent/milestone/issue/PR. These task IDs are pack tracking keys, not new invented canonical issue IDs. Every issue must deliver a small vertical slice: typed source → projection → SSR → optional JS enhancement → tests → documented behavior → .ai enforcement when architectural → merged/released only when eligible.

## M05-I01: Canonical roadmap projection

**Intent:** Derive milestones, intent links, statuses, dependencies, evidence and release identities.

**Implementation contract**
1. Find existing canonical producer, consumer, route, policy, test and the active PRs touching them. Cite exact paths in the actual issue.
2. Extend existing typed data model/projection minimally; prefer derived data and code generation, reject per-page duplicated arrays or registries.
3. Implement working server-rendered content, stable deep links and any necessary progressive enhancement using design tokens.
4. Distinguish loading, empty, unknown, unsupported, stale, forbidden and failed. Never inject reference-image data.
5. Add negative and positive tests; enforce a meaningful invariant in existing gate machinery (when applicable) without making every PR rerun expensive suites.
6. Update appropriate docs and generated artifacts, attach source revision/evidence; validate, review, integrate, evaluate release bump, deploy only if authorized/eligible, then verify.

**Done when:** A reviewer can reproduce the working experience on real canonical data, identify data provenance, execute supported actions safely and see passing tests and operational evidence. Record genuine blockers, do not fake completion.

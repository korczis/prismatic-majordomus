HTTP API: intents

What must become true above the milestones that realise it: each intent's statement, invariants and satisfaction criteria, its stage derived from the plan's milestone status, each criterion's state derived from the evidence ledger, and its verdict derived from those criteria alone. Nothing is stored and nothing transitions; an intent added under the project model is answered by all of these without a registration anywhere.

intents

What must become true above the milestones that realise it: each intent's statement, invariants and satisfaction criteria, its stage derived from the plan's milestone status, each criterion's state derived from the evidence ledger, and its verdict derived from those criteria alone. Nothing is stored and nothing transitions; an intent added under the project model is answered by all of these without a registration anywhere.

GET /api/v1/intents intents.list

Every intent, with its derived stage and verdict

Every intent the project model declares, each with the status the plan derives for its milestones, the state of the evidence behind each satisfaction criterion, the stage those two derive — declared, planned, executing, verifying or satisfied, or cancelled or superseded when the record says so — and the verdict the criteria alone derive (ADR 0107): satisfied when every criterion is met, unsatisfied when a test or claim criterion is not, unknown when only command or deployment criteria are unmet or none is declared, with the criteria holding it back.

  • query
  • behaviorally_verified
  • benchmark required
  • cache disabled
  • MCP tool majordomus_intents
  • MCP resource {"name": "intents", "uri": "majordomus://intents"}
  • $ intent list

No parameters.

Try it

The port is whatever the server logged; 8741 is the one it asks for first. The values are the operation's first example.

curl -s "http://127.0.0.1:8741/api/v1/intents"

Tested by apps/majordomus-cli/tests/http_serve.rs, which replays the route with these values against a server on a real socket.

GET /api/v1/intents/binding intents.binding

What a piece of work is bound to before it starts

What a task asks before it starts (ADR 0111): given the issue the work executes, the intent it serves, the paths it will touch, or an exemption class with its reason, one standing — `bound` when the work serves a criterion of a live intent through links the preflight accepts, `maintenance` when its issues sit under milestones no live intent names, `exempt` when the class is one the policy declares under `intent.exemptions` and a reason was given, `refused` otherwise, each refusal with a cause: the preflight's own seven, and nothing_named, unknown_intent, intent_retired, intent_has_no_open_work, issue_outside_intent, ambiguous_intent (paths alone reached more than one intent), unknown_exemption, exemption_without_reason, exemption_names_work. The answer carries what was named, the issues and intents resolved with what each intent asks of the worker, a note when the paths lie outside the named issue's scope, and two pins a later reader compares: `plan_revision`, which moves when the intent, a link or the critique is edited, and `evidence_standing`, which moves when a served criterion's evidence changes state. Nothing is stored.

  • query
  • behaviorally_verified
  • benchmark required
  • cache disabled
  • MCP tool majordomus_intent_binding
  • $ intent binding

GET /api/v1/intents/coverage intents.coverage

Which work carries which criterion, and why each issue exists

The plan read against the intents (ADR 0073): every criterion of every live intent with the live issues that serve it, the milestones they belong to, and its strength — covered, weakly covered when no serving issue requires evidence, observed when the recorded gap saw it already true, or uncovered when nothing in the plan will make it true — and every issue with the reason it exists: the criteria it serves, maintenance under a milestone no intent names, or unexplained under one that realises an intent.

GET /api/v1/intents/preflight intents.preflight

Which intent a piece of work serves, or why it may not proceed

Given the issue a piece of work executes, or the paths it will touch, one verdict: `serves` when no issue is refused and at least one serves a criterion of a live intent through a link that holds, the plan of each such intent critiqued with no blocking finding open (issues judged maintenance beside it do not change the verdict); `maintenance` when the issues sit under milestones no live intent names and serve nothing, as `intent validate` allows; `refused` otherwise, each refusal with its issue, a cause — unknown_issue, no_issue_covers_paths, issue_serves_nothing, serves_another_intent, serves_unknown_criterion, intent_not_critiqued, open_blocking_finding — in path mode every issue judged and the worst verdict answered. The answer carries, for the intents reached and no others, the statement, the served criteria with the live state of their evidence, the invariants, non-goals and governance, the critique with its open blocking findings, and the recorded gap bounded to those criteria.

GET /api/v1/intents/validate intents.validate

What the intent model refuses

Every finding over the intents: an intent naming no milestone or no criterion, a milestone that does not resolve, a criterion with no evidence reference or one that names nothing this repository holds, governance that does not resolve, a successor that is not an intent, a file name that disagrees with its id — each a failure — and a milestone no intent serves, a warning.

Schemas

The components only this tag's operations use. Each row is the type's own field, its doc comment the description; a type another page owns links there.

BindingCause

"unknown_issue" | "no_issue_covers_paths" | "issue_serves_nothing" | "serves_another_intent" | "serves_unknown_criterion" | "intent_not_critiqued" | "open_blocking_finding" | "nothing_named" | "unknown_intent" | "intent_retired" | "intent_has_no_open_work" | "issue_outside_intent" | "ambiguous_intent" | "unknown_exemption" | "exemption_without_reason" | "exemption_names_work"
Why a binding was refused, as a word a reader greps for. The first seven are the preflight's own causes, carried through unchanged; the rest are what only a binding can find.

use majordomus_cli::intent::IntentPreflightCause;
use majordomus_cli::intent_binding::BindingCause;
// a preflight cause keeps its word
assert_eq!(
    serde_json::to_string(&BindingCause::from(IntentPreflightCause::IntentNotCritiqued)).unwrap(),
    serde_json::to_string(&IntentPreflightCause::IntentNotCritiqued).unwrap(),
);
  • unknown_issueThe issue named is not an issue of the plan.
  • no_issue_covers_pathsNo open issue's scope covers any of the paths.
  • issue_serves_nothingThe issue's milestone realises a live intent and the issue serves none of its criteria.
  • serves_another_intentThe issue serves a criterion of an intent whose milestones do not include its own.
  • serves_unknown_criterionThe issue serves an intent or a criterion that does not exist.
  • intent_not_critiquedAn intent the work serves has no critique.
  • open_blocking_findingThe critique of an intent the work serves has a blocking finding still open.
  • nothing_namedNothing was named: no issue, no intent, no paths and no exemption.
  • unknown_intentThe intent named is not an intent of this repository.
  • intent_retiredThe intent named is cancelled or superseded.
  • intent_has_no_open_workThe intent named has no open issue serving it, so there is no work to be bound to.
  • issue_outside_intentThe issue named serves none of the criteria of the intent named beside it.
  • ambiguous_intentPaths alone reached more than one intent; the worker must name the issue.
  • unknown_exemptionThe exemption class is not one the policy declares.
  • exemption_without_reasonAn exemption was given with no reason.
  • exemption_names_workAn exemption was given beside an issue or an intent: work is one or the other.

BindingRequest

object
What a worker named when it asked what its work serves. Every field is optional and the combinations are judged, not assumed: an issue alone, an intent alone, an issue beside the intent it should serve, paths alone, or an exemption with its reason.

use majordomus_cli::intent_binding::BindingRequest;

assert!(!by_issue.names_nothing());
// blanks are what a query string or a shell variable leaves behind, and name nothing
let blank = BindingRequest { issue: Some("  ".into()), ..Default::default() }.trimmed();
assert!(blank.names_nothing());

issue string | null no The issue the work executes.
intent string | null no The intent the work serves, when the worker names it directly.
paths array of string no The paths the work will touch.
exemption string | null no The exemption class, when the work is under no intent on purpose.
because string | null no Why the exemption applies.

Used by IntentBinding

BindingStanding

"bound" | "maintenance" | "exempt" | "refused"
Where a piece of work stands against the intents: the one word a start decides on.

use majordomus_cli::intent_binding::BindingStanding;
assert_eq!(serde_json::to_string(&BindingStanding::Bound).unwrap(), "\"bound\"");
assert!(BindingStanding::Refused.refuses());
assert!(!BindingStanding::Maintenance.refuses());
  • boundThe work serves at least one criterion of a live intent, through links that hold, and each such intent's plan was critiqued with no blocking finding open.
  • maintenanceThe issues the work resolves to sit under milestones no live intent names: derived maintenance, as intent validate allows.
  • exemptThe worker gave an exemption class the policy declares, with a reason.
  • refusedThe work may not start as bound work; every reason is in refusals.

Used by IntentBinding

ConditionState

"satisfied" | "missing" | "conflicting" | "unknown"
The state of one criterion as the gap observed it. Four values, because "not determined" has to be writable: an omitted criterion is refused, and Unknown is never a pass.

use majordomus_cli::intent_review::ConditionState;
assert_eq!(serde_json::to_string(&ConditionState::Conflicting).unwrap(), "\"conflicting\"");
assert_ne!(ConditionState::Unknown, ConditionState::Satisfied);
  • satisfiedAlready true at the observed commit.
  • missingNot true; work is needed.
  • conflictingSomething in the repository contradicts it.
  • unknownNot determined. Never read as satisfied.

Used by GapCondition

CritiqueClass

"missed_requirement" | "unproven_assumption" | "insufficient_work" | "unnecessary_work" | "regression_risk" | "surface_missing" | "delivery_verification"
The class of a critique finding: the question the adversarial pass asked. Closed, so that a review's findings can be counted by question rather than read as prose.

use majordomus_cli::intent_review::CritiqueClass;
assert_eq!(
    serde_json::to_string(&CritiqueClass::DeliveryVerification).unwrap(),
    "\"delivery_verification\""
);
  • missed_requirementDoes the plan miss something the intent requires?
  • unproven_assumptionWhich assumption is unproven?
  • insufficient_workWhich criterion lacks sufficient work?
  • unnecessary_workWhich work item is unnecessary?
  • regression_riskWhat could regress?
  • surface_missingWhich related surface must also change?
  • delivery_verificationWhich deployment or runtime verification is required?

CritiqueFinding

object
One critique finding: what the review found, what it is about, whether it blocks execution, and how it was resolved. class and resolution are None when the record spells one this module does not know, and the _text fields keep what was written.

use majordomus_cli::intent_review::{CritiqueFinding, CritiqueRecord, ResolutionState};
let c = CritiqueRecord::from_metadata("c.yaml", &serde_json::json!({

class_text string yes As written.
subject string yes <intent>#<criterion>, an issue id or a milestone id.

IntentBinding

object
What a piece of work is bound to: its standing, what was named, the issues and intents it resolved to with what each intent asks of the worker, the two pins, and every refusal.

use majordomus_cli::intent::Intents;
use majordomus_cli::intent_binding::{
    bind, BindingCause, BindingRequest, BindingStanding, IntentBinding,
};
use majordomus_cli::plan::Plan;
use majordomus_cli::policy::IntentPolicy;
#### let plan: Plan = serde_json::from_value(serde_json::json!({
####     "project": {"name": "p", "repository": "o/p", "default_branch": "master",
####                 "active_milestone": ""},
####     "statuses": {"issue": [], "milestone": []},
####     "milestones": [], "issues": [], "waves": [], "edges": [],
####     "milestone_edges": [], "findings": []})).unwrap();
let intents = Intents { intents: vec![], findings: vec![] };
let nothing: IntentBinding =
    bind(&intents, &plan, &[], &[], &IntentPolicy::default(), BindingRequest::default());
assert_eq!(nothing.standing, BindingStanding::Refused);
assert_eq!(nothing.refusals[0].cause, BindingCause::NothingNamed);
// nothing was reached, so there is nothing to pin
assert!(nothing.plan_revision.is_empty() && nothing.evidence_standing.is_empty());
propertytyperequireddescription
standing BindingStanding → BindingStanding yes bound, maintenance, exempt or refused.
named BindingRequest → BindingRequest yes What the worker named, trimmed: the request this answers.
exemption BindingExemption | null → BindingExemption no The exemption accepted, when the standing is exempt.
issues array of IntentPreflightIssue → IntentPreflightIssue yes The issues the work resolved to, each with the preflight's verdict.
intents array of IntentPreflightIntent → IntentPreflightIntent yes The intents the work serves, each with the criteria served, their evidence state, the invariants, the critique and the gap: what the worker is held to.
governance array of string yes The governance of those intents, each entry once.
plan_revision string yes The pin of what the work is for; empty when no intent was reached.
evidence_standing string yes The pin of where the served criteria's evidence stands; empty when no intent was reached.
notes array of string no What a worker should know and no gate refuses on.
refusals array of BindingRefusal → BindingRefusal yes Every reason the binding was refused; empty unless the standing is refused.
refusal string | null no When refused: every refusal's sentence, joined.

IntentPreflight

object

episodes.attach

Otevře epizodu provádění pro volajícího klienta, nebo obnoví tu, kterou už měl. 'external_id' je vlastní trvalé jméno klienta pro sezení — id jeho konverzace nebo vlákna — a musí přežít opětovné připojení: klient, který se vrátí pod stejnou identitou, dostane znovu svou vlastní epizodu, pod jakýmkoli peer id, které má nyní, místo druhé. Peer id tohoto serveru nestačí; přiděluje se na připojení. Poté vlastní provoz klienta udržuje epizodu naživu, ztráta spojení ji odpojí, ne uzavře, a uzavře ji majordomus_session_detach, zastavení serveru nebo reaper po uplynutí odkladu opětovného připojení. Epizodu repozitáře otevírá stejný příkaz, který spouští hook providera, a co ohlásil, je v odpovědi. Vyžaduje relaci MCP: přes prosté HTTP není připojení, ke kterému by se vázalo.

input · AttachInput

Vstup episodes.attach: který kus práce toto připojení nese.

Identita je jediné pole a neznámé je odmítnuto místo ignorováno, takže klient, který pošle peer id pod jiným názvem, se to dozví hned:

use majordomus_cli::capability::builtin::episodes::AttachInput;
let input: AttachInput = serde_json::from_str(r#"{"external_id":"conv-42"}"#).unwrap();
assert_eq!(input.external_id, "conv-42");
assert!(serde_json::from_str::<AttachInput>(r#"{"external_id":"x","peer":"p1"}"#).is_err());
assert!(serde_json::from_str::<AttachInput>("{}").is_err(), "the identity is required");
vlastnosttyppovinnépopis
external_id string ano Vlastní trvalé jméno epizody od klienta — id jeho konverzace, id vlákna nebo jak jinak nazývá sezení, v němž je.

Musí přežít znovupřipojení, protože to je celá jeho úloha: klient, který se vrátí pod stejnou identitou, dostane znovu svou vlastní epizodu a ne druhou. Postačí cokoli, co klient dokáže reprodukovat; nepostačí peer id tohoto serveru, které se přiděluje pro každé spojení a je při každém znovupřipojení klienta jiným řetězcem.

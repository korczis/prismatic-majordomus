Jeden příkaz k instalaci, jeden k inicializaci, nic dalšího, čemu věřit

Instalátor stáhne jeden archiv pro váš stroj, před rozbalením čehokoli ověří jeho otisk (digest) proti metadatům releasu a instaluje atomicky; bez gitu, bez Rustu, bez Node, bez roota.

Co dělá

majordomus init vytvoří vrstvu z kostry nástroje a odmítne přepsat existující; --extend doplní, co chybí, a nic nepřepíše. Repozitář zřízený dřív, než vrstva existovala, přesune migrate, náhled je s --dry-run, s ověřenou zálohou. Samotný nástroj potřebuje POSIX shell, git a program na kontrolní součty a při práci nikdy nesahá do sítě.

S --personal, na init nebo na instalátoru se vytvoří táž vrstva jako osobní vrstva jednoho člověka ve sdíleném repozitáři: je pokryta vlastním exclude souborem adresáře git, nic se nezapisuje do .gitignore a příkaz selže, pokud git status po něm nečte totéž jako před ním. update a capture install pokrývají to, co zapisují, stejně, doctor to při každém běhu znovu ověří a init --extend --shared předá vrstvu týmu, když své opodstatnění doložila.

Co nedělá

Neinstaluje do vašeho projektu nic kromě .ai/ a souborů, které politika jmenuje, a neinstaluje git hooky: doctor pojmenovává dva řádky, které ještě musíte přidat. Osobní vrstva necestuje: je jednoho checkoutu na jednom stroji, dokud není sdílena. Archiv pro Windows se nepublikuje, dokud shellová polovina nemá odpověď pro Windows, a model distribuce to říká, místo aby dodával program, který nic nemůže řídit.

Proč existuje

Provozní okamžiky z katalogu Why, které pojmenovávají některý z mechanismů této funkce. Nic zde nebylo přiděleno: okamžik se objeví, protože pojmenovává pravidlo, příkaz, schopnost nebo tvrzení, které pojmenovává i tato funkce.

Princip

Moduly schopností spustitelného souboru, které tato funkce pojmenovává, každý se schopnostmi, které skládá. Rozhraní, jichž každý dosahuje, jsou uvedena níže v části Rozhraní: jde o projekce jedné deklarace, ne o samostatné registrace.

Distribuce distribution ověřeno chováním

Jak je tento projekt balen, publikován a instalován: platformy, pro něž release staví, názvy artefaktů, které odvozuje jediná pojmenovávací funkce, kanonický příkaz instalátoru, publikované release a čím je samotný tento build. Každá odpověď pochází ze share/distribution.yaml a ze záznamů release; žádný zdejší povrch netvrdí vlastní fakt.

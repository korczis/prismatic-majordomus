# session close writes the episode's session record, which is meant to be committed, under .ai/repo/sessions/ as an untracked file of the checkout it runs in; in a linked worktree that was removed after its pull request, the record went with it and the episode's record was lost; commit the session record before a worktree is removed, and a removal should count untracked records under .ai/repo as unfinished work

Observed as friction about command:session.close in episode s-20261111110145-5143.

- `file:lib/session_context.sh`

# Evidence

- lib/session_context.sh line 11: the session record under .ai/repo/sessions/ is shared, derived and immutable, written by `session close` into the checkout's tree, where it stays untracked until committed (the primary checkout on the Linux build host holds two such untracked records from 2026-09-09 and 09-10).
- The second evolve run of 2026-11-10 closed its episode in a linked worktree that was removed afterwards, and its session record was lost; this run commits its record before anything else (the caller's instruction for this run).

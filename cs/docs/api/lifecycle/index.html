Vyvážení

object
Co ledger říká o životním cyklu epizody oproti tomu, co drží úložiště.

Invariant, který ADR 0052 žádá, vyjádřený jako aritmetika, kterou si člověk může ověřit: každá epizoda, která začala, se buď uzavřela, nebo je stále otevřená. Když started přesáhne closed + open, rozdíl jsou epizody, jejichž uzavření nebylo nikdy zaznamenáno — tvar výpadku, který ADR popisuje, kdy události stále přicházely a záznamy, které měly vytvořit, ne.

Znaménko záleží a oba směry znamenají opak. Kladné unaccounted je výpadek: epizody, které začaly, nejsou otevřené a nevytvořily žádný uzavřený záznam — práce, která proběhla a nezanechala nic. Záporné je běžné účetnictví: ledger byl rotován, nebo byl záznam commitnut z checkoutu, jehož řádky ledgeru nejsou v tomto, takže záznamů je víc než zahajovacích řádků, které je vysvětlují.

use majordomus_cli::capability::builtin::lifecycle::Balance;
use serde_json::json;

let of = |started, closed, open, unaccounted, agrees| -> Balance {
    serde_json::from_value(json!({
        "started": started, "closed": closed, "open": open,
        "unaccounted": unaccounted, "agrees": agrees, "note": "as measured",
    })).unwrap()
};

// the good case: every episode that started either closed or is still open
let sound = of(40, 37, 3, 0, true);
assert_eq!(sound.started as i64 - sound.closed as i64 - sound.open as i64, sound.unaccounted);
assert!(sound.agrees);

// the outage ADR 0052 describes: four closes that were never recorded
let lost = of(40, 33, 3, 4, false);
assert!(lost.unaccounted > 0 && !lost.agrees);

// and a rotated ledger, which is not a fault in either half
let rotated = of(2, 37, 3, -38, false);
assert!(rotated.unaccounted < 0, "more records than lines to account for them");

ClosedSession

object
Jedna uzavřená epizoda sledované, trvalé projekce — polovina tohoto podsystému, která přežije klon.

Nese jak path, tak uri, protože odpovídají na různé otázky: cesta je místo, kde je záznam v tomto checkoutu, a identifikátor majordomus://session/<identity> je to, čím tentýž záznam oslovuje každý jiný povrch, takže ho čtenář může následovat na stránku objektu, aniž by ji musel sestavovat.

Vše kromě identity, identifikátoru a cesty je volitelné, protože záznam zapsaný starším uzavřením nese méně polí a je pořád záznamem.

use majordomus_cli::capability::builtin::lifecycle::ClosedSession;
use serde_json::json;

let s: ClosedSession = serde_json::from_value(json!({
    "session_id": "s-0042",
    "uri": "majordomus://session/2026-09-12-s-0042",
    "path": ".ai/repo/project/sessions/2026-09-12-s-0042.md",
    "created_at": "2026-09-12T15:44:00Z",
    "branch": "master",
    "head": "cd04012f1",
    "outcome": "landed",
})).unwrap();

assert!(s.uri.starts_with("majordomus://session/"), "addressable as an object");

// an older record with less in it is still one, and says so by absence
let sparse: ClosedSession = serde_json::from_value(json!({
    "session_id": "s-0001",
    "uri": "majordomus://session/2026-08-01-s-0001",
    "path": ".ai/repo/project/sessions/2026-08-01-s-0001.md",

Používá ClosedSessions

ClosedSessions

object
Sledovaná polovina subsystému: záznamy, které klon obdrží.

total je přesné a newest je okno a držet je jako dvě čísla je celý smysl tohoto typu. Sledovaný adresář roste bez omezení a karta Cockpitu není stránka výpisu, takže řádky jsou omezeny — ale omezený seznam, který by nenesl skutečný součet, by repozitář potichu podhodnotil, což je tvar vady, který tento repozitář pokousal natolik často, že si zaslouží jméno. window říká, kolik řádků se vrátilo, aby čtenář viděl strop, místo aby ho odhadoval.

use majordomus_cli::capability::builtin::lifecycle::ClosedSessions;
use serde_json::json;

let row = |id: &str| json!({
    "session_id": id,
    "uri": format!("majordomus://session/{id}"),
    "path": format!(".ai/repo/project/sessions/{id}.md"),
    "branch": "master",
});
let c: ClosedSessions = serde_json::from_value(json!({
    "total": 137,
    "on_this_branch": 41,
    "newest": [row("s-0137"), row("s-0136")],
    "window": 2,
})).unwrap();

// the window is what came back; the total is what exists
assert_eq!(c.window, c.newest.len());
assert!(c.total > c.window, "the rows are capped and the total is not");
assert!(c.on_this_branch <= c.total);

Používá lifecycle.closed

Epizoda

object
Jedna otevřená epizoda, jak ji zaznamenává její soubor a jak ji viděl registr.

Vše zde je zaznamenáno, ne odvozeno, a téměř vše je volitelné, což je smysl: ručně otevřená epizoda nemá poskytovatele, worker, který nedodal identitu, žádnou nemá, a epizoda, která se otevřela a nic neudělala, nemá řádek v knize, a tedy ani last_activity. Každé z toho je běžné a nic není chyba, takže je každé neseno jako absence — prázdná pole se na drátě přeskakují — a čtenář musí jejich absenci zvládnout, ne očekávat zástupnou hodnotu.

Dvě pole, která jsou vždy přítomna, jsou standing a note: kde epizoda stojí a proč tam stojí, slovy. Stav, podle kterého čtenář nemůže jednat, je selhání, kvůli kterému byl tento subsystém opraven, takže note není nikdy prázdné.

use majordomus_cli::capability::builtin::lifecycle::{Episode, EpisodeStanding};
use serde_json::json;

// the smallest true record: an episode opened by hand that has written nothing yet
let e: Episode = serde_json::from_value(json!({
    "session_id": "s-0001",
    "path": ".ai/local/state/sessions-open/by-hand.yaml",
    "standing": "open",
    "events": 0,
    "note": "open in this worktree; the pointer names another episode",
})).unwrap();

assert_eq!(e.standing, EpisodeStanding::Open);
assert!(e.provider.is_empty(), "no provider session owns a hand-opened episode");
assert!(e.last_activity.is_empty(), "it has written no ledger line");
assert!(e.tasks.is_empty(), "work outside a task is permitted");
assert!(!e.note.is_empty(), "a standing always says why");

// and absence stays absence: the empty fields are not serialised back as ""
let wire = serde_json::to_value(&e).unwrap();
assert!(wire.get("provider").is_none());
assert_eq!(wire["events"], 0, "a count of zero is a measurement, so it is kept");

Epizoda bez úlohy je běžná — práce mimo úlohu je povolena — a rozhodně to není důvod, aby se záznamy epizody nepsaly, což je předpoklad, který ADR 0052 odstraňuje.
poznámka string ano
Proč stojí tam, kde stojí, slovy. Nikdy prázdné: postavení, se kterým čtenář nemůže nic udělat, je právě ta vada, kterou se tento subsystém napravuje.

Používá Episodes

EpisodeStanding

"current" | "open" | "foreign" | "stranded"
Kde otevřená epizoda stojí, pokud to repozitář dokáže pozorovat.

Stojí za to být přesný v tom, co tady není. Zda poskytovatel, který otevřel epizodu, je stále připojen ke své konverzaci, není fakt tohoto repozitáře: soubor epizody nezaznamenává pid, nástěnka peerů nezaznamenává id epizody a klient, který skončí, aniž by vyvolal svou koncovou událost, zanechá soubor shodný s tím, který používá živý pracovník. Hádání by dalo přesně tu sebevědomě špatnou odpověď, které se tento subsystém snaží vyhnout, takže slovník níže je pozorovatelný — kde soubor je, čí worktree jmenuje a zda ho ukazatel sleduje — a note vždy říká, který.

Čteno jako škála, čtyři běží od „práce tohoto checkoutu“ po „už ničí práce“ a jen poslední je závada: current a open jsou obě živé epizody tohoto worktree a liší se jen tím, na kterou ukazatel právě míří, foreign patří jinému worktree a hlásí se, nepřebírá, a stranded je ta, která potřebuje člověka, protože ji nic nemůže uzavřít.

use majordomus_cli::capability::builtin::lifecycle::EpisodeStanding;

// the standings that are somebody's live work, against the one that is nobody's
let live = [EpisodeStanding::Current, EpisodeStanding::Open, EpisodeStanding::Foreign];
assert!(live.iter().all(|s| *s != EpisodeStanding::Stranded));

// serialised as the word `as_str` gives, so the two renderings cannot drift apart
for s in [EpisodeStanding::Current, EpisodeStanding::Foreign, EpisodeStanding::Stranded] {
    assert_eq!(serde_json::to_value(s).unwrap(), serde_json::json!(s.as_str()));
}
  • currentUkazatel tohoto checkoutu se na něj vyřeší. continuity.state se týká tohoto.
  • openOtevřená a jmenuje tento worktree, ale ukazatel jmenuje jinou epizodu. Dvě okna jednoho poskytovatele na jednom worktree jsou dva workeři a ukazuje se jen na jednoho.
  • foreignJmenuje jiný worktree tohoto repozitáře. Hlásí se, nikdy se nepovažuje za checkout tohoto — záznam o cizí práci, který se tiše stane vaším, je přesně selhání, kterému má dvouúrovňové pravidlo rozlišení předejít.
  • strandedWorktree, který jmenuje, z disku zmizel. Nic ji nemůže uzavřít: cesta uzavření skládá záznam z gitu ve worktree, ve kterém se epizoda otevřela.

Náprava je zde mechanická — odstranit soubor — protože je správná v každém checkoutu a nepotřebuje nic, co ještě není nainstalováno. lib/recover.sh na feature/session-store-recovery jsou tytéž tři degradace viděné ze strany zápisu: klasifikuje každého kandidáta čtením, tiskne důkazy před akcí a uvízlou epizodu uzavře do skutečného záznamu místo mazání. Až to přistane, náprava, kterou nález nese, by se měla stát majordomus recover episodes a obě detekce by se měly stát jednou — čtenář a zapisovatel, kteří si každý sám rozhodují, co znamená „uvízlý“, jsou dvě definice, a tento repozitář tento tvar pokousal dost často na to, aby jej pojmenoval.

use majordomus_cli::capability::builtin::lifecycle::Stranded;
use serde_json::json;

let s: Stranded = serde_json::from_value(json!({
    "session_id": "s-0007",
    "path": ".ai/local/state/sessions-open/claude-7.yaml",
    "reason": "the worktree it opened in is gone from disk",
    "remedy": "rm .ai/local/state/sessions-open/claude-7.yaml",
})).unwrap();

// the reason is about the world and the remedy is a command: a finding with no
// remedy is a complaint, so both are required fields rather than optional ones
assert!(!s.reason.is_empty() && !s.remedy.is_empty());
assert!(s.remedy.contains(&s.path), "the remedy acts on the file it names");

Cockpit

Your repository,at a glance.

The Cockpit renders every capability, object, graph, worktree and health check of the repository as pages, asking the same executor the command line, the HTTP API and MCP ask. It is served by majordomus at /cockpit; what follows is a picture of it, built from the same data.

The Cockpit, documented HTTP API

  • One navigation

    Its areas, then catalogues built from the registry's modules, the index's kinds and the graph derivations, in one sidebar.

  • Live repository state

    Every page asks a capability through the one executor MCP and the HTTP routes use.

  • Drill down anywhere

    A capability's page carries its schemas, projections, provenance and a runner built from its input schema.

A picture, not the Cockpit: the counts are the generated registry's, the series and the changes the changelog's. Run majordomus serve and open /cockpit for the live one.

  • One health report

    Health names the engine behind every check; a source that cannot answer is unknown, never ok.

  • Complete without script

    Every page is whole HTML before any script runs; the palette, runner and graph drawing are enhancements.

  • Nothing is a second list

    A capability, kind or graph added to the backend has a page, a navigation entry and a search entry.

Cockpit features

More than just a dashboard.

  • One executorthe same answer as the CLI, the API and MCP
  • A runner per capabilitya form from its input schema calls its real route
  • What writes is declareda command that writes tracked files says so before it is sent
  • For people and agentsthe server that answers agents renders the pages

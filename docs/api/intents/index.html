HTTP API: intents

What must become true above the milestones that realise it: each intent's statement, invariants and satisfaction criteria, its stage derived from the plan's milestone status, and each criterion's state derived from the evidence ledger. Nothing is stored and nothing transitions; an intent added under the project model is answered by all of these without a registration anywhere.

intents

What must become true above the milestones that realise it: each intent's statement, invariants and satisfaction criteria, its stage derived from the plan's milestone status, and each criterion's state derived from the evidence ledger. Nothing is stored and nothing transitions; an intent added under the project model is answered by all of these without a registration anywhere.

GET /api/v1/intents intents.list

Every intent, with its derived stage

Every intent the project model declares, each with the status the plan derives for its milestones, the state of the evidence behind each satisfaction criterion, and the stage those two derive: declared, planned, executing, verifying or satisfied — or cancelled or superseded, when the record says so.

  • query
  • behaviorally_verified
  • benchmark required
  • cache disabled
  • MCP tool majordomus_intents
  • MCP resource {"name": "intents", "uri": "majordomus://intents"}
  • $ intent list

No parameters.

Try it

The port is whatever the server logged; 8741 is the one it asks for first. The values are the operation's first example.

curl -s "http://127.0.0.1:8741/api/v1/intents"

Responses

400 ErrorBody invalid_input: The input does not fit the schema: a parameter of the wrong type, an unknown one, or a value the capability rejects.
404 ErrorBody not_found: The input names something the repository does not hold.

default ErrorBody Any other failure the transport reports: 405 method_not_allowed for another method on this path, 400 invalid_input for a body that is not a JSON object.
GET /api/v1/intents/preflight intents.preflight

Which intent a piece of work serves

Given the issue a piece of work executes, or the paths it will touch, the intents it serves — issue to milestone to intent, each link named — and the governance those intents load; or a refusal naming the first link that is missing: an issue that does not exist, paths no open issue covers, a milestone no intent names.

  • query
  • behaviorally_verified
  • benchmark required
  • cache disabled
  • MCP tool majordomus_intent_preflight
  • $ intent preflight

GET /api/v1/intents/record intents.record

One intent, with everything derived about it

One intent in full: its statement and invariants as authored, each milestone with the status the plan derives, each satisfaction criterion with the state of its evidence and the command that reproduces it, and the stage. The record's own file stays at `majordomus://intent/<id>`.

  • behaviorally_verified
  • benchmark required
  • cache disabled
  • MCP tool majordomus_intent_record

GET /api/v1/intents/validate intents.validate

What the intent model refuses

Every finding over the intents: an intent naming no milestone or no criterion, a milestone that does not resolve, a criterion with no evidence reference or one that names nothing this repository holds, governance that does not resolve, a successor that is not an intent, a file name that disagrees with its id — each a failure — and a milestone no intent serves, a warning.

  • query
  • behaviorally_verified
  • benchmark required
  • cache disabled
  • MCP tool majordomus_intent_validate
  • $ intent validate

No parameters.

Schemas

The components only this tag's operations use. Each row is the type's own field, its doc comment the description; a type another page owns links there.

IntentCriterion

object
One criterion with the evidence behind it: what the record declared, what the ledger says about it, whether that meets it, and the command that would produce the evidence again.

use majordomus_cli::intent::{IntentCriterion, IntentEvidenceState};
let c = IntentCriterion {
    id: "stage-is-derived".into(),
    criterion: "the stage follows the plan".into(),
    evidence: "test".into(),
    reference: "apps/majordomus-cli/tests/intent.rs".into(),
    state: IntentEvidenceState::NotRun,
    met: false,
    reproduce: None,
};
// nothing recorded is not a pass
assert!(!c.met);
propertytyperequireddescription
id string yes Unique within the intent.
criterion string yes What is observably true when it is met.
evidence string yes test, claim, command or deployment.
ref string yes What the evidence names, as authored.
state IntentEvidenceState → IntentEvidenceState yes Derived: what the evidence says.
met boolean yes Derived: the state is current.
reproduce string | null no The command that produces the evidence again, when one is known.

Used by IntentView

IntentEvidenceState

"current" | "stale" | "failing" | "not_run" | "not_derivable" | "unresolved"
What the evidence behind one criterion says, as a word. Only Current meets a criterion: a stale, failing, unrecorded or underivable reference never does, and neither does one that resolves to nothing.

use majordomus_cli::intent::IntentEvidenceState;
assert_eq!(serde_json::to_string(&IntentEvidenceState::NotRun).unwrap(), "\"not_run\"");
assert_ne!(IntentEvidenceState::Stale, IntentEvidenceState::Current);
  • currentA passing run of the test that is in the tree now, or a claim proven or with its inputs unchanged since its passing run. The only state that meets a criterion.
  • staleA passing run of a test whose source has changed since, or a claim whose inputs have.
  • failingThe latest recorded run did not pass.
  • not_runThe reference resolves and nothing has been recorded for it.
  • not_derivableThe reference resolves, and this kind of evidence (command, deployment) is not derivable from the ledger, so it never meets a criterion by itself.
  • unresolvedThe reference is empty or names nothing this repository holds.

Used by IntentCriterion

IntentFinding

object
One validation finding: its level, a stable code a reader greps for, the intent or milestone it is about, one line of what is wrong, and the command that shows it again.

use majordomus_cli::intent::{IntentFinding, FAIL};
let f = IntentFinding {
    level: FAIL.into(),
    code: "unknown_milestone".into(),
    subject: "intent-lifecycle".into(),
    message: "`no-such` is not a milestone".into(),
    reproduce: "majordomus intent validate".into(),
};
assert_eq!(f.level, "FAIL");
assert_eq!(f.reproduce, "majordomus intent validate");
propertytyperequireddescription
level string yes FAIL or WARN. A failure means the intent model is invalid.
code string yes The stable code a reader greps for.
subject string yes The intent or milestone the finding is about.
message string yes What is wrong, in one line.
reproduce string yes The command that shows it again.

Used by IntentValidation

IntentList

object
Every intent, with its derived stage, and how many there are in each stage: what majordomus intent list, GET /api/v1/intents and the majordomus_intents tool all answer with, out of one derivation.

use majordomus_cli::capability::builtin::intents::IntentList;
let empty = IntentList {
    count: 0,
    stages: std::collections::BTreeMap::new(),
    intents: vec![],
};
// a repository that declares no intent answers the route, with nothing in it
assert_eq!(empty.count, 0);
propertytyperequireddescription
count integer (uint) yes How many intents.
stages map of integer (uint) yes How many in each stage, keyed by the stage word.
intents array of IntentView → IntentView yes Every intent, in identity order.

Used by intents.list

IntentMilestone

object
One milestone an intent names, as the plan derives it. A milestone that does not resolve is carried with resolved: false rather than dropped, because a name that points at nothing is a finding and not an absence.

use majordomus_cli::intent::IntentMilestone;
let named = IntentMilestone { id: "no-such".into(), resolved: false, status: None };
assert!(!named.resolved);
assert!(named.status.is_none());
propertytyperequireddescription
id string yes The id the intent names.
resolved boolean yes Whether the plan holds a milestone with that id.
status string | null no The status the plan derives for it; absent when it does not resolve.

Used by IntentView

IntentPreflight

object
Which intent a piece of work serves, or why it serves none: the issues it resolved to, every intent reached with its link, the governance those intents load, and — when nothing is reached — the first link that is missing.

use majordomus_cli::intent::IntentPreflight;
let refused = IntentPreflight {
    verdict: "refused".into(),
    issues: vec![],
    matches: vec![],
    governance: vec![],
    refusal: Some("no open issue's scope covers README.md".into()),
};
assert_eq!(refused.verdict, "refused");
assert!(refused.refusal.is_some());
propertytyperequireddescription
verdict string yes serves or refused.
issues array of string yes The issues the work was resolved to: the one named, or the open issues whose scope covers a path.
matches array of IntentPreflightMatch → IntentPreflightMatch yes Every intent reached, with the link.
governance array of string yes The governance of every intent reached, each entry once, in first-seen order.
refusal string | null no When refused: the link that is missing.

Used by intents.preflight

IntentPreflightMatch

object
One intent a piece of work serves, and the link that says so: issue to milestone to intent, each step named rather than asserted.

use majordomus_cli::intent::{IntentPreflightMatch, IntentStage};
let m = IntentPreflightMatch {
    intent: "intent-lifecycle".into(),
    title: "Work is traceable to the intent it serves".into(),
    stage: IntentStage::Executing,
    milestone: "intent-lifecycle".into(),
    issue: "I1900".into(),
};
assert_eq!(m.issue, "I1900");
propertytyperequireddescription
intent string yes The intent.
title string yes Its title.
stage IntentStage → IntentStage yes Its derived stage.
milestone string yes The milestone that links the work to it.
issue string yes The issue that links the work to that milestone.

Used by IntentPreflight

IntentStage

"declared" | "planned" | "executing" | "verifying" | "satisfied" | "cancelled" | "superseded"
Where an intent stands, derived on every read and stored nowhere.

use majordomus_cli::intent::IntentStage;
// one word every surface prints, and an order that follows the work
assert_eq!(IntentStage::Executing.as_str(), "executing");
assert!(IntentStage::Declared < IntentStage::Satisfied);
  • declaredA named milestone does not resolve, or none is named.
  • plannedEvery milestone resolves and none has started.
  • executingA milestone is under way.
  • verifyingEvery milestone that counts is DONE; satisfaction is not yet evidenced.
  • satisfiedVerifying, and every criterion has current evidence.
  • cancelledThe record says it was abandoned.
  • supersededThe record names the intent that replaced it.

Used by IntentPreflightMatch IntentView

IntentValidation

object
What the intent model refuses: whether it is valid, how many intents were examined, and every finding with its level. Warnings are reported and do not make it invalid.

use majordomus_cli::capability::builtin::intents::IntentValidation;
let v = IntentValidation {
    valid: true,
    intents: 2,
    failures: 0,
    warnings: 20,
    findings: vec![],
};
// twenty warnings and no failure is a valid model
assert!(v.valid);
propertytyperequireddescription
valid boolean yes True when no finding is a failure. Warnings do not make it false.
intents integer (uint) yes How many intents were examined.
failures integer (uint) yes How many findings are failures.
warnings integer (uint) yes How many findings are warnings.
findings array of IntentFinding → IntentFinding yes Every finding.

Used by intents.validate

IntentView

object
One intent, as its record declares it and as the plan and the ledger derive it: the statement and invariants as authored, each milestone with its derived status, each criterion with the state of its evidence, and the stage that follows from both.

use majordomus_cli::intent::{IntentStage, IntentView};
let view = IntentView {
    id: "intent-lifecycle".into(),
    title: "Work is traceable to the intent it serves".into(),
    statement: "A reader can ask what work is for.".into(),
    invariants: vec!["no intent status is stored".into()],
    stage: IntentStage::Declared,
    milestones: vec![],
    satisfaction: vec![],
    met: 0,
    governance: vec!["adr:adr-0070".into()],
    non_goals: vec![],
    superseded_by: None,
    source: ".ai/repo/project/intents/intent-lifecycle.yaml".into(),
};
// a record naming no milestone that resolves has not been planned
assert_eq!(view.stage, IntentStage::Declared);
propertytyperequireddescription
id string yes The identity, which is also the file name.
title string yes One line.
statement string yes What must become true.
invariants array of string yes What must stay true.
stage IntentStage → IntentStage yes Derived: the stage.
milestones array of IntentMilestone → IntentMilestone yes The milestones, each with its derived status.
satisfaction array of IntentCriterion → IntentCriterion yes The criteria, each with its evidence state.
met integer (uint) yes Derived: how many criteria are met.
governance array of string yes The governance a worker on this intent loads.
non_goals array of string yes What is deliberately not required.
superseded_by string | null no The replacement, when the record names one.
source string yes Repository-relative path of the record.

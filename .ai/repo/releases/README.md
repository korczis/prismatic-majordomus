# Published releases

One file per release, `v<major>.<minor>.<patch>.yaml`, contract `release/v1`
(`share/schemas/release.schema.json`). A record says which tag was published, which commit
it was built from, and, for every target the distribution model declares supported, the
artifact's name, URL, SHA-256 digest and size.

## Who writes these

The release workflow, after the artifacts exist and have been verified, and nobody else. A
record is evidence, not a plan: it is written from what was actually uploaded, and a
release the pipeline did not record was not published. Editing one by hand to describe an
artifact that does not exist makes every projection below lie in the same way.

## What reads them

```text
site/static/releases/<tag>.json    the public, versioned release metadata the installer resolves
site/static/releases/latest.json   the stable pointer: the highest non-yanked stable record
```

Both are generated by `majordomus generate` and committed; `just derive-check` refuses a
tree in which they disagree with the records here. The installer never reads GitHub's API
or HTML — it reads those two files and the artifacts they name.

## The stable pointer

`latest.json` is derived, never authored: it is the record with the highest version among
those whose `channel` is `stable` and whose `yanked` is not true. Withdrawing a bad release
is therefore one edit — set `yanked: true` on its record and regenerate — and it neither
deletes artifacts anyone already has nor breaks an installation pinned to that exact tag.
A `prerelease` record is published and addressable by its tag, and is never resolved by an
unpinned installation.

## Invariants

- one record per tag, and the file name is the tag;
- `version` equals the crate's version at `commit`, and `tag` is `v` followed by it;
- every target the distribution model marks `supported` appears exactly once in
  `artifacts`, and nothing else appears: a partial release is not a release
  (`docs/DISTRIBUTION.md`, rule `project.distribution-canonical`).

The model those targets come from is `share/distribution.yaml`. Adding a target there and
regenerating is the whole procedure; this directory is never edited to keep up.

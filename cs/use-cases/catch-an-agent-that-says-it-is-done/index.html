Přichytit agenta, který tvrdí, že je hotov, a není

Jedna úloha od začátku do konce: pracovník vybočí ze svého rozsahu, tvrdí, že je hotov, předá a je přijat teprve tehdy, když projde vlastní ověření repozitáře.

○zaručeno Kontroly dokončení a kvalityzákladníagentoperátorzapisuje stav

Situace

Programovací agent dostane požadavek na jednu změnu. Změnu provede, upraví soubor, na který ho nikdo nežádal sáhnout, a ohlásí, že je hotov. Jiný agent už pracuje ve stejných cestách. Relace skončí dřív, než diff někdo přečte, a další relace začne tím, co si chat pamatoval. Každá z těchto věcí je běžná a žádná není problém modelu.

Co spouštíte

  • start: nárokuje cesty, kterých se úloha smí dotknout, a hlásí, že je už nárokuje jiný worker
  • check: odmítne dotčený soubor mimo nárokované cesty
  • finish: vyhodnotí kontrakt dokončení řádek po řádku a nezapíše nic, dokud některý řádek selhává
  • handover: zapíše do repozitáře stav, od kterého začíná další relace
  • context: vrátí dalšímu workerovi tento stav, bez konverzace, která ho vytvořila

Scénář

setup: challenge
given:
  - 'a repository with Majordomus installed, and a second worktree whose worker already claims lib'
  - 'a test, test/parse.sh, that passes only when the parser message names the column'
steps:
  - id: claim-the-work
    note: 'The task claims lib. Another worker already claims lib in a second worktree, and start says so before any file is touched.'
    run: ['start', 'refuse tabs in the parser', '--scope', 'lib']
    expect:
      exit: 0
      stdout_contains: ['^started t-', 'INFO overlap', 'claims lib']
  - id: the-worker-strays
    note: 'The worker makes the change it was asked for, and also edits a note under docs, which the task never claimed.'
    worker: 'echo "tabs are refused" >> lib/a && echo "parser notes" >> docs/d'
    expect:
      exit: 0
  - id: check-refuses-the-stray-file
    note: 'check names the file outside the claimed scope and exits non-zero. It is a failure, not a warning.'
    run: ['check']
    expect:
      exit: 10
      stdout_contains: ['FAIL scope', 'docs/d']
  - id: the-worker-says-it-is-done
    note: 'The worker reports the task finished. finish evaluates the contract instead of believing it, and refuses.'
    run: ['finish', '--outcome', 'completed', '--verify-command', 'sh test/parse.sh']
    expect:
      exit: 10
      stdout_contains: ['FAIL scope', 'FAIL verification', 'refused']
  - id: the-worker-reverts-the-stray-file
    note: 'The stray edit is taken back.'
    worker: 'git checkout -- docs/d'
    expect:
      exit: 0
  - id: hand-over
    note: 'The session ends. What the next one needs is written into the repository, not left in a transcript.'
    run: ['handover']
    stdin: challenge-handover.md
    expect:
      exit: 0
      files_exist: ['.ai/local/state/handovers']
  - id: the-next-session-resumes
    note: 'A new session asks the repository what it needs to know, and gets the task, its scope and the handover back.'
    run: ['context']
    expect:
      exit: 0
      stdout_contains: ['## TASK', 'LATEST COMPATIBLE HANDOVER', 'name the column']
  - id: finish-refuses-a-failing-verification
    note: 'Scope is clean now, but the repository''s own test still fails. finish runs it and refuses again.'
    run: ['finish', '--outcome', 'completed', '--verify-command', 'sh test/parse.sh']
    expect:
      exit: 10
      stdout_contains: ['OK +scope', 'FAIL verification', 'refused']
      stdout_not_contains: ['FAIL scope']
  - id: the-worker-finishes-the-work
    note: 'The worker does what the handover said was left.'
    worker: 'echo "the message names the column" >> lib/a'
    expect:
      exit: 0
  - id: finish-accepts
    note: 'Every line of the contract passes, so the outcome is recorded, with the verification that proved it.'
    run: ['finish', '--outcome', 'completed', '--verify-command', 'sh test/parse.sh']
    expect:
      exit: 0
      stdout_contains: ['OK +scope', 'OK +verification', 'completed']
      stdout_not_contains: ['FAIL']
then:
  - 'a file outside the claimed scope is refused by check and by finish'
  - 'a worker saying it is done is a claim finish evaluates, and a failing verification keeps it refused'
  - 'the next session resumes from what the repository recorded, not from the conversation'
  - 'the work is accepted only when every line of the contract passes'

Výsledek

Práce je přijata právě jednou, když projde vlastní test repozitáře a nic mimo nárokované cesty se nezměnilo. Dvě dřívější tvrzení, že je hotovo, byla odmítnuta s uvedeným důvodem a příkazem, který jej reprodukuje. Další relace začala z předávky, kterou repozitář držel, a druhý worker ve stejných cestách byl jmenován dřív, než se cokoli upravilo.

Proč to nástroj ví

Řetězec od této stránky ke kódu: případ užití jmenuje příkazy, pravidla a tvrzení; každé pravidlo se dispatchuje z registru a každé tvrzení jmenuje test, který ho dokazuje; scénář výše provedl příkazy. Nic v tomto řetězci není text o záměru.

  • majordomus startZahájit jednu úlohu s rozsahem pod profilem a odmítnout, dokud je aktivní jiná.
  • majordomus checkJe aktuální úloha stále konzistentní se svou politikou, rozsahem a tímto checkoutem?
  • majordomus finishVyhodnotí kontrakt dokončení a odmítne výsledek, pokud je jakýkoli jeho řádek nesplněn.
  • majordomus handoverZapíše append-only záznam pokračování a vyhledá nejrelevantnější předchozí.
  • majordomus contextCo potřebuje vědět další worker právě teď, v pořadí podle autority a v rámci rozpočtu.

Pravidla, díky nimž platí

  • ✕blokující Integrita rozsahuÚloha se dotkne jen cest, které uplatnila; práce nalezená jinde se nepřijímá jako hotová.
  • ✕blokující Konzistence stavuZáznam úlohy stále popisuje tento checkout — stejná branch a HEAD na zaznamenaném commitu nebo před ním.

Uplatněné záruky

  • ○zaručeno Úloha se spouští s deklarovaným rozsahem souborů a profilem a na checkout je aktivní jen jedna úloha
  • ○zaručeno Dotčený soubor mimo nárokovaný rozsah je selhání, nikoli varování
  • ○zaručeno Překryv mezi paralelními workery se počítá na nárokovaných cestách v obou směrech zahrnutí
  • ○zaručeno handover zapisuje záznam jen pro připojování s vypočtenou front matter a povinnými sekcemi
  • ○zaručeno finish vyhodnotí kontrakt dokončení řádek po řádku a odmítne, pokud některý řádek není splněn
  • ○zaručeno Výsledek je hodnota z uzavřeného slovníku, ne volný text

Související případy užití

Vypočteno z toho, co sdílejí: tvrzení, pravidla, příkazy, kategorie, aplikace. Tento seznam nikdo neudržuje.

  • Provozovat několik workerů v jednom repozitáři, aniž by se sraziliDejte každému workeru deklarovaný rozsah a zjistěte okamžitě, když dva z nich nárokují stejné cesty.
  • Předat práci s otevřenou otázkou a nechat ji blokovatUzavřít úlohu do předávky, dokud je otázka nevyřešená, spustit navazující úlohu a vidět, že tatáž otázka tam přijetí stále odmítá.
  • Rozhodnout, zda je dokončená práce skutečně dokončenáVyhodnoťte kontrakt řádek po řádku, místo abyste přijali větu, která tvrdí, že je práce hotová.
  • Zablokovat přijetí kvůli otázce, na kterou nikdo neodpovědělOtevřete k úloze otázku, sledujte, jak finish odmítá dokončení, dokud je nevyřešená, vyřešte ji odpovědí a teprve pak úlohu dokončete.
  • Dodávejte úkoly ve vlnách, které graf spočítá, a berte dalšíOvěřte plán, přečtěte si vlny provádění, které z grafu závislostí plynou, podívejte se, které úkoly jsou připravené a které na co čekají, a vezměte ten jeden úkol, který má worker dělat teď.

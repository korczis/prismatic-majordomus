When a server that no client owns is idle, and when it leaves (I4007).

A server serve ensure starts for a checkout carries an idle life: the declared server.idle_seconds: in .ai/repo/policy.yaml (900 when nothing is declared), passed to it as serve --idle. It is meant to end when nobody uses it. On 2026-10-22 fifteen of them had run for up to eight hours on one Mac with no peer attached, each holding a port, a lease and 60-450 MB, because the idle timer counted every HTTP request as use — and the machine’s servers talk to each other all the time. Every server on a machine hears the mesh’s multicast and links to the others (POST /api/v1/mesh/link/hello, .../sync), a board gather from any checkout reads every sibling’s board (GET /api/v1/peers? checkouts=this), and serve status, serve ensure and the gather probe every lease’s server (GET /). Fifteen servers kept each other alive.

Idle is decided here from state the server already holds, never from a guess:

  • no MCP session attached and no row on this checkout’s peer board;
  • no execution queued, starting, running or cancelling;
  • no live /events channel open;
  • no request from a client answered since the last look: a request another Majordomus process sends to keep the machine’s servers in touch (counts_as_use) is not one.

The lease is not part of the question. Every serve that is still running holds its own checkout’s lease — the election ends any other at once — and a server whose lease was taken over ends when its last session has been handed on (I2127). A server started without an idle life (plain serve, a hosted deployment, the server majordomus mcp hosts for its client’s stdio session) never idle-exits: its owner is whoever started it.

When the bound is reached the server logs why (IdleExit), runs its ordered stop — sessions and episodes closed, listeners closed, mesh drained, lease released — and serve returns 0. That is the server leaving on its own, which ADR 0200 permits; nothing here signals or kills another process.

The lifecycle, as the serve loop runs it once a second:

use std::time::{Duration, Instant};
use majordomus_cli::idle::{counts_as_use, Activity, IdleTimer};

let start = Instant::now();
let mut timer = IdleTimer::new(Duration::from_secs(3), start);
let at = |s| start + Duration::from_secs(s);
// every second another server's mesh sync arrives: it is not a client
let sync = counts_as_use("POST", "/api/v1/mesh/link/sync", false);
let look = Activity { client_request: sync, ..Activity::default() };
assert!(timer.observe(&look, at(1)).is_none());
assert!(timer.observe(&look, at(2)).is_none());
// three idle seconds: the server logs why, stops in order and exits 0
let why = timer.observe(&look, at(3)).unwrap();
assert!(why.to_string().contains("machine traffic"));

Why an idle server leaves: what the log line says.
IdleTimer
The idle clock of one server: reset by every look that finds it in use, and due when it has been idle for the whole bound. Deterministic: the caller passes the time.

Constants§

PROBE_HEADER
The header this executable’s own probes carry (lease::probe and every caller of it), so that a server tells “another Majordomus process asked whether I am here” apart from a person or a client reading its home page. A probe from an older executable lacks it and still counts as use, which errs on the side of keeping a server.

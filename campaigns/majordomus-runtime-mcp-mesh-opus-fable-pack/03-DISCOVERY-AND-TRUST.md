# M03: Mesh auto-discovery with security preserved

Reuse `apps/majordomus-cli/src/mesh/` and ADR 0050/0067, existing discovery envelopes, Ed25519 node keys, per-repo runtime ID and signed hello/welcome. Audit multicast, broadcast, rendezvous, explicit seeds, localhost/worktree association, interface binding, IPv4/IPv6, Docker/VPN/tailnet, partial network and NAT limitations. Auto-discover eligible local runtime peers out of the box; make network mesh easy to opt into with a declarative policy and a guided safe enrollment UI/CLI. Preserve deny_unknown default and require explicit authorization for unfamiliar remote peers. No secret material in discovery. Document why automatic peer appearance does NOT mean automatic trust or execution rights.

Ensure all discovery providers emit one canonical bounded candidate event into one registry; no provider-specific admission shortcuts. Add retry/backoff+jitter, rate/capacity bounds, de-dup, TTL, identity rotation/revocation, version/capability negotiation, replay and malformed frames, clock skew diagnostics, endpoint health and staleness; no unbounded scans. Defend against amplification, signed-event replay, self-link, downgrade, unknown key, wrong repo and address substitution. Verify any non-loopback write-capable endpoint has authentication and appropriate confidentiality; do not claim plain HTTP supplies TLS. Security state should be projected to UI/MCP/CLI.

Tests: independent ephemeral 2-3 nodes, same user multiple worktrees, unrelated repo never joins, malicious peer, trust revoke, key rotation, packet duplicate/loss/reorder, clock skew, unknown-version negotiation, network disabled, multi-NIC and loopback. Gate: zero accidental remote trust or cross-repository leakage; local healthy path automatic; remote enrollment obvious and safe.

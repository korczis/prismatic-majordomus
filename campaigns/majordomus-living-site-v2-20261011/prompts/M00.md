# M00 · Reality audit and page inventory

## Mandatory operating contract
Operate in `korczis/prismatic-majordomus` after inspecting current branch, `.ai/**`, governance, ADRs, generator and CI before modifying. Implement using existing canonical project model (intent -> milestone -> issue -> evidence), capability registry, site projection, mesh, `prs` integration and CI. Do not create parallel registries, orchestration, route catalogs, duplicated JSON schemas or loose shell scripts. Reconcile proposed work against existing issues/PRs, re-use IDs and record decisions. Keep changes small enough to merge and release continuously. Any missing access is an evidence-backed BLOCKED state, never a fabricated success. No disabling required security checks, no arbitrary workflow permission expansion, no publishing credentials, and no unsupported marketing claims. Continue without routine conversational prompts within authorized scope; checkpoint after every stable increment.

## Issue-level acceptance template
For EVERY issue: specify owner milestone and canonical ID, dependencies, affected paths (discovered, not guessed), expected behavior and negative test, baseline, linked execution/evidence, docs consumers, CI gates, PR and release eligibility, deployed proof URL/SHA and rollback. Track state as `PLANNED -> READY -> ACTIVE -> VERIFY -> DONE` using project-native stages; do not maintain a second tracking authority.

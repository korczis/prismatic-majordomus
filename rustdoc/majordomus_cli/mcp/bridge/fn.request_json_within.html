One HTTP/1.1 request whose reply is a JSON document held at most at bound.bytes and read whole within bound.within: what a dialer asks of a peer it does not control.

The body is held without the whitespace JSON allows between tokens, which makes the bound the size of the document rather than of its formatting: the shared server pretty-prints every answer, and a peer that pads one costs time — bounded by within — never memory. The bound counts what is held, so the first reply refused is the one a byte over it, however it was formatted. The head is bounded too, at MAX_HEAD_BYTES. A body that is not JSON loses its spaces: a caller that reads more than the status of a non-JSON answer uses request.

use std::time::Duration;
use majordomus_cli::mcp::bridge::{request_json_within, ReplyBound, ReplyRefused};

let bound = ReplyBound {
    bytes: 1024,
    idle: Duration::from_secs(1),
    within: Duration::from_secs(2),
};
// port 9 discards: nothing answers there, which is a failure to connect, not a refusal
let error = request_json_within("http://127.0.0.1:9", "GET", "/", &[], None, bound)
    .unwrap_err();
assert_eq!(ReplyRefused::of(&error), None);

Vykresleno z docs/MCP.md — stejného Markdownu, který ukazuje GitHub.

Co spustitelný soubor v Rustu pod apps/majordomus-cli/ poskytuje klientovi MCP, odkud to pochází a co odmítá. Chování tak, jak je implementováno a testováno; kde se implementace a tento dokument rozcházejí, je chybný dokument a mění se ve stejném commitu jako oprava. Vývojářský detail (architektura, každá volba, schéma druhu) je ve vlastním README.md aplikace.

Co to je

Proces, který klient spouští a který mluví Model Context Protocolem na svém stdin a stdout, obsluhuje AI vrstvu repozitáře (čtení a pojmenované příkazy, které mění stav) a připojuje se k jedinému sdílenému serveru repozitáře: první takový proces v repozitáři naváže loopback HTTP projekci vedle své stdio relace (domovská stránka s výpisem všech povrchů, dokumentace tohoto repozitáře, Swagger UI, dokument OpenAPI, každá routa schopnosti, MCP přes HTTP) a oznámí kde; každý další se k ní připojí.

cargo build --manifest-path apps/majordomus-cli/Cargo.toml
apps/majordomus-cli/target/debug/majordomus mcp --inspect    # what would be served, and every diagnostic
apps/majordomus-cli/target/debug/majordomus mcp              # serve until the client goes; the first one is the server
apps/majordomus-cli/target/debug/majordomus mcp --standalone # this client alone: no port, no lease, no peers
bin/majordomus-mcp                                           # the same, built first when needed: what a client configuration names

Log na stderr to pojmenuje v okamžiku, kdy server běží:

shared server listening on http://127.0.0.1:8741 — 7 surface(s): api http://127.0.0.1:8741/api/v1, cockpit http://127.0.0.1:8741/cockpit, docs http://127.0.0.1:8741/docs, home http://127.0.0.1:8741/, mcp http://127.0.0.1:8741/mcp, openapi http://127.0.0.1:8741/openapi.json, swagger http://127.0.0.1:8741/swagger; the one server of this checkout ...

Není to démon: nic jej nespouští kromě klienta, nic jej nedrží naživu kromě klientů a končí, když zmizí jeho vlastní klient a odejde poslední připojený. Nedrží žádný stav kromě paměti, nepotřebuje databázi a zapisuje jeden soubor: lease pod .ai/local/state/mcp/, lokální polovinou checkoutu, kterou vrstva vyhrazuje pro provozní stav, odstraněný při zastavení serveru. Je to jedna projekce registru schopností spustitelného souboru (CAPABILITIES.md): stejné schopnosti jsou trasy HTTP a příkazy capabilities a každý nástroj a zdroj zde je odvozen ze záznamu registru, žádný není deklarován v kódu MCP. Rozhodnutí je .ai/repo/adrs/0003-shared-mcp-server-peers-and-client-autostart.md.

Zpráva, která se potkala se selháním, se pošle znovu, jen když server prokazatelně neběžel — spojení nikdy nevzniklo nebo server odpověděl 404 (relace ztracena) či 409 (lease ztraceno) — nebo když je idempotentní: každá metoda kromě tools/call a nástroj, jehož deklarované nápovědy provádění to říkají (každé čtení). Jeden repozitář, každý jeho server

Server obsluhuje checkout. Propojený worktree je vlastní checkout — má manifest, takže má kořen, lease i vlastní server — a do ADR 0035 nic neříkalo, že dva takové servery patří jednomu repozitáři. Nyní indexová trasa (GET /) jmenuje vedle identity samotného checkoutu i git repozitář, ke kterému checkout patří: commit je commit, ze kterého byl odpovídající spustitelný soubor sestaven, celý nebo unknown, a dirty zda jeho strom nesl necommitnuté změny (null, když to sestavení nevědělo) — stejná dvě pole odpovídají GET /api/v1/live a GET /api/v1/ready; stale je null, dokud je spustitelný soubor, ze kterého byl proces načten, stále souborem na disku, a říká proč, jakmile ho přestavba nahradila nebo odstranila — proces pak obsluhuje kód, který už neexistuje, a GET /api/v1/ready odpovídá ready: false se stejným důvodem (I1502); repository_id je checkoutu (otisk jeho kořene, s čím lease sonda porovnává), git_repository_id je repozitáře (otisk adresáře gitu, který sdílí každý worktree; chybí tam, kde se git nedá zeptat), linked_worktree říká, zda jde o primární checkout, a leaseholder říká, zda odpovídající proces je stále tentýž (níže). branch a head jsou větev a commit, z nichž byly obsluhované odpovědi čteny, jak je četl index (I1031). Domovská stránka a shell Swaggeru na /swagger nesou stejnou identitu na jednom řádku vedle svého obsahu; nic z toho není cesta, protože kdo dosáhne socketu, se dozví, který checkout odpověděl, a nikdy kde leží. GET /api/v1/server — nástroj majordomus_server, zdroj majordomus://server — vypisuje každý checkout, který git pro repozitář eviduje, primární první, každý s jeho leasem, stavem jeho serveru a počtem peerů, které drží, a říká, kde stojí server tohoto checkoutu měřeno proti tomu, co by obsluhoval tento spustitelný soubor:

postavenívýznam
absentžádný lease: tento checkout nic neobsluhuje
startingpronájem bez adresy, dost mladý na to, aby ho jeho vlastník ještě navazoval
readyserver, který lease jmenuje, odpovídá za tento checkout, ze souboru na disku, ve verzi tohoto spustitelného souboru
outdatedodpovídá, ale z jiné verze, nebo ze souboru nahrazeného od jeho startu: vše, co říká, je včerejší
stalelease jmenuje server, který neodpovídá, nebo vůbec není leasem; důvod říká které

Seznam je to, co volající dostane, když se na nic neptá, a stojí čtení lease a sondu na checkout — na počítači se sty registrovaných worktree sto od každého. Volající, který chce vědět jen o checkoutu, ve kterém je, to řekne — checkouts=this v query stringu, ve vstupu nástroje nebo --checkouts this na příkazové řádce — a toto čtení nevyčísluje žádný jiný checkout, nečte žádný jiný lease a nesonduje žádný jiný server. Výchozí je celý seznam, protože to je odpověď, kterou tato schopnost dávala dříve, než pole existovalo.

Lease samotný je jeden typ, čtený jednou (lease::LeaseDocument, lease::LeaseFile::read): volba, serving jen pro čtení, snímek prostředí a stav ho všechny parsují stejným čtením a nese version serveru vedle spustitelného souboru, z něhož byl spuštěn. .ai/local/state/mcp/server.json je stále místem, kde ho člověk čte pomocí cat; stav je místem, kde ho čte program.

Server, který už není tím serverem

Lease lze převzít, i když proces, který ho držel, stále běží a je zdravý — protože jeho spustitelný soubor byl nahrazen rebuildem, což volba čte jako „servíruje kód, který už není na disku“, nebo protože je to starší release než volící klient. Instalátor ukládá každý release do vlastního adresáře, takže upgrade mění cestu spustitelného souboru a kontrola rebuildu to nikdy nevidí; kontrola releasu ano. Rozhoduje jediný verdikt (lease::version_verdict) pro volbu, serve ensure i server.status, řadící releasy podle precedence sémantického verzování definované release::version::Version, takže server na 1.0.0-alpha.1 je novější než 0.29.0 a starší než 1.0.0-alpha.2 a 1.0.0:

release serveru jeklient tohoto spustitelného souboru
totéžpřipojuje
staršípřebírá lease; starší server předá své relace dál, jak je uvedeno níže
novějšíse připojí a jeho odpověď initialize nejprve říká, že tento klient je starší
nepublikováno, nebo neřazeno jako release (není to sémantická verze, například lokální tag sestavení)připojí se; server.status hlásí outdated

Starší klient nikdy nepřevezme novější server, takže dva releasy vedle sebe nebojují o lease: drží ho novější (I2163). Nahrazený proces se nezabíjí. Drží svůj socket, svou nástěnku peerů a generaci vrstvy, kterou načetl, a obsluhuje relace, které už měl, dokud neskončí. Je to záměrné: klient uprostřed odpovědi nemá přijít o svůj server proto, že někdo spustil cargo build.

Co nesmí dělat, je dál být tím serverem. Od okamžiku, kdy jeho vlastní čtečka zjistí, že lease už nenese jeho token:
říká to jeho indexGET / odpovídá leaseholder: false; každé další pole — repository, repository_id, git_repository_id — je o něm stejně pravdivé jako o aktuálním serveru, což je přesně důvod, proč je třeba je jedním polem oddělit
sonda jej odmítnelease::probe klade tři otázky, ne dvě: server Majordomus, tento checkout, stále držitel leasu. Klient s adresou z doby před převzetím se dozví, že tam žádný server není, místo aby dostal nástěnku, kterou nikdo jiný nevidí
nepřebírá nikoho novéhoinitialize bez relace dostane 409 lease_lost a odkaz na spouštěč jako cestu k aktuálnímu serveru
opouští meshobjevování a kooperace se zastaví; tento checkout reprezentuje jen nástupce, takže vyřazený proces nemůže dál nahrazovat své ověřené odkazy
jeho otevřené relace se předají dálodpovídá se jim po deklarovanou lhůtu zaneprázdnění (server.busy_grace_seconds), takže rozpracovaný požadavek a ty za ním skončí tam, kde začaly; poté je každá relace uzavřena a dostane 404, most klienta otevře novou, je odmítnut s 409 lease_lost a zvolí aktuální server; když nezbude žádná relace, nahrazený proces skončí (I2127)

tests/mesh_lease_retirement.rs dokazuje převzetí se skutečnými servery: vyřazený proces stále odpovídá svému připojenému klientovi MCP, přestane se účastnit meshe a nástupce se synchronizuje se vzdáleným runtime bez opakovaných opětovných připojení.

Server příliš starý na to, aby odpověděl na třetí otázku, sonda přijme. Na tom endpointu jej nelze odlišit od aktuálního a jeho odmítnutí by bylo horším selháním: živý server považovaný za mrtvý se převezme, a tak se stane, že jeden checkout má dva.

Bylo to změřeno dřív, než to bylo napsáno: 2026-09-10 měl tento repozitář dva servery, jeden lease, a relace, jejíž prostředí nesla starší adresu, četla nástěnku peerů s jedním peerem, zatímco nástěnka, kterou sdíleli všichni ostatní, měla dva.

Čtyři významy slova „připraveno“

Tento spustitelný soubor odpovídá „ready“ čtyřikrát a audit, který podnítil ADR 0035, počítal tři z nich za nehodu (docs/ENTRY_AUDIT.md, příčina 5). Nejsou to jedna otázka špatně rozdělená: jsou to čtyři otázky o čtyřech subjektech a sloučení kterýchkoli dvou by ztratilo to jediné, co ten čtenář potřebuje. Každá je zde pojmenována se svým vlastníkem, aby další čtenář nemusel znovu objevovat, na kterou se dívá.

Zajištění serveru a jeho zastavení

majordomus serve status [--checkouts this|repository] [--format json]
                                            where this checkout's server stands, and every server of the repository
majordomus serve ensure [--idle S] [--wait S] [--port P]
                                            a ready server for this checkout, started if it must be
majordomus serve stop [--wait S]            end the server this checkout's lease names

serve ensure přečte lease a vyzkouší server, který jmenuje, přesně jako volba, a konverguje: ready se vytiskne a nic se nespustí; na starting se čeká; absent a stale spustí server jako vlastní proces — tento spustitelný soubor, serve --fallback --idle S, jeho log na .ai/local/state/mcp/server.log, ve vlastní skupině procesů, aby přežil shell, který o něj požádal — a čekají, až je připraven; outdated spustí server jen tehdy, když by volba lease převzala (tentýž spustitelný soubor, vyměněný na disku, nebo starší release než tento spustitelný soubor) a jinak se hlásí s nápravou, protože server jiného buildu, který odpovídá, tento příkaz nekončí. Spuštěno dvakrát nespustí podruhé nic; spuštěno třemi shelly najednou nechá volba jeden ze tří serverů navázat a ostatní ustoupí. Volání je omezeno --wait; server, který se včas nepřipravil, se hlásí se stavem, jehož dosáhl, a exit kódem 10.

Server, který ensure spustí, nemá vlastního klienta. Skončí, když ho --idle sekund (ve výchozím stavu patnáct minut) nic nepoužilo — není připojena žádná relace MCP, nebyl zodpovězen žádný požadavek HTTP a není otevřen žádný živý kanál /events, takže člověk, který čte Cockpit nebo volá REST API, si server, který používá, ponechá (I2131) — což zachovává linii ADR 0003 — žádný proces bez klienta — platnou v čase, ne v každém okamžiku: vstup agenta má server dlužen před prvním připojením a checkout, ve kterém nikdo nepracuje, žádný nedrží.

serve stop pošle signál serveru, který jmenuje lease, pokud tento server odpovídá za tento checkout, a čeká, až lease toho serveru zmizí — dokument, který přečetl, podle jeho tokenu, nejen cesta — a pak až proces skončí. SIGTERM, který pošle, je uspořádané zastavení, ne kill: server dá připojeným peerům dvě sekundy na odchod, zavře jejich relace a epizody, které nesly, zavře své listenery (rozpracovaná odpověď se dokončí první), uvolní svůj lease a vyprázdní mesh. Soubor odstraní jen proces, jehož token soubor stále nese: každé odstranění a každé přepsání lease ho znovu čte pod zámkem vedle něj (.ai/local/state/mcp/server.lock), takže server zastavený těsně poté, co byl jeho lease převzat, nechá lease svého nástupce na pokoji. serve pak skončí s exit 0 vlastním návratem; zastavení, které nedoběhne do osmi sekund, nebo druhý SIGTERM ho přesto ukončí. serve ensure stále čekající ve volbě převezme uvolněnou cestu během milisekund, takže čekání na cestu by hlásilo server, který se nezastavil, ačkoli už se zastavil; převzetí se místo toho pojmenuje v odpovědi. Lease, který jmenuje server jiného checkoutu, nebo takový, který neodpovídá, se ponechá na pokoji a řekne se to; nic zde nezabíjí proces, který nebyl vyžádán jménem.

Kdo volá ensure. Volá ho startovní událost providera (session.ensure_server_on_start v politice, ve výchozím stavu zapnuto): jediný okamžik, kdy je dlužen server, který ještě nikdo nespustil, je příchod agenta, a briefing, který událost zapíše, nese jeden řádek — Shared server: ready http://127.0.0.1:8741 pid 123 — aby pracovník věděl už před prvním voláním nástroje, zda nástěnka, kterou má číst, existuje. Událost nikdy nesestavuje spustitelný soubor: chybějící nebo starší než jeho zdroje se v tom řádku pojmenuje a nechá být, protože hook není místo pro spouštění kompilátoru a server ze zastaralého kódu by odpovídal stromem ze včerejška. Launcher klienta MCP (bin/majordomus-mcp) konverguje vždy stejně přes volbu; shell vstupující do repozitáře (.envrc) je informován a není obsloužen, protože project.envrc-is-an-adapter zakazuje vstupnímu hooku cokoli spouštět a shell není klient.

Oznámení přežije server, kterému bylo učiněno. Most vidí každý rámec, který jeho klient pošle, takže si drží argumenty posledního oznámení, které server přijal, a řekne je znovu, kamkoli klient dopadne dál: po opětovném připojení, jakmile je relace znovu otevřena; po převzetí na nástěnku serveru, kterým se stal vlastní proces mostu. Worker, který oznámil jednou, je na nástěnce každého serveru, který ho obsluhuje, aniž by musel oznamovat znovu; pokyn oznámit znovu po opětovném připojení zůstává v bootstrapu pro jediný případ, který most nepokryje: klient, jehož vlastní proces je serverem a restartuje se.

Před čím volba nyní chrání. Vlastník udržuje své lease mladé, zatímco se vrstva načítá (Lease::keep_alive), takže studený start pomalejší než odklad vazby se nikdy nepovažuje za opuštěný; převzetí odstraní jen soubor, který posoudilo, nikdy ten, který mezitím dorazil, a dva voliči, kteří posoudili jedno lease jako zastaralé, skončí s právě jedním lease, protože každý před odstraněním znovu přečte soubor pod zámkem vedle něj; vlastník, jehož lease bylo převzato během vazby, odmítne publikovat a degraduje, místo aby přepsal adresu vítěze, a publikuje přes vlastní dočasný soubor, synchronizovaný před přejmenováním; a server, jehož lease je později převzato, je přestane nárokovat — nic, co dělá při odchodu, se nedotkne souboru, který patří někomu jinému — po dobu odkladu zaneprázdněnosti obsluhuje peery, které má, každého z nich předá aktuálnímu serveru a skončí. Čtečka samotného serveru také zapomíná relace HTTP, které přestaly pingovat, na každé cestě, a ne jen když vlastník čeká na odchod peerů, takže mrtvý peer nikdy nezůstane attached na nástěnce.

Rozhraní pojmenovává stroj

Lokální server se váže na loopback. Tato výchozí hodnota se nehýbe: vrstva, její diagnostika, její peeři a dva nástroje, které odpovídají o .ai/local/, nejsou pro každého hostitele v síti, ve které se notebook zrovna nachází.

Jeden stroj může chtít být dosažitelný — druhý stroj se připojující přes LAN, peer meshe vytáčející se dovnitř, telefon otevírající Cockpit — a do 0.14 byl jediný způsob, jak to říct, majordomus serve --host 0.0.0.0, psané ručně. To trvalo přesně tak dlouho jako proces: serve ensure, což spouští start relace a vstup do shellu, spouští server vůbec bez hostitele, takže příští zastavení z nečinnosti nebo příští relace vrátily checkout na loopback bez jediného slova a serve status celou dobu hlásilo desired 127.0.0.1.

Rozhraní se tedy čte z jednoho místa, které dědí každý starter:

Z toho, že je to proměnná a ne nastavení, plynou čtyři věci:

  • Patří stroji, nikdy repozitáři. Nic sledovaného ho nemůže nastavit. Klíč v .ai/repo/policy.yaml by způsobil, že by každý klon veřejného repozitáře naslouchal v jakékoli síti, ve které se probudí.
  • Příkazová řádka vyhrává, prázdná hodnota není hodnota a hodnota, kterou nelze nikam navázat, odmítne start a pojmenuje adresu.
  • Varování platí. Vazba zvolená proměnnou stále loguje, že každý hostitel dosahující na rozhraní může číst vrstvu; řádek logu před ním říká, že adresu pojmenovala proměnná, takže vazba není nikdy nevysledovatelná. Jen objekt deploymentu deklaruje expozici a jen deklarovaná je tichá.
  • server.status odpovídá za prostředí, ve kterém se ptá. desired.host je to, co by server spuštěný z toho prostředí navázal, takže adresa, kterou server naváže, a adresa, kterou stav nazývá žádoucí, jsou jedno rozlišení (cli::resolve_http_host) a nemohou se rozcházet. Běžící server odpovídá serve status a odpovídá za prostředí, v němž byl spuštěn.

Nastavte to tam, kde to uvidí každý, kdo cokoli spouští — ve vlastním startovacím souboru shellu (~/.zshenv, ~/.profile). .envrc.local je pro jednoho z nich příliš pozdě: .envrc vyhodnotí majordomus-env enter, což zajistí server, dříve než načte .envrc.local, takže server, který spustí první cd, by proměnnou neměl, zatímco vše spuštěné z toho shellu poté by ji mělo.

Už běžící server si ponechá adresu, na kterou se navázal. Po nastavení proměnné majordomus serve stop a příští serve ensure — nebo příští relace — ho zvedne na pojmenovaném rozhraní.

Na tomto povrchu nejsou žádné účty ani tokeny, takže požadavek se posuzuje podle toho, odkud přišel (ADR 0126). Navázání mimo loopback poskytne každému dosažitelnému hostiteli povrch pro čtení a nic víc: požadavek z adresy, která není loopback, spustí schopnost jen tehdy, když schopnost čte (effect: read) nebo když je jejím vstupem podepsaná zpráva, kterou handler ověří proti politice důvěry — link.hello, link.sync a register meshe. Každá jiná trasa a každý nástroj MCP, který něco mění, odpoví volajícímu forbidden (HTTP 403) dříve, než se spustí jeho handler, včetně executions.start, který by jinak spustil libovolnou schopnost. Rozhodnutí se činí na každý požadavek, ne na relaci: id relace MCP je jméno, nikoli důkaz. Čtení se stále poskytuje celé síti, nešifrovaně; chcete-li zapisovat z jiného počítače, připojte se k loopback serveru přes SSH tunel (ssh -L 8741:127.0.0.1:8741 <machine>), jehož požadavky přicházejí z loopbacku.

Požadavek z loopbacku musí tento server pojmenovat adresou nebo localhost: požadavek, který jmenuje jiného hostitele, se odmítne forbidden dřív, než odpoví kterýkoli povrch, včetně čtení, protože přesně to posílá stránka, jejíž doména byla přinucena překládat na tento stroj (DNS rebinding). Požadavek z jiného hostitele smí stroj pojmenovat tak, jak jej zná. /swagger se servíruje s Content-Security-Policy, která připouští jen jeho připnuté soubory z CDN, jejichž integritní hashe stránka jmenuje, a jeho jediný inline skript.

Čím se spor posuzuje

O tom, který proces vlastní lease, rozhodují čtyři čísla a pátým zůstává vlastník schopen odpovídat. Jsou deklarována v bloku server: souboru .ai/repo/policy.yaml a čtou se jednou při otevření repozitáře: mcp i serve je čtou před první volbou, takže hodnoty níže jsou ty, které používá každá volba v procesu (I2129); dříve byla hodnota přečtená před politikou po celý život procesu zkompilovaným výchozím.

klíčo čem rozhoduje
probe_timeout_secondsjak dlouho sonda čeká, až současný vlastník odpoví, než se toto ticho počítá jako důkaz. Příliš málo a živý, ale pomalý vlastník je posouzen jako zastaralý a převzat zatímco ještě obsluhuje; příliš mnoho a zaseknutý drží server checkoutu tak dlouho
bind_grace_secondsjak dlouho se lease, který zatím nejmenuje žádnou URL, nechá být — server zapíše svůj lease dřív, než může obsluhovat, takže čerstvý lease bez URL je vlastník, který startuje, ne mrtvý
join_timeout_secondsjak dlouho proces čeká na připojení k souboru leasu nebo jeho vytvoření, než odmítne, místo aby čekal věčně
busy_grace_secondsjak dlouho se čeká na živého vlastníka, který neodpovídá, a ptá se ho znovu, než se jeho lease převezme. Volba dává zaneprázdněnému vlastníkovi tuto dobu a stejně tak serve ensure, než cokoli zahájí: sonda, která vyprší proti živému procesu, není mrtvý server, ale ten, který mlčí tak dlouho, je zaseknutý a nahradí se. Server, který ensure spustil po vyčkání této lhůty, je informován, který lease posoudil, takže jeho volba na něj nečeká podruhé
read_deadline_secondsjak dlouho server nechá spojení bez plně přečteného požadavku — čekání na hlavičku, udržování mezi požadavky nebo čtení těla — než spojení zavře. Klient posílající jeden bajt za sekundu by jinak držel vlákno požadavku navždy a dost takových klientů by nechalo výše uvedenou sondu bez odpovědi. Spojení, na jehož požadavek se odpovídá, nebo které bylo povýšeno na živý kanál, se tím nikdy nezavře. Každé zavření se počítá v server.status (connections.closed_by_deadline), vedle požadavků odmítnutých 503, protože všech 64 handlerů požadavků bylo zaneprázdněno (connections.refused_busy); sonda GET / se zodpoví i tehdy. Knihovna HTTP drží vlákno na každém spojení, dokud žije, a může zařadit do fronty spojení, které přijde ve vlně, dokud se nějaké neuvolní; termín je také tím, co omezuje toto čekání (I2156)
idle_secondsjak dlouho server spuštěný pro checkout, který nevlastní žádný klient — příkazem serve ensure nebo shellem vstupujícím do checkoutu — přežije svého posledního peera, než se sám zastaví; 900, pokud není deklarováno. --idle na příkazové řádce to přepíše. Server spuštěný ručně pouhým serve a bez --idle běží, dokud není zastaven, jako dříve: jeho vlastníkem je ten, kdo jej spustil (I2701)

Klient nečeká na build. mcp je jediný příkaz, který klient spustí a pak na něj čeká, a klient, který nedostane handshake, hlásí server jako selhavší a pokračuje bez něj. Takže když tento checkout nemá spustitelný soubor ke spuštění, nebo takový, který nemůže přebuildovat — není cargo, je méně volného místa než práh buildu (MAJORDOMUS_MIN_FREE_MB, výchozí 5120), build selhal — bin/majordomus-mcp místo toho spustí nainstalovaný release (MAJORDOMUS_INSTALLED_BIN, výchozí majordomus v ~/.local/bin, kam jej dává install.sh) a na stderr řekne, který release a proč. Zastaralý spustitelný soubor, který lze přebuildovat, se přebuilduje jako dříve, MAJORDOMUS_MCP_BUILD=1 způsobí, že mcp builduje jako každý jiný příkaz, a každý jiný příkaz stále končí s exit 12, když nemá co spustit: záložní řešení je pro klienta, který by jinak byl odmítnut, nikdy způsob, jak nehlášeně spustit jiný release. Soubor uvnitř repozitáře se nikdy nebere za nainstalovaný release, ani takový, který neodpovídá na --version. ADR 0172; případ je test/cases/3177_a_client_always_gets_a_server.sh.

just mcp, just serve a just inspect v kořeni dělají totéž pro člověka; just docs-ui otevře Swagger UI běžícího serveru. Tentýž dokument, s tagy, příklady a stavy, je referencí API na webu na /docs/api/ a servíruje se surový na /openapi.json webu; instrukce initialize, OpenAPI info a GET / se otevírají jedním shrnutím z about.rs (CAPABILITIES.md).

  • Sign the extension in to the claude.ai organization that /status names in Claude Code. Claude Code needs a claude.ai login (Pro, Max, Team, Enterprise); an API key or a setup-token keeps the bridge off.
  • The first enable writes the native messaging host — on macOS ~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.anthropic.claude_code_browser_extension.json, which runs claude --chrome-native-host — and Chrome finds it after a restart.

Every browser action still passes the extension's own per-site permissions; a rule in .claude/settings.json does not lift them, and this repository pre-approves no browser tool.

When it does not connect — list_connected_browsers answers an empty list, or a browser tool says "Browser extension is not connected":

  1. The extension is not running, or it is signed in to another account or organization than /status names. Sign it in again with that organization.
  2. /chrome → Reconnect extension, then restart Chrome and Claude Code.
  3. An organization IP allowlist that blocks bridge.claudeusercontent.com blocks the bridge (Claude Code documentation, code.claude.com/docs/en/network-config).
  4. A JavaScript dialog open in a controlled tab stops every later browser event until a person dismisses it.

The mesh half is diagnosed as always, from the same session: majordomus mesh doctor, and majordomus_peers for the board.

Každá relace je peer: vlastní stdio klient serveru, každý přemostěný majordomus mcp a každý klient mluvící přímo /mcp. Nástěnka patří repozitáři (ADR 0044)

Server servíruje checkout, takže repozitář, na němž se pracuje přes linked worktree, má jednu nástěnku na worktree — a až do ADR 0044 odpovídal peers.list jednou z nich, zatímco bootstrap v CLAUDE.md a AGENTS.md říkal každému workeru, že viděl repozitář. Změřeno 2026-09-11: sedm živých serverů, jeden git_repository_id, sedm nástěnek, devět agentů napříč šedesáti worktree, z nichž každý četl nástěnku, která držela jen jeho.

peers.list nyní sbírá. Vyjmenuje checkouty, které git registruje, a přečte zápůjčku každého — týmiž čtečkami, jaké používá server.status — vlastní nástěnku vezme z paměti tohoto procesu a každého dalšího checkoutu, jehož server odpovídá, se zeptá na jeho vlastní nástěnku samotnou (checkouts=this). Ten parametr drží sběr hluboký jeden skok: server dotázaný na this nevyjmenovává žádný checkout a nezkouší žádný server, takže se nikdy nemůže zeptat zpět. Bez něj není žádné opakování, protože server příliš starý na to, aby parametr znal, by odpověděl celou svou nástěnkou a cyklus je jediné selhání, které to mít nesmí; takový checkout se místo toho hlásí jako nepřečtený s důvodem.

Id peera je pozice na jedné nástěnce, přidělená v pořadí připojení a po opětovném připojení přidělená znovu — relace, která byla dnes ráno p3, je p1, jakmile se její most znovu připojí. Nic podle něj nesmí korelovat pracovníka v čase; checkout, který peer nese, je trvalá polovina jeho identity. Oznámení rovněž patří spojení: most zopakuje poslední oznámení svého klienta po opětovném připojení nebo převzetí a pracovník, jehož proces mostu je nahrazen, oznamuje znovu.

Stojí jedno čtení lease na registrovaný checkout, jednu sondu na checkout, jehož lease pojmenovává adresu, a jeden round trip na server, který odpoví. V tomto repozitáři 2026-09-11 — 118 registrovaných checkoutů, 7 živých serverů — trvalo vyčíslení a sondování, které server.status už provádí, 3,0 s wall.

Claim se zodpovídá, nejen zaznamenává. peers.announce porovná rozsah, který dostane, se všemi ostatními oznámeními a vrátí peery, jejichž claimy se s ním setkávají, s dvojicemi cest, které se setkávají: dva claimy se setkávají, když jsou stejné nebo je jeden uvnitř druhého (apps obsahuje apps/majordomus-cli; app ne, protože claim je cesta, ne prefix řetězce). peers.list hlásí tytéž kolize napříč celou nástěnkou, každou dvojici jednou. Stále to není vynucování, ani check --overlap shellového nástroje, které hlásí rozsahy úloh jiných worktree a končí s 0. Odmítá rozsah vlastní úlohy z start --scope, při check, při finish a v hooku pre-push — ale kolize je nyní známa v okamžiku svého vzniku, a ne objevena později v historii větve.

Nástěnka dosáhne i na workera, který o ni nikdy nepožádá. Čtení bylo dobrovolné a dobrovolná spolupráce selhala: relace se ohlásila, její transport se obnovil pod novým id peera a osm dalších ji tři hodiny nevidělo; dvě relace postavily týž subsystém, protože se ani jedna nepodívala. Proto majordomus context — příkaz, který bootstrap nařizuje každému workerovi spustit před prací — nese sekci PEERS mezi GIT a TASK: kdo další je připojen, co si každý z nich nárokuje a konkrétně které z těch nároků se dotýkají rozsahu aktuální úlohy. Čte lease sdíleného serveru (který je vázán na repozitář, takže jej linked worktree najde přes --git-common-dir v primárním checkoutu) a ptá se GET /api/v1/peers. Nápověda nikdy nenese zátěž: bez lease, bez jq či curl, se serverem, který neodpoví do dvou sekund, nebo s nástěnkou, na které nikdo není, zůstane context přesně takový, jaký byl, protože repozitář s jediným workerem nesmí dostat sekci o tom, že je sám. test/cases/106_context_peers.sh to celé drží.

Oznámení přežije spojení, které ho učinilo. Relace, která se znovu připojila, dřív mlčky ztratila vše, co řekla, sama sobě i všem ostatním; nástěnka nyní drží oznámení odešlého peera a vypisuje ho s attached: false, takže to, na čem relace řekla, že pracuje, přežije přerušený socket. Peer, který nikdy neoznámil, nezanechá nic, uchovává se nejnovějších 32 odešlých peerů, aby server, který běžel celý den, nebyl muzeum, a připojený peer se nikdy nevyhodí, aby se uvolnilo místo pro toho, kdo odešel. count z peers.list jsou skutečně připojení peeři; pole peers je delší, když nástěnka drží to, co kdo řekl, než odešel.

Peer je spojení. Epizoda je posezení práce a pro klienta bez vlastních hooků poskytovatele je spojení jediné, co může nakreslit její hranici (ADR 0103). Do té doby bylo kreslení hranice pod modelem zapojeno jen pro Claude Code a tvrzení repozitáře, že to dělá, bylo tvrzením o jednom dodavateli.

Identita patří klientovi, nikdy ne id peera. external_id je to, čemu klient trvale říká sezení, ve kterém je — id jeho konverzace nebo vlákna — a jeho celým úkolem je přežít opětovné připojení. Id peera se přiděluje na připojení a je pokaždé, když se klient vrátí, jiný řetězec; považovat jej za trvalé je to, co udělalo relaci neviditelnou pro osm dalších po tři hodiny dne 2026-09-09.

Přerušené spojení se odpojí; nezavře se. Zmizení klienta řídí dvoje hodiny a odpovídají na dvě otázky. SESSION_IDLE_TIMEOUT (90 s) rozhoduje, kdy se socket zapomene. episodes::REATTACH_GRACE (15 minut) rozhoduje, kdy je práce u konce. Čtenář logů uvidí spojení vyklizené dlouho před epizodou, kterou neslo, a je to záměr.

Nic zde nezapisuje záznam relace. Nástěnka spouští majordomus capture session --provider generic --event start|end — stejný příkaz, který spouští shim hooku poskytovatele, se stejným tvarem payloadu, přes stejný čtecí kód — a hlásí, co řekl, doslova, v poli repository epizody. Druhý zapisovač záznamu, který už hooky zapisují, by byla opakovaná sémantická definice, kterou CAPABILITIES.md zakazuje. Vlastní úložiště repozitáře je také to, co epizodu obnoví po restartu serveru: zabitý server nezapíše žádnou koncovou událost, epizoda zůstane otevřená v .ai/local/state/sessions-open/ a další attach pod stejnou identitou je session start --if-open keep, který ji zachová.

Zachycení surového promptu tu není a je deklarováno, že není. MCP server dostává initialize, volání nástrojů a oznámení; prompt osoby mezi nimi není nikdy, v žádné verzi protokolu. share/providers.yaml říká prompts: none pro generického poskytovatele, s tímto zdůvodněním v poli důkazů, a pod prompts neexistuje hodnota connection, po které by kdokoli mohl sáhnout. Co každý poskytovatel umí a kde to bylo ověřeno, je majordomus product providers a majordomus capture status.

URI, které registr nezná, se na žádném z nich nenajde. majordomus://repository je dotaz (repository.info) s expozicí zdroje: přečtený jako zdroj je to report jako text JSON; přečtený přes majordomus_get je to report jako data (answer) se stejným textem vedle (content). Registr odmítne dotaz vystavený jako zdroj, jehož vstup cokoli vyžaduje, protože čtení nic nedodá.

Objekt má také adresu, kterou URI není: majordomus://rule/project.x@1 je identita a /cockpit/objects/rule/project-x-1 je to, kam je čtenář poslán. Adresa se odvozuje z druhu a identity jednou funkcí, takže existuje pro každý objekt a je stejná na každé ploše; majordomus_entity odpovídá na obě podoby a majordomus_kinds hlásí všechny dvě identity jednoho druhu, které se redukují na jednu adresu. majordomus_entity také jmenuje veřejnou stránku dokumentace objektu (documentation: projekce, route, url, nebo reason, jeho druh není publikován), čtenou z site/data/publication.toml repozitáře a base_url webu — null, když repozitář žádnou publikaci nedeklaruje.

Identita jsou identitní pole druhu spojená pomocí @ — majordomus.scope-integrity@1 pro pravidlo, continue pro prompt, implementation pro profil, M001 pro milník — nebo, u druhu bez identitních polí (politika, dokument), cesta relativní k repozitáři. Každý vypsaný zdroj nese _meta.majordomus s druhem, identitou a proveniencí: cesta, adresář, třída, která jej objevila, sekce manifestu, pod kterou spadá, a jeho velikost.

Klasifikace je konzervativní ve směru, který volající přežije: nic, co něco mění, se neohlašuje jako bezpečné k opakování, protože žádný handler nedeklaroval, že druhé volání je prázdná operace, a cokoli, co zapisuje repozitář, se ohlašuje jako schopné přepsat nebo odstranit. openWorldHint je všude false, protože žádný handler nesahá za hranice stroje: pozorování forge a konzultace poradce jsou příkazy, které spouští člověk, ne schopnosti. Odmítnuté volání je výsledek s isError: true, důvodem jako textem a kategorií jako jedním slovem v _meta.majordomus.error.code — invalid_input, not_found, refused nebo forbidden, stejným slovem, jakým odpovídá trasa HTTP jako error.code, protože obojí čte z téže chyby. Odmítnutý výsledek nenese structuredContent: výstupní schéma popisuje úspěch. Neznámý nástroj, metoda nebo zdroj je chyba protokolu.

# A validate run started by a labeled event (priority:p0) only carries the head's existing verdict through carried-verdict and cancels its own jobs; rerunning it cannot turn a head green. Train 28 (#2940, a4bcc410edc): the seat reran the labeled run 42105197744 twice; the pull_request run 42105196366 was the one to rerun. Read the run's event before any rerun.

Observed as defect about scripts/ci/carried-verdict in episode s-20261105135037-9134.

# Evidence

- `.github/workflows/validate.yml` at 1112bace343: line 27 starts the workflow on `labeled`; lines 164-178, the plan job's step, run `scripts/ci/carried-verdict yield --action "$ACTION" --label "$LABEL" --sha "$HEAD_SHA" --self "$GITHUB_RUN_ID"`; lines 2138-2169, the `carried` step of the ci job, and every later step of it is conditioned on `steps.carried.outputs.carried != 'true'`.
- `scripts/ci/carried-verdict`, header: "a label that changes nothing starts no second verdict (I4347) ... it never writes a verdict of its own": a run started by `priority:*`, `type:*`, `train` or `records` on a head that already carries a verdict gives its runners back and writes the earlier run's verdict.
- Train 28 (#2940, merged as 1112bace343): the seat reran the labeled run 42105197744 twice and the head stayed as it was; the pull_request run 42105196366 was the one whose rerun could change the verdict. `gh run view <id> --json event` before any rerun.

Celá argumentace

Delší výklad za domovskou stránkou: proč vývoj řízený prompty neškáluje s repozitářem, co je záměr, model provádění s poctivým označením toho, co existuje, proč musí být governance spustitelná, a doktrína.

Domovská stránka říká, co Majordomus je, a dokazuje to na jedné stránce. Toto je argument, z něhož byla tato stránka destilována, celý: problém tak, jak jej prožívá repozitář, model, který hájí, a — fázi po fázi — kolik z tohoto modelu dnes běží a kolik je zatím jen argument.

02 / hlavní myšlenka

Popište požadovaný stav, ne úpravu

Záměr je výrok o realitě: co se musí stát pravdou, co musí zůstat pravdou a jaké důkazy to rozhodnou. Záměrně to není seznam souborů k otevření.

Co se musí v aktuálním repozitáři změnit, aby se záměr stal pravdou?

Záměr je primární artefakt

Prompt není zdrojem pravdy. Je jedním ze způsobů, jak sdělit záměr pracovníkovi. Není jím ani úkol, milník, commit, pull request, ADR či test: to jsou projekce, omezení, důkazy nebo následky kolem něj.

kontext před kódem

Kontext se kompiluje, nejen vyhledává

Cílem není nalít repozitář do modelu. Je to zkompilovat nejmenší užitečnou reprezentaci reality, kterou práce potřebuje. Byla by řazena podle autority, nesla svou provenienci, vešla se do rozpočtu řádků, který jmenuje každé vyloučení, vynechala, co worker už má, a řekla, kde se dva zdroje rozcházejí.

Vysypat dvacet souborů Markdownu do kontextového okna není architektura. Je to znečišťování pomocí GPU.

řídicí smyčka

Agent nemůže prohlásit úspěch jen proto, že se jeho patch aplikoval

Uzavřete tytéž fáze a máte řídicí systém místo asistenta: kontext by pozoroval, plán by počítal rozdíl, provádění by jednalo, ověření by měřilo a výsledek by se porovnával se záměrem, ne s diffem — přeplánování, dokud není uspokojen. Majordomus nikdy nevolá model a nikdy nepíše kód; rozhoduje, co se pracovníkovi řekne a zda lze věřit jeho tvrzení, že je hotov.

Repozitář, testy, runtime, governance i důkazy mají hlas. Důkazy mají poslední.

Automatické. Podporované. Vynucované. Generované. Testované.

Repozitáře takovými slovy hromadí a jsou překvapivě nebezpečná. Tvrzení má cenu jen tehdy, když ho něco spojuje s důkazy. Zde každé tvrzení jmenuje zdroj, implementaci a test, které ho rozhodují, a tvrzení, jehož důkazy se už nerozlišují, shodí build.

Pak se změní buď implementace, nebo tvrzení. Vyhrává realita — v softwarové dokumentaci nezvyklá politika, to se musí nechat.

Index tohoto repozitáře jich obsahuje 250, každé pojmenovává zdroj, implementaci a test, které o něm rozhodují. Tvrzení, jehož důkazy se už nedají dohledat, shodí build dřív, než lze web publikovat; porovnat znění tvrzení s chováním, které popisuje, je tu stále úkol pro člověka.

Dokončení znamená splnění záměru

Kód napsán, testy zelené, PR sloučen: vše užitečné, nic z toho není důkaz výsledku. Sloučený pull request, jehož záměr zůstává nepravdivý, je nedokončená práce a git server není orákulum.

Smlouva tak, jak ji ukazuje README samotného repozitáře: zaznamenaný běh z výzvy, začerněný a jinak nedotčený, který build odmítne publikovat, pokud přestane odpovídat. Jeden řádek na kontrolu, každý uvádí, co dokázal; selhávající řádek nese příkaz, který ho reprodukuje, a dokud neprojdou všechny řádky, nic se nezapíše.

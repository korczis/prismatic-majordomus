# an empty build directory variable stops the build-directory sweep silently: with CARGO_TARGET_DIR= (empty, meant as unset) mj_rust_prune_build_dir asks cargo metadata, which refuses an empty CARGO_TARGET_DIR or CARGO_BUILD_BUILD_DIR, so the sweep prints 'none removed: cargo did not say where this build keeps them (cargo metadata failed)' and returns 0; callers that discarded its output saw nothing and a build host sat under its 35 GiB floor for over an hour on 2026-11-05, while the same sweep with the variable unset freed 4.7 GB

Observed as defect about lib/rust_bin.sh in episode s-20261105041806-8f14.

# Evidence

- `file:lib/rust_bin.sh`
- `test:test/cases/3080_idle_incremental_sessions_are_pruned.sh`

# Evidence

- `cd apps/majordomus-cli && CARGO_TARGET_DIR= cargo metadata --format-version 1 --no-deps`: exit 101,
  "the target directory is set to an empty string in the `CARGO_TARGET_DIR` environment variable";
  `CARGO_BUILD_BUILD_DIR= cargo metadata`: "the build directory is set to an empty string".
- lib/rust_bin.sh mj_cargo_metadata_dir asked cargo with the empty variable exported, so
  mj_rust_prune_build_dir printed "none removed: ... (cargo metadata failed)" and returned 0.
- Fixed on this branch: mj_cargo_empty_dir_vars names the empty variables, mj_cargo_metadata_dir
  asks cargo with them unset, and the refusal names them. Case
  test/cases/4561_an_empty_cargo_dir_variable_is_read_as_unset.sh fails on 4795a79d954's
  lib/rust_bin.sh ("did not expect /cargo metadata failed/") and passes with the fix; case 3080 passes.

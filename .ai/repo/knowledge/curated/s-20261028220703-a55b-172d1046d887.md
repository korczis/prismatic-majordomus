# mj_provider_session_env sources lib/capture.sh lazily, and it is called inside a command substitution, so a function capture.sh defines is still undefined in the caller afterwards; a caller that then calls one dies with command not found under set -e and no message, as mj_session_start did with mj_provider_of_session_env until it sourced capture.sh itself

Observed as defect about lib/common.sh in episode s-20261028220703-a55b.

# Evidence

- `test:test/cases/111_session_per_provider.sh`

# Evidence

Measured on 2026-10-29 on branch chore/the-sessions-lessons-of-2026-10-28-are-reviewed. After
adding mj_provider_of_session_env to lib/capture.sh and calling it from mj_session_start, case 111
failed with no message: the scratch repository's sessions-open/ was empty, so the hand start had
exited. Cause: mj_session_start had called mj_provider_session_env as
"$(mj_provider_session_env)". That function sources capture.sh only inside that subshell, so the
parent shell never defined mj_provider_of_session_env, and the call died with "command not found"
under set -e. Sourcing capture.sh in the caller (lib/session.sh, guarded by MJ_LIB_capture, as
common.sh does) fixed it, and case 111 passed. shellcheck -x reported nothing either way.
Rule for the shell layer: a function from a lazily sourced library is only defined in a shell
that sourced it itself. A command substitution is not that shell.

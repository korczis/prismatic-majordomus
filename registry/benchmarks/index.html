Benchmarks

Every benchmark target derived from the registry, the coverage, the regression policy, and the accepted baselines with their provenance.

Registry The executable Modules Capabilities Command line MCP HTTP API Benchmarks

Every externally callable operation is a benchmark target, derived from the registry: each executable capability directly and on every transport its exposure declares, with the cases its input type provides, plus the transports' own operations. majordomus bench coverage computes the same table live, majordomus bench times it, and bench --check compares a run with the accepted baseline of its platform under the policy below.

The same matrix as Markdown is docs/generated/benchmarks.md; how to read a measurement is the performance document.

Regression policy

What bench --check applies, read from .ai/repo/benchmarks/rust/policy.yaml: a metric fails when it grows by more than its relative threshold and by at least the absolute floor, and gates only once the run took its minimum samples.

metricallowed increasegates from
p5025.0%0 samples
p9530.0%50 samples
p9950.0%200 samples
absolute floor1000.0 µs — an increase under it is noise, whatever the ratio

Accepted baselines

One per platform, committed and reviewed. A measurement is evidence of the host, build and commit named with it and of nothing else: a debug build on one laptop says nothing about a release build elsewhere, and bench --check fails a run only against a baseline recorded on the same host.

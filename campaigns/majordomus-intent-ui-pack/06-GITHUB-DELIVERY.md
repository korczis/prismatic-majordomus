# 06 — GITHUB, PR THROUGHPUT, RELEASE AND DEPLOY

Inspect existing `prs`, GitHub workflows, milestones/issues mapping, worktree hygiene, version policy, changelog, `.ai` enforcement, CI/CD, deploy strategy and docs site. Reuse current GitHub adapter and command/reconciliation model. Never assume GitHub is the canonical owner of intent semantics: it may be the authoritative external owner of PR/issue fields; define bidirectional reconciliation ownership explicitly.

Provide derived GitHub projections for intent realization: link criteria → milestones → issues → branches/worktrees → commits → PRs → checks → releases → deployments → verification evidence. Use stable repository identifiers and URLs, not title heuristics alone. Show source of truth and last observation time for each external fact. Detect and explain drift without silently overwriting user edits.

Implement command-backed actions only where allowed: preview GitHub issue/milestone reconciliation; publish/create/update with idempotent reconciliation; run selected ready work; open/update PR; view checks, reviews, conflicts, diff; safe rebase strategy; merge when checks/review/protection policy permit; release version derivation and bump according to existing `.ai`/version policy; generate changelog/docs; publish and deploy with explicit gates. Update the existing UI / CLI / MCP consistently. Ensure no open-ended force-merging or bypass of GitHub branch protections. Closed PR does not imply done; a merged PR alone does not satisfy a criterion or verify production.

Reconcile conflicts: same issue changed remotely; PR branch advanced; check stale for head SHA; mergeability unknown; contributor worktree overlaps; release tag already exists; partial publish; deploy succeeded but smoke failed; rollback requested; credentials missing or rate limited; offline mode. Fail safely and surface actionable blockers with retry/reconcile options. Restrict destructive cleanup to verifiably merged, unmodified, unclaimed worktrees and authorized scopes. Preserve histories.

Design staged pipeline: local verification → PR checks/review → merge → version/release → deploy → post-deploy smoke/health → recorded evidence/intent reevaluation. Consider action-driven CI status updates and event replay. Verify running artifact version matches expected release, endpoint routes are reachable, critical UI flows work and claims/evidence are current. For unavailable deploy credentials, produce an honest blocked deployment record and complete all local steps; never claim deployed.

Acceptance: one representative fixture issue can be planned, implemented, checked and reconciled through mocked GitHub transport; an explicitly authorized real-repo validation exercises read-only discovery plus safe permissions-scoped write tests if permitted. No remote mutations in integration tests unless isolated test repository is configured. Capture evidence for actions and their inverse/recovery paths.

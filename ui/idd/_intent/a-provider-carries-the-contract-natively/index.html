What is this intent for?

What the work is for, what it holds the work to, and whether the evidence says it is met.

a-provider-carries-the-contract-natively

Each agent client enforces and observes the repository's contract through its own extension points, generated from the registry

plannedunknown0 of 10 criteria metClose

Claude Code first, then Codex, carry Majordomus's scope, finish and session contract through their own hooks, skills, plugins and mods, all generated from the capability registry and kept in sync by a gate, so that an out-of-scope edit is refused before it happens and a session that stops owing work is told so, the hooks and the MCP listing they load stay within declared budgets, and the editors that read the layer validate it against its own schemas, without Majordomus embedding or patching any client.

What does it hold the work to?

  • Every client artefact is a generated projection stamped with its source; a hand edit fails the drift gate
  • A client's own memory or settings never become canonical state
  • Personal settings, permission modes and model choice are never projected (ADR 0140, ADR 0145)
  • No client binary is patched

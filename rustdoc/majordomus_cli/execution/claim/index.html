Module claim 

Source
Expand description

The mesh claim an execution started for an issue holds while it runs (I4004).

Two workers that start the same issue at once must not both run it. The mesh already decides that question for sessions — an exclusive claim that meets a live exclusive claim of another session is refused, on this runtime and on every runtime it has heard — so an execution started for an issue asks it the same way a person’s session does: through Cooperation::claim, the function mesh.claim calls, as the mesh session execution-<id>, for the issue’s declared scope.

  queued ──► take ──► held ──────► claimed ──► running ──► final ──► released
                 │                                     └─► unknown_outcome ──► kept
                 ├─► conflict ──► refused  (the holder named; nothing runs)
                 └─► no mesh ───► unclaimed ──► claimed ──► running ...   (said, never a failure)

The claim is given back when the execution reaches a final state, by the worker that ran it, and — through HeldClaim’s Drop — when that worker unwinds instead. An outcome that is not known keeps the claim: whether the work happened is still to be read, and the scope is not free until it has been. A kept claim, or one whose process died, ends when its runtime stops beating, as every mesh claim does. Fencing a holder that comes back after its claim expired is not done here (I3174).

use majordomus_cli::execution::claim::{disposition, scope_of, session_of};
use majordomus_cli::execution::{ClaimStanding, ExecutionId, ExecutionState};
let repo = majordomus_cli::synthetic::SyntheticRepository::small().unwrap();
let ctx = repo.context().unwrap();
let id = ExecutionId::fresh();
assert_eq!(session_of(&id), format!("execution-{id}"));
assert_eq!(scope_of(&ctx, "I4004"), ["issue/I4004"]);
assert_eq!(disposition(ExecutionState::Cancelled), ClaimStanding::Released);

Functions§

disposition
What the claim does when the execution reaches state: kept for an outcome that is not known, released for anything else — a final state, or a worker that is leaving.
scope_of
The scope an issue’s claim covers: the paths its record declares under scope, or the issue’s pseudo-path issue/<id> when the record declares none or is not in this checkout.
session_of
The mesh session an execution claims as: execution-<id>, so that a refusal that names the session names the execution that holds the scope.

# Mission 03: Every public promise must have living evidence

Locate actual claims, tests, use cases, scenarios, execution ledger and evidence verdict rules. Enforce claim -> implementation -> executable behavioral test -> recorded run -> revision/freshness -> surfaced verdict. Distinguish declared `guaranteed`, `advisory`, `planned`, `rejected` from recorded `proven`, `stale`, `failing`, `not_run` and any actual project enum. Do not invent enum variants. A promised capability with no current proof must not appear proven. Include positive, negative, boundary, tampering and mutation tests; fixtures should run real CLI/server where feasible in isolated repos. Test broken tests, changed revision, dirty tree, failing test, not-run, stale ledger, unrelated test evidence preservation and missing test ID. Cross-check all consumers use same evidence service. Integrate with existing tests/coverage policy, do not add a magic percent that encourages fake assertions. Expose `why unproven` with reproducible command. Verify guarantees on site exactly reflect ledger verdict from deployed revision; if evidence cannot be shipped, show unknown rather than success.

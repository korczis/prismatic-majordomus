description = "release/changelog.rs takes its forge base from the repository's .ai/repo/project/project.yaml `repository` (https://github.com/<repository>) and its trunk from `default_branch`, falling back to CARGO_PKG_REPOSITORY and master only where there is no project.yaml (the project schema requires both keys). Every link it builds reads that base and trunk: the unreleased compare and tree links (today `...master` and `tree/master`), the notes, compare, tree and commit links of each release, and each decision's `blob/<trunk>/<path>` link (today `blob/master`). How the release window is read is something a repository declares: an optional project.yaml key `history: first-parent`, added to the project schema. Where nothing is declared, release/commits.rs keeps `git log --no-merges` exactly as today. With first-parent declared, it reads the window with --first-parent, and each first-parent commit is one change. A merge commit whose subject ends in ` (#N)` (merge_commit_title=PR_TITLE) is read by its subject without that suffix; one whose subject is the forge's `Merge pull request #N from ...` is read by its body's first line; a squash or direct commit whose subject ends in ` (#N)` is read as today. The first-parent mode reads a merge's pull request and title by calling I4366's shared merge-subject reader (merge_subject), and release/commits.rs keeps no ` (#` or `Merge pull request #` matcher of its own. Each of the three carries pull request N in a new optional Change field, linked to <base>/pull/N; outside first-parent mode the field stays empty. With first-parent declared, no changelog line begins with 'Merge pull request'. This repository declares nothing, so `majordomus release changelog` and its page docs/generated/changelog.{md,json,yaml} are byte-identical, although it too lands mostly by merge commits (313 of the last 400 first-parent commits on master)."

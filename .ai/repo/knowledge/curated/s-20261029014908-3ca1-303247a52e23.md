# an active task's scope cannot be widened: start refuses while a task is active, so a scope that missed one case the change pins (case 3959 on I4340) cost a finish --outcome partial with a note and a second start; every test case the change edits is named in --scope before the first edit

Observed as friction about command:start in episode s-20261029014908-3ca1.

# Evidence

- `file:.ai/repo/workflows/task-lifecycle.md`

# Evidence

- On fix/the-reaper-bounds-an-untagged-build-dir, `majordomus check` failed with `FAIL scope test/cases/3959_the_shared_build_dir_stays_under_its_bound.sh — outside claimed scope`. A second `start` was refused with `task t-20261029011020-eb72 is active ...; run majordomus finish (or majordomus handover --close) first`, and the task was closed `finish --outcome partial` and reopened.
- `majordomus start --help` documents no way to amend a scope.
- Enforced as a step in .ai/repo/workflows/task-lifecycle.md (this change): name every file the change will edit, the cases it pins among them, before the first edit. The evolve task of this change was itself widened that way before its first edit outside .ai/repo/knowledge.

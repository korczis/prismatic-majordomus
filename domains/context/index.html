Context

Every worker starts from what the repository already knows: the context that applies to its path, the handover the last session left, and the decisions already made.

The failure it answers

Agents forget. What one session learned dies with its conversation, and the next one starts over.

What a worker — a model or a person — knows at the moment it begins, and what is left behind when it stops. The context documents that apply to a path, the session and its handover, the decisions and knowledge that outlive a conversation, and the procedures a worker can load: each is a file the repository owns, read through the same commands by every tool, rather than a transcript somebody hopes to find again.

Not in this domain: who may touch which paths while the work runs, which is coordination; and whether the rules the worker loaded hold, which is governance.

The features filed under it

Each feature names this domain in its own file; the domain lists none of them. A feature added with this domain is on this page at the next build, and one removed is gone.

The failure modes its features answer

Operational moments from the Why catalogue that name a rule, a command, a capability or a claim of a feature in this domain. Nothing here was assigned.

  • →re-explained the same context to a brand-new session
  • →found two agents fixing the same bug in two branches
  • →watched the strongest model, at maximum effort, rename a variable
  • →opened CLAUDE.md and AGENTS.md and found two different rulebooks for one repository
  • →watched a session undo last week's decision, for the reason it was made
  • →found a task "in progress" that nobody had touched for three weeks

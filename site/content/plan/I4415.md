title = "I4415 — finish names the load its verification ran under, waits below a declared load bound before it runs, and retries a failure under load only as policy allows, recording every attempt"
description = "Three changes to mj_validate_verification in lib/finish.sh, none of which changes a repository that declares nothing. First, every verification run reads the host's 1-minute load average and core count before and after it, through one helper in lib/common.sh that lib/bench.sh's mj_bench_load then calls, and the result line says so on pass and on fail: `npm test — exit 1, 412s, load 77.3 -> 93.1 on 12 cores`. The same fields (load_start, load_end, cores) go into the verify object of task.finished, and task.refused gains that verify object, which it does not carry today. Second, a policy key verification.load_max_per_core (absent: no gate) with verification.load_wait_seconds (default 600), overridable per invocation by MAJORDOMUS_VERIFY_LOAD_MAX: before the command starts, finish waits while the load is above the bound, saying on stderr what it waits for and how long it has waited, and past the wait it does not run the command; the verification line fails as `not run: load <x> above <bound> for <n>s`, and task.refused records verify.not_run: load, so I3131's aggregate can tell a refusal of the work from a refusal of the machine. Under CI (CI or GITHUB_ACTIONS set) there is no gate, as in OSCILLA's suites and I4006. Third, a policy key verification.verify_retries (integer 0-2, default 0): a failed attempt is retried only when that attempt started or ended above the load bound and the tree id is the one the failed attempt ran over; a failure on a quiet machine, or with no bound declared, is never retried, so a deterministic failure cannot be retried into a pass. Every attempt is recorded (verify.attempts: exit, seconds, load_start, load_end, tree), and a pass after a failed attempt reads `exit 0 on attempt 2 of 3 (attempt 1: exit 1, load 81.0)`, never as a plain pass. The rule majordomus.verification-integrity states the attempt record and the conditions under which a retry is admitted."

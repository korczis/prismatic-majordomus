# a background task reported failed with exit 144 while its script, reparented to pid 1, kept a cargo build running for 25 minutes and was reported to a peer as stopped; a wrapper's exit is not its script's, so a task is not called dead until its script's pid is gone, and the script is stopped before its child so it cannot go on to commit

# Evidence

- The mechanism is the one rule project.one-derive-at-a-time records: stopping a wrapper shell does not
  stop its foreground child, which runs on reparented to pid 1 (`generate-site-data` ran for an hour).
- docs/BACKLOG.md reaps only processes whose parent is init, which is what such a script becomes.
- On 2026-10-25 a background task reported "failed with exit code 144" while its script, reparented to
  pid 1, kept a cargo build running for 25 minutes; it was reported to a peer as stopped.
- So a task is not called dead until its script's pid is gone, and the script is stopped before its
  child so it cannot go on to commit.

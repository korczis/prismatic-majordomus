# at load 30-45 on 18 cores one git process costs 0.2-0.6 s where it costs 0.07 s idle, so a served read that spawns git per record or per commit costs tens of seconds: environment.preflight spawns about 60 (7.4 s to 39 s by load); a served read asks git once per answer, not once per candidate

Observed as friction about capability:environment.preflight in episode s-20261027131618-6269.

# Evidence

- `test:apps/majordomus-cli/src/capability/builtin/continuity.rs`

# Evidence

- Load 43 on 18 cores (uptime, 2026-10-27T12:35Z): ten `git merge-base --is-ancestor <sha> HEAD` calls took 6.4 s (0.64 s each). At load ~36, the 30 git commands of environment.preflight's ledger comparison took 2.25 s as a shell loop.
- `run environment.preflight` took 34.4 s (master binary) and 39.2 s at load 27-43, then 7.4 s once the load fell. A ps capture of its children counted about 60 git processes (12 merge-base, 12 diff, 18 rev-parse, 7 ls-files, 2 status).
- In-process, the same command costs what the machine's load makes a process spawn cost, so per-record git calls in a served read scale with both the record count and the load. Continuity's 352 per call was the extreme case (lesson s-20261027131618-6269-77d9a54bdc7a).

The Observatory: the repository and its mesh, drawn for a wall

One screen of the UI rotates eight scenes on a display nobody is sitting at, and every mark on it is a value a capability answered; a scene with nothing true to draw says why and is never drawn empty.

What it does

The other screens of majordomus ui are rows for a person who came to decide something. The Observatory is the same facts as a picture, for a hallway display. It rotates eight scenes: Mesh Cosmos, Event River, Intent Nebula, Token Spectrum, System Pulse, Delivery Tree, Cooperation Choreography and Ambient Intelligence. Each scene names the capabilities it requires, what its marks mean, and the screen where the same facts are rows.

A mark is a fact or it is decoration. A machine, a runtime, an event, a milestone, a health dimension, a release and a session are drawn from what mesh.peers, mesh.events, plan.roadmap, health.report, distribution.releases and mesh.state answered. The drifting background and the slow motion are decoration, and the display says so.

A scene whose source did not answer, or answers that no mesh runs in this process, is unavailable with the source's own reason. The rotation skips it. An event is drawn by its kind, its stream and its clock; its body stays in the capability that owns it.

The status word is true: LIVE while the page was read again within forty seconds, STALE when the server stopped answering, SNAPSHOT on the published site, with the commit it was read at. /ui/kiosk is the same screen, projection and script filling the window.

What it does not do

It adds no capability, no store and no transport: the page carries one bounded projection, and the script asks the server for nothing but that page. It starts no work and writes no record.

On the published site the process that takes the snapshot runs no mesh, so the three scenes of the mesh replay the recording the repository carries, labelled REPLAY with the time it was recorded; the recording is as old as the last capture someone committed. The display follows the journal from a cursor between readings of its page (observatory.events). Its gates are recorded with their evidence in .ai/repo/benchmarks/observatory/manifest.json: screenshots at 1920x1080 and 3840x2160 of the published site, 60 frames per second in headless Chromium on an Apple M5 Pro, no WCAG 2.2 AA violation, reduced motion honoured, an hour-long soak with a stable page, and recovery drills. No physical wall display has been measured.

The plan and its derivations plan behaviorally verified

The milestone and issue model of this repository, and everything derived from it that nobody authored: the status of each record, the dependency graphs above and below the milestone boundary, the topological execution waves, the roadmap order, the milestone being executed and the one issue to take next. Status is never stored — a record says what happened to it and the status follows from that and from the state of its dependencies — so no file can contradict the graph. This capability reads; writing a lifecycle marker into a record is `plan.transition`, which declares that it writes the repository.

Using it

From the executable's command line

The synopsis of each, as the executable's own help prints it.

  • majordomus scope [OPTIONS] [PATHS]

    The repository scope: what a worker reads and what it never reads; with paths, whether each is in or out and why

  • majordomus distribution show [OPTIONS]

    The model: the install command, where an installation goes, and every declared target

  • majordomus distribution status [OPTIONS]

    Whether the advertised one-line installation works right now, and what is missing when it does not

  • majordomus distribution artifact [OPTIONS]

    The archive name and root directory a target and a tag derive

  • majordomus distribution releases [OPTIONS]

    Every recorded release, newest first, and the one an unpinned installation resolves to

  • majordomus distribution build [OPTIONS]

    What this executable is: version, target triple, profile, commit

  • majordomus mesh identity [OPTIONS]

    This machine's node identity, public half only; absent is an answer, not an error

  • majordomus mesh doctor [OPTIONS]

    Prove the mesh prerequisites on this machine alone: declaration, identity, sockets, multicast, broadcast, the protocol end to end, and the host firewall

  • majordomus mesh firewall [OPTIONS] [COMMAND]

    What the host firewall must admit for the declared mesh and whether it does; `apply` admits it, as root

  • majordomus mesh firewall apply [OPTIONS]

    Run the commands that admit the plan on this host's firewall; needs root, and exits 10 when it refuses or the firewall still does not admit the mesh

  • majordomus served observe [OPTIONS]

    Probe the build identity a deployment serves, judge it against a commit and record it

  • majordomus served forge [OPTIONS]

    Ask the forge which deployments and releases it recorded, and keep the answer for the readers

  • majordomus served show [OPTIONS]

    Each deployment's newest record, re-judged against a commit

  • majordomus plan delivery [OPTIONS] [ISSUE]

    Every issue's furthest delivery stage, with the object that proved it and its declared status beside it

  • majordomus plan drift [OPTIONS] [ISSUE]

    Every contradiction between an issue's declared status and its delivery — merged_not_recorded, active_without_work, done_without_trace — each with its proof; with --gate, judged against the window .ai/repo/ci/plan.yaml declares

  • majordomus economics summary [OPTIONS]

    Every metric with its class, sample size and interval, the pairs, the segments, the state of the evidence, and the one statement the publication rule allows

  • majordomus economics explain [OPTIONS] <METRIC>

    One metric and everything it rests on: formula, class, pairs, runs, exclusions, and how to reproduce it

  • majordomus economics runs [OPTIONS]

    The recorded runs every metric is computed from

  • majordomus economics check [OPTIONS]

    Refuse an unsupported savings claim: quantities next to the economics vocabulary in hand-written prose, and bound claims whose evidence does not stand

## 157. A mesh node may offer a shared build cache, peers discover and select it, and compilation never depends on it

### Context

On 2026-10-13 the cluster could not derive: both declared offload hosts were under their
10 GiB free-space minimum (7 and 1), the owner's Mac had no free disk and was cleaned by
hand, and a derive of one documentation pull request took thirteen minutes of compiler time
three times in two hours, each time from a cold cache. Every machine compiles the same
Rust for the same commits, each into a cache of its own: ADR 0139 shares what cargo
compiles between the worktrees of one machine and says, in terms, that `sccache` "stays
optional and is not part of this decision". Nothing shares compilation between machines.

The owner's order, the same day, names the shape: one node with a large disk (an aarch64
Jetson with 783 GB free) holds a shared object store, every node uses its local disk first
and that store second, and the result is verified and validated, not assumed.

### Decision

1. **A capability, not a host.** A node may *offer* `build-cache`: `protocol: s3`,
   `provider` (MinIO first), `scope: mesh`, a non-secret endpoint, a bucket, a priority,
   capacity and headroom, and health. Nothing canonical names a machine; the first
   provider is whichever node offers it. Clients ask for `build-cache/s3`.
2. **Offered at run time, not committed.** The repository's declaration holds policy only —
   which providers and protocols are accepted, bucket naming, expiry, the headroom floor.
   An endpoint is a fact about a running node and travels as a signed, expiring mesh
   record (ADR 0044's board, the journal's liveness): a provider that stops is stale
   within its lifetime and nobody edits a client. A private address is never written to
   a tracked file or a published page.
3. **Selection is a pure function** of the offers, the policy and the measured latency:
   healthy first, then scope, priority, headroom, round-trip time, and the node id as the
   last, deterministic tie-break. It answers with the chosen offer *and why*, including
   the candidates it passed over. With no offer it answers "none", and that is a normal
   answer.
4. **The client is derived, never configured by hand.** `majordomus env` emits the sccache
   configuration for the selected offer — the local disk as the first level, the offer as
   the second — and `.envrc` stays the thin adapter it is (`project.envrc-is-an-adapter`).
   With no offer, or a sccache that cannot do two levels, the client is local-only, and
   with no sccache at all the build is exactly what it was.
5. **The cache is acceleration, never a dependency.** A provider that is down, slow,
   full, or refusing a credential must leave the build correct and not much slower: the
   client falls back to the local level, the failure is a diagnostic naming the cause
   without a secret, and a probe is bounded (the 80 ms budget of `environment/services.rs`;
   unknown, never "down").
6. **Nothing portable is assumed.** The cache key is sccache's: toolchain, target and
   flags. A hit across architectures is not claimed; the proof of a shared hit is made
   between two nodes of one platform, and where there are not two, it says so.
7. **Secrets stay out of the model.** The offer, the selection, the CLI, the API, the MCP
   tool, the UI and the docs carry no key. A client credential is provisioned onto a node
   with the owner's SSH access into a file of mode 0600 outside the repository, one key
   per node that can be revoked, and a write without one is refused by the store.

### Consequences

- The slowest thing a node does — compile Rust it already compiled elsewhere — becomes a
  read from a disk on the LAN, for every node that has the same toolchain and target.
- A new provider is a record, not a code change, and a second provider is ranked, not
  configured.
- A new operation family (read of offers and selection, provisioning, verification) joins
  the registry by `capability!` and is projected to the CLI, MCP, HTTP and OpenAPI by
  `majordomus generate`, as `docs/CAPABILITIES.md` requires.
- The mesh's advertisement datagram is size-bound; the offer rides the journal as an
  expiring record and not the UDP advertisement.

### Alternatives rejected

- **A committed list of endpoints.** It is a second registry that rots at the first
  address change, and it publishes a private address.
- **Distributed compilation** (`sccache-dist`, icecream). It moves compilers across
  machines of one platform and is a much larger trust and failure surface than a cache.
- **Making the Jetson mandatory, or naming it.** A provider that cannot be absent is not
  a cache; and the first host is an accident of which disk was large.
- **Writing `~/.cargo/config.toml` on peers.** It is a user's file. The derived
  configuration is exported through the environment, and a missing sccache is a
  diagnostic, not a silent edit.

### Measured on 2026-10-13

The first provider was set up and verified before this decision was written down, and the
measurements change it:

- **MinIO publishes no binaries any more.** `dl.min.io` answers `410 Gone` for the server and
  the client; the last source tag is `RELEASE.2025-10-15T17-29-55Z`. The provider here was
  built from that tag (a static `linux/arm64` executable), which makes it a build nobody
  patches for us. `provider` is a field of the offer because of this: an S3 server with
  supported releases (Garage, SeaweedFS) replaces it without a change to the model.
- **sccache 0.18.0 has the two levels** (`SCCACHE_MULTILEVEL_CHAIN=disk,s3`, with
  `SCCACHE_MULTILEVEL_WRITE_ERROR_POLICY`). It was read from the executable, not assumed.
- **A real remote hit was shown:** the local level wiped, the second compile reported one
  hit from the store and an identical object.
- **A provider that is down when the sccache server starts fails the compile** (exit 2,
  no object): the start-up check of the store is a hard error. A provider that stops while
  the server is running does not: the compile succeeds as a miss. So decision 5 is a rule
  about *when* the second level is put into the chain — only when the offer is healthy at
  the moment the server is started — and not only about what happens after a failure.
- **Writes without a credential are refused (403)**, a client identity cannot create a
  bucket or reach the admin interface, and it sees only the one bucket.

### Verification

The model and the selection are proved by unit tests (discovery, determinism, no offer,
stale offer). The client derivation, the fallback with the provider stopped and the
refusal of an unauthenticated write are proved by `test/cases/3013_a_mesh_build_cache.sh`
against a stub S3 endpoint. The claim that a second node hits what the first wrote is
proved on two real nodes of one platform, or reported as not proved. Acceptance is the
contract of the pack the owner filed
(`majordomus-jetson-mesh-cache-claude-pack/contracts/acceptance.md`), item by item.

### Amended on 2026-10-22: dependency installs, the key, and enforcement

On 2026-10-22 lundra, the build and deploy host, reached zero free bytes, and the owner asked for
the shared cache to be part of Majordomus — used when a store is available, enforced, derived —
for compiled Rust, the shared cargo build directory, `mix deps.get` and `npm install`. A critique
of the plan (`.ai/repo/project/critiques/a-build-reuses-what-the-mesh-already-built.yaml`) and the
owner's three answers the same day amend this decision; intent
`a-build-reuses-what-the-mesh-already-built` and milestone `builds-reuse-the-mesh-cache` carry it.

8. **Dependency installs are cached too, under a key Majordomus derives.** Decision 6 stays true
   for compiled Rust: sccache keys it. A dependency install (`node_modules` from `npm ci`, `deps/`
   from `mix deps.get`) is cached as one archive under a key of a schema version, the platform
   (the toolchain's host triple, or `any` for platform-independent source such as mix
   dependencies), the toolchain as its executables state it, and the digest of every input that
   changes what the install leaves (I3950). `majordomus mesh build-cache ensure <kind> --
   <command>` skips an install already in place, restores a hit from the machine's local archive
   level and then the store, and on a miss runs the command and saves its result (I3952).
9. **An archive is restored only after its digest matches.** The SHA-256 recorded when it was
   saved is checked before extraction, and an entry that is absolute, climbs out with `..` or is a
   link leaving its target is refused; either failure is a miss.
10. **Discovery stays the signed offer of decision 2.** A store answering on a port is never
    trusted for being there: what a client restores is executable. A probe of the client's own
    declared store is health, not trust.
11. **The repository's own builds go through the cache.** ADR 0139 left sccache optional; for this
    repository's local build paths it is now the path: the cargo choke point in `lib/rust_bin.sh`
    starts sccache with the store as its second level when the store is healthy at that moment,
    the credential is read from an AWS-format file of mode 0600 through
    `AWS_SHARED_CREDENTIALS_FILE` and never exported as a value, and a gate refuses a new local
    path around it unless the line declares why (I3953). GitHub's runners, which cannot reach the
    store, keep `actions/cache`.
12. **The cargo build directory is a kind, because a second node was measured reusing it.**
    On 2026-10-22 (I3955) commit 2034d4a3f0b was built cold on node A in 566 s (142 units), its
    build directory archived without incremental state (2.9 GB uncompressed), and restored on node
    B, which had its own checkout and its own registry: B's build found all 142 units Fresh and
    compiled none. The reuse holds when the toolchain, `CARGO_HOME` and the tree's path match; a
    tree at another path recompiles its own workspace crate only (ADR 0139, MAJORDOMUS_BUILD_TREE),
    its dependencies stay Fresh. The archive is restored only into a cold directory, under cargo's
    own lock, extracted beside it and renamed into place with cargo's CACHEDIR.TAG, and it is
    saved only below one PUT's size.
13. **The machine-wide local level lives outside `.ai/local/`.** It is shared by every checkout of
    a machine, so it lives under `~/.cache/majordomus/build-cache`, bounded by policy and reduced
    by `scripts/reap-orphans` (ADR 0055); rule `project.cache-is-invisible` is amended for it
    (I3952).

The earlier issues keep their places: I2671 (the signed offer) is what I3952 trusts, I2672 is the
read `mesh build-cache` projects, I2673 is the sccache derivation I3953 uses, I2674 provisions the
store and now also its bounds and the build host's disk guard, I2675 shows health and hits, I2676
measures sccache and the archives on two real nodes, and I2677 is absorbed by
`docs/BUILD_CACHE.md` of I3953.

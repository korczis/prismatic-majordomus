# Evidence

- Reported by the coordinating session: on 2026-11-05 two long-running sessions stamped mesh
  messages 10-17 minutes ahead (04:31Z sent ~04:14Z; 04:3xZ sent ~04:18Z), each corrected by the other.
- `grep -rniE "date -u|clock|stamp" .ai/repo/rules docs/MESH.md .ai/repo/workflows`: no rule,
  workflow or MESH.md passage says a message's stamp is read from the clock right before it is
  sent (session-records.v1 derives record times from the clock; nothing covers messages).
- Remedy now: run `date -u` immediately before every stamped message. A rule would not be enough;
  the mechanism owed is a stamp the board or the message tool writes itself (needs an issue).

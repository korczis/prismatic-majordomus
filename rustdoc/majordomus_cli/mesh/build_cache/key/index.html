majordomus_cli::mesh::build_cache

Module key 

Source
Expand description

What a dependency install or a build directory is cached under: a triplet of platform, toolchain and inputs, derived from the machine and the repository (I3950).

Derived, never typed. The kinds a repository has are the lockfiles it tracks: a Cargo.lock makes a cargo build directory, a mix.lock a set of mix dependencies, a package-lock.json an npm node_modules. The platform is the toolchain’s own host triple where it states one (rustc -vV) and this machine’s otherwise. The toolchain is read from the executable that will run in that directory — so a rust-toolchain.toml or an asdf pin is honoured because the executable honours it, never because this module read the pin. The inputs are the files whose change changes what the install produces, hashed with their paths.

Path-free. The key names no directory, so two checkouts — or two repositories — with the same lockfile on the same platform and toolchain share one entry, which is the reuse the mesh exists for. Where the entry is restored to is a separate field.

Unknown is said. A kind whose toolchain is absent, or does not answer within its budget, has no key and says why; nothing is guessed, and the caller does the work itself.

use majordomus_cli::mesh::build_cache::key::{Kind, KindKey, KEY_SCHEMA};
// a lockfile names a kind; the kind's word and the schema open every key
let kind = Kind::parse("npm-modules").unwrap();
let key = format!("{KEY_SCHEMA}/{}/aarch64-apple-darwin/node-24-npm-11/{}", kind.as_str(), "0".repeat(32));
let entry = KindKey {
    kind, dir: "site".into(), location: "site/node_modules".into(),
    platform: "aarch64-apple-darwin".into(), toolchain: Some("node-24-npm-11".into()),
    inputs: vec!["site/package-lock.json".into()], digest: "0".repeat(32),
    key: Some(key), unavailable: None,
};
assert!(entry.key.unwrap().starts_with("v1/npm-modules/"));

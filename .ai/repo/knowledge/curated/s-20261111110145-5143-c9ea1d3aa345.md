# a git push over SSH from the Linux build host was cut by the remote ('Connection to github.com closed by remote host') while the report-only pre-push ran for about 8 minutes; the same push over HTTPS with gh as the credential helper (git -c credential.helper='!gh auth git-credential' push https://github.com/<owner>/<repo>.git) completed, because smart HTTP sends the pack in a new request after the hook ends and holds no connection idle while it runs, where SSH keeps one open the whole time

Observed as workaround about .githooks/pre-push in episode s-20261111110145-5143.

# Evidence

- `file:.githooks/pre-push`

# Evidence

- On 2026-11-10/11 a push from the Linux build host over SSH ended with "Connection to github.com closed by remote host" while .githooks/pre-push ran for about 8 minutes; the same push over HTTPS with `credential.helper='!gh auth git-credential'` completed. This run pushes the same way.
- .githooks/pre-push runs `scripts/ci/run-plan --before-push` (a bounded plan of minutes) before the pack is sent.

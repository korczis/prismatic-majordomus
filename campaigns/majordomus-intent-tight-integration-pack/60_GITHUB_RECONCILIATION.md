# Milestone 6 — Reconcile GitHub milestones/issues with intent

Goal: GitHub becomes a faithful projection/integration surface for intent execution, not a parallel planning database.

## Determine current authority

Document exact ownership:

```text
Intent            canonical in repository model
Criteria          canonical in repository model
Milestones/issues canonical according to existing Majordomus plan policy
GitHub objects    synchronized external projection
```

Adjust if current repo doctrine differs, but preserve one authority.

## Reconciliation model

Implement/reuse a typed reconciliation result:

```text
matched
missing_remote
missing_local
drifted_title
drifted_state
drifted_milestone
criteria_mapping_drift
closed_without_evidence
remote_closed_local_unsatisfied
...
```

Use actual vocabulary.

## Directionality

Do not blindly mirror both directions.

Define which fields are:
- local authoritative,
- remote authoritative,
- mergeable,
- observational only.

GitHub issue closed state must not by itself satisfy intent criteria.

## Milestones

Ensure intent milestones map deterministically to GitHub milestones where synchronization is enabled.

No manually maintained unrelated mapping table if identity can be derived/stored canonically.

## Issues

Issue → criteria-served mappings must survive GitHub synchronization.

If GitHub cannot natively represent the structure:
- keep canonical mapping locally,
- project a human-readable marker/body section generated by Majordomus,
- recognize only Majordomus-owned generated region when reconciling.

Do not parse arbitrary prose as authority.

## Apply vs dry-run

Follow current `github sync`/reconciliation conventions.

Default reads/dry-run should not mutate if that is current policy.

Mutation requires explicit apply path and current trunk/worktree safety rules.

## Diagnostics

Detect:
- closed GitHub issue with unmet criteria,
- milestone marked complete while intent milestone not satisfied,
- orphan remote issue,
- missing remote projection,
- generated region drift,
- invalid criteria references.

## Tests

Use mocked/scripted forge fixtures unless live integration is existing test policy.

Test:
- initial projection,
- idempotent second sync,
- remote title edit,
- remote close,
- local criterion mapping change,
- milestone move,
- deleted remote object,
- stale generated body region,
- non-trunk apply refusal,
- network/error propagation.

## Acceptance criteria

GitHub can drift, but cannot silently redefine intent truth.

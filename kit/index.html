Component kit

One vocabulary.Every screen.

The components every page of this site is composed of: tones, atoms, panels, lists, terminals, tabs, a dashboard and diagrams. Each is shown here rendered from the repository's own data, written once in share/design/kit.css and site/templates/kit/.

The design system Source

01 / tones

Tones

Hues that carry identity and never meaning: the colour of a step, of one surface's card, of one kind in a cloud of kinds. A tone is a class; every component reads it through the same four properties.

  • 1 blueGET

    the first step of a sequence; the tone of the CLI, the files a repository holds

    .mj-tone--blue
  • 2 violetGET

    the second step; the tone of the typed model and of the API

    .mj-tone--violet
  • 3 greenGET

    the third step; the tone of the derived surfaces

    .mj-tone--green
  • 4 orangeGET

    the fourth step; the tone of what is presented and fed back

    .mj-tone--orange
  • 5 roseGET

    a fifth hue for a vocabulary longer than four, such as a cloud of kinds

    .mj-tone--rose
  • 6 cyanGET

    a sixth hue for a vocabulary longer than five

    .mj-tone--cyan

Buttons, glyphs, steps, words of a vocabulary and state words. A state word is coloured by the status it is filed under in share/design/tokens.yaml, and by nothing else.

10 / screens

Screens composed of the kit

Whole pages built from nothing but these components, each rendering one of the page designs from this repository's own data.

  • ArchitectureOne repository, many interfaces: what the layer reads, the model it builds, and every surface derived from it.
  • Command lineThe command line as the design draws it: the top-level commands read from the generated reference, a recorded run, and examples the reference documents.
  • CockpitA picture of the Cockpit that majordomus serves at /cockpit: its areas, the layer's counts, decisions per release, the latest changes and what is declared, from the same data.
  • DocumentationA documentation page as the design draws it: where the documents are, the first four commands of a supervised repository, and a briefing the generator recorded.
  • Key featuresSix surfaces around one model: the command line, the HTTP API, OpenAPI and Swagger UI, the Cockpit, MCP and the documentation, each shown with what it really serves.
  • How it worksFrom repository to every surface: discover what the repository declares, build one typed index, derive every interface, present the same facts on each, and what that buys, with measured figures only.
  • IntegrationsOne repository, every interface: what the layer reads, the snapshot it builds, and the command line, HTTP API, Swagger UI, Cockpit, MCP, this site and CI that read it.
  • LandingOne repository, many perspectives: what Majordomus discovers, the model it builds, the surfaces it derives, and what a person gets from them.

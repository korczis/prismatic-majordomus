The proof plan: the tests that are to settle what Majordomus is worth, registered before any of their records exists, and each protocol frozen by its own digest.

.ai/repo/benchmarks/proof-plan.yaml (schema proof-plan/v1) names every proof test: the question it answers, the claims of docs/CLAIMS.yaml it settles, the dimension it measures, the instrument that measures it, and, once it is registered, its protocol. A protocol is how the test is decided, fixed in advance: a paired benchmark over an economics suite’s registration block, a count of trials, or an observation window.

A protocol carries registered_digest, the digest of its own canonical form, and a record counts toward its test only when it carries that digest and was recorded after registered_at (counts_toward). Each protocol is frozen by its own digest rather than by the plan file’s, so registering a second test’s protocol never makes the first test’s records stale, and the plan file is a freshness input of no suite: load refuses a suite whose freshness inputs reach it.

The canonical form is the protocol as the YAML reader reads it, without its registered_digest, with every object’s keys sorted and no whitespace. It is the data as written, not a typed value written back, so a later version of this code that adds a defaulted field changes no digest and stales no record.

use majordomus_cli::economics::proof::{load, NO_PLAN};
let dir = tempfile::tempdir().unwrap();
let findings = load(dir.path()).unwrap_err();
assert_eq!(findings[0].kind, "no_plan");
assert!(findings[0].detail.starts_with(NO_PLAN), "an absent plan is not an empty plan");

Functions§

counts_toward
Whether record counts toward test: only when the test has a protocol, the record carries that protocol’s digest, and it was recorded strictly after registered_at. A test’s own protocol decides, so another test’s registration changes nothing here.
digest
The one digest of the proof plan: SHA-256 over the canonical JSON of value (object keys sorted at every depth, no whitespace), spelled sha256:<hex>. A protocol’s registered_digest and a paired protocol’s registration_digest are both this function, so pre-registration is written once and read the same way everywhere.
